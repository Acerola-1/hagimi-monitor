# 报表：模块真实子项 + 本机分类菜单 + 实时渲染（原型 v3）

浏览器打开 `index.html`。工具条可切**变体**（A 右栏常驻 / B 底部横带 / C 折叠右栏）、
**本机分类菜单形态**（顶栏 / 下拉 / 左栏）、**窗口宽度**（860 / 1040 / 1240 建议 / 1280）、
以及**数据来源**标注（默认关）。「适应窗口」默认开启。报表内的**实时**开关在时间栏右侧。

文件：
- `index.html` + `style.css` + `app.js`（渲染与交互）
- `data-core.js`（图标 / 常量 / 左栏顺序）+ `data-modules.js`（六个监控模块）+ `data-machine.js`（本机 10 分类）
- `data-source.js`（**每组的取值来源与「已有/需新读/不可得」状态**）
- **`HARDWARE-DATA-MAP.md`——逐字段的数据来源与取舍表，实现阶段直接对着看**

打开「数据来源」后，每个分组会显示它读哪个接口/键，行级不一致的会单独标注（`已有` 绿 / `需新读` 蓝 / `混合` 橙 / `不可得` 划掉）。

所有数值为演示夹具，不读取本机。本原型只做布局与交互形态，不构成对正式报表 WKWebView 的回归验证。

## 1. 本轮要解决的三件事

1. 每个监控模块（CPU / GPU / 内存 / 网络 / 磁盘 / 电源）内部，**右侧**加该模块的硬件规格区，全站结构统一。
2. 报表窗口从「快照」变「**实时**」；导出仍按时间点生成快照，两条路径并存。
3. 报表左栏新增硬件总览模块，取名 **「本机」**，内容对齐参考项目的硬件页。

已确认的方向（2026-09-12）：

| 决策点 | 选定 |
| --- | --- |
| 实时化路线 | 保留 WebKit 模板，Swift 每秒推增量；不重写原生 SwiftUI |
| 硬件区落点 | 只落报表窗口；菜单栏面板保持现有尺寸 |
| 新模块命名 | 本机 |
| 内容范围 | 精选合并 10 类，不照搬参考项目 20 类 |
| 报表窗口默认尺寸 | 从 1040×760 提到 **1240×800**（`minSize` 860×580 不变） |
| **本机模块结构** | **顶栏分类菜单（10 类可切换）+ 选中分类的详细规格**，不把明细铺在一页 |

## 2. 模块块：主列铺开真实子项 + 右栏规格

正式报表里每个模块并不是一张图，而是「1 整行 + 若干并排/短条」。原型按 `ReportTemplate.html` 的**真实结构**铺开：

| 模块 | 整行卡 | 并排 / 短条卡 | 合计 |
| --- | --- | --- | --- |
| CPU | CPU 占用（总/性能核/能效核） | 性能核 · 能效核、核心负载分布 | 3 项 |
| GPU | GPU 占用（核心/渲染器/分块器） | 核心负载分布、显存使用 | 3 项 |
| 内存 | 内存使用 | — | 1 项 |
| 网络 | 网络速率（下行/上行） | 每日流量（短条） | 2 项 |
| 磁盘 | 磁盘读写速率（读/写） | 每日读写量（短条） | 2 项 |
| 电源 | 整机功耗 | 电池电量、电池健康 | 3 项 |

结构（**纯加法**，现有 `.card` / `.sec-head` / `.inner-grid` / ECharts 图表不动）：

```
<section class="module-block">            ← 新增容器,一个模块一个
  <header class="mod-head">  图标 · 模块名 · 副标题 · N 项 · 序号
  <div class="mod-body">                  ← 新增两栏
    <div class="mod-main">                ← 现有 section 原样搬入
       整行卡（高度 300）
       <div class="inner-grid"> 两列并排卡（高度 260）
    <aside class="spec-card">             ← 新增「硬件与配置」规格区
</section>
```

**右栏规格栏信息架构固定为两组**：该模块的静态规格 + 「运行状态」（带 `● 实时` 标记）。
缺失值显示 `—`，长值换行而不是省略号（沿用面板 `DisplayArchiveTile` 的既有取舍）。

### 字段命名对齐现有常量

面板里已有一整套硬件规格先例：`Views/Panel/DisplaySection.swift` 的 `DisplayArchiveGrid` / `DisplayArchiveTile`
（规格 tile + 展开/收起 + 复制 + 缺失 `--`），字段标签走 `metric.display.*`。新字段沿用同一命名法：

| 已有键 | 用途 |
| --- | --- |
| `metric.display.*`（model / serial / resolution / refresh-rate / color-depth / gamut / ppi / size / hidpi-scale / manufacture-date / adaptive-sync） | 显示器整组可直接用 |
| `metric.storage.*`（smart / free / total / used）、`metric.battery.*`（cycle-count / health / capacity / adapter / temperature / current） | 磁盘、电源 |
| `metric.memory.*`、`metric.cpu.*`、`metric.gpu.*`、`metric.network.*` | 各自模块 |
| `kind.cpu` / `kind.gpu` / `kind.memory` / `kind.storage` / `kind.display` / `kind.battery` / `kind.network` / `kind.bluetooth` | 分类名 |

新增键按 `metric.<module>.<field>` 与 `kind.sensors` / `kind.system` 补齐。注意 `kind.storage` 中文是**磁盘**，参考项目叫「存储」。

## 3. 本机模块：顶栏分类菜单 + 详细规格

参考项目的硬件页用左侧二级菜单（`HSplitView` + `List` + `OutlineGroup`）收起 20 个分类——因为明细量极大，
铺一页放不下。原型照此改成**可切换**：顶栏分类菜单 + 选中分类的详细规格面板。

```
<section class="module-block" id="machine">
  <header class="mod-head">  本机 · 10 类硬件清单 · 规格可切换 · 297 项 · 07
  <div class="machine-workbench">
    <nav class="machine-tabs">   10 个分类（顶栏形态）
```

| 形态 | 说明 |
| --- | --- |

### 参考项目的取与舍

**取**：主列 + 固定规格轨的结构；每模块自己的规格；传感器按域分组；静态规格一次读取、不跟采样 tick；
缺失占位与复制；分类可切换。

**舍 / 并**：20 类里的低频道不单列（打印机、PCI、摄像头、音频、外设、智能卡）；USB/雷雳/蓝牙/Wi-Fi 并入「连接」；
「软件」+「安全」并为「系统与安全」；**不做单独的「概览」屏**（其内容与本机模块/各模块右栏重复）；
传感器只做温度 + 风扇（参考项目也只做这些：电压电流走 IOKit 电池、功耗走 IOReport，不在 SMC 传感器路径里）；
不引入它的 root 特权辅助进程（App Store 渠道不可分发）。

## 4. 实时

报表图表走内联 ECharts、canvas 渲染，统一入口是 `paintChart` → `setOption(option, {notMerge:true})`
（`ReportTemplate.html:1692-1716`）；Swift 侧已有 `evaluateJavaScript` 与 `WKScriptMessageHandler` 桥
（`ReportWindowPresenter.swift:37,189`）。所以实时=同一份模板、同一条渲染链路，只把数据从「一次注入」改成「按秒追加」：

1. **范围**：实时只对「今日」有意义。切到近 7 天及以后自动停实时。
2. **推送**：Swift 每秒取当前分钟桶（既有 `StatisticsRecorder` 持续落库），把增量交给前端重跑该模块的渲染函数。
3. **门控**：窗口不可见或被遮挡时暂停推送（原型用 `document.hidden` 模拟；正式实现用 `NSWindow.occlusionState`）。
4. **粒度**：**静态规格组不刷新，只有「运行状态」组跟随**。这既省开销，也让「规格 vs 读数」语义分明。
5. **导出**：`打印 / 另存为` 仍走既有快照路径，导出前把状态切回快照。

## 5. 宽度预算（原型实测）

原型沿用报表令牌：左栏 184pt、`.content` 内衬 26pt，并把内容上限从 **1180 提到 1360**（候选改动之一）。

| 窗口 | 内容内宽 | 主列 | 规格栏 | 主列占内容内宽 |
| --- | --- | --- | --- | --- |
| **1240（建议默认）** | **977** | **662** | **300** | **68%** |
| 1280 | 1017 | 701 | 300 | 69% |
| 1040（现默认） | 782 | 506 | 260 | 65% |
| 860 | 606 | 606 | 606 | 100%（降级：规格区下移为横带） |

已减掉滚动条约 15pt。结论：

- 右栏不是免费的。1040 下加 260pt 规格栏，图表只剩 506pt（掉 35%）；1240 下剩 662pt（掉 32%）。
- **杠杆是窗口默认宽度**。已确认提到 1240×800。
- 内容上限 1180 → 1360 只在窗口宽于约 1364 时才生效，是可选项。
- 主列的并排子卡（`.inner-grid`）在 1240 下每张约 324pt，仍有充足绘图宽度——这是加右栏后掉幅最明显的部分。

## 7. 落进正式报表还缺的能力（Swift 侧，本轮的主要工作量）

版面是加法，**数据采集是真正的新工作**：

- **硬件清单读取**（新增）：`system_profiler` 的 SPHardware / SPMemory / SPNVMe / SPDisplays / SPUSB /
  SPThunderbolt / SPBluetooth / SPPower / SPSoftware / SPEthernet / SPNetwork 等 DataType；
  `sysctl`（`hw.model`、`hw.memsize`、`machdep.cpu.*`、`kern.osrelease`）；
  IOKit（`IOPlatformExpertDevice`、`AppleSmartBattery`、`AGXAccelerator`）；CoreWLAN；Metal 设备查询。
- **成本与缓存**：`system_profiler` 启动数百毫秒，必须沿用 `StorageSMARTProbe` / `BluetoothBatterySampler`
  已有的「一次性读 + 长缓存 + 手动刷新」，**不能随每秒采样执行**。参考项目也是一次性 `capture`（并发上限 6）+ 手动 Refresh。
- **渠道边界**：`system_profiler`、CoreWLAN 在本项目已有先例（`StorageSMARTProbe.swift:38`、`WiFiProbe.swift`），
  新增数据源仍要逐项核对沙盒与两渠道差异。
- **实时推送**：Swift → WKWebView 的增量通道，以及窗口遮挡门控。
- **文案**：新字段标签补 `Localizable.xcstrings` 中英两语。

- 五个 JS 文件 `node --check` 通过；浏览器控制台无报错。

- **本机分类**：10 个分类切换正常，字段数 21/34/30/12/30/38/38/22/41/31（合计 **297**）；
  三种菜单形态都能切换并保持选中项。
- **左栏跳转**：七个条目在 860 / 1040 / 1280 三档下落点均稳定在滚动容器顶 +8px，高亮与点击项一致。

### 已修的问题

**布局与交互**

1. **左栏顺序与正文顺序不一致**：模块数组里磁盘排在网络前（正式报表是「内存 → 网络 → 磁盘 → 电源」），
   且本机被渲染在正文第 3 位、左栏却列第 7 位，点「网络」跳到第 6 块。
   现在 **`RAIL` 是顺序的唯一来源**，左栏、正文板块、序号徽章都从它派生。
2. **跳转落点偏移**：原用 `target.offsetTop`（相对 `offsetParent`，带上工具条与舞台外边距，还漏掉 zoom）。
   改为 rect 差算：`(target.rect.top - scroller.rect.top) / zoom + scroller.scrollTop`。
3. **子项图表互相覆盖**：`data-chart` 用了同一个 key（`m.id`），后渲染的子项覆盖前者。
   改为每个子项独立 key（`cpu-s0` / `cpu-i1`）。
4. **并排子卡图表空白**：序列按「名称」登记。原先用 `defs.indexOf(对象)` 查，
   内联子项里的 series 是另一批对象字面量，查不到就拿到空数组。改为按名称建索引。
5. **实时数值解析**：`parseFloat("6 800 RPM")` 读成 6，风扇上限被抖成 54；「最热」各自独立抖动会低于单键。
   改为去千分位后再解析，`最热` 改为派生值（取同组最大），硬件上限/数量不参与抖动。

**口径修正（本轮新增）**

6. **删掉「CPU 主频」**：Apple Silicon 没有公开的当前频率接口（`powermetrics` 需 root），
   参考项目全仓库也没有这一项。夹具里原先的「主频 1 512 MHz」是编的，已换成「空闲占比」（`metric.cpu.idle`，我们已有）。
7. **删掉显示器「像素分辨率」与「虚拟设备」**：前者在参考项目里是个丑值（`spdisplays_3024x1964Retina` 原样输出），
   后者是虚拟显示设备标记。同时补上「刷新率」（`metric.display.refresh-rate`）。
8. **磁盘「运行状态」补齐**：原先「读速率 / 写速率」是空的占位 `—`，现改为参与实时刷新的真实读数，并补「可用空间」。

- 未验证：复制到剪贴板的实际结果、正式报表 WKWebView 内的表现、`system_profiler` 采集的实际耗时。
