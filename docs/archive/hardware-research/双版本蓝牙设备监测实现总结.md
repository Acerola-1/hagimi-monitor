# 双版本蓝牙设备监测实现总结

本项目蓝牙模块在 App Store 版和 Direct 版的核心矛盾是：**沙盒里蓝牙数据源被砍到只剩一条**。所有设计都围绕这个不对称展开。

## 一、核心矛盾：沙盒砍数据源

实测 macOS 26 沙盒下：

| 数据源 | App Store 版 | Direct 版 |
|---|---|---|
| `system_profiler SPBluetoothDataType` | 返回空骨架(bluetoothd 拒绝沙盒客户端) | 完整数据 |
| `IOBluetooth` 公开 framework | 可用 | 可用 |
| `IOBluetooth` 未公开电池 getter(KVC) | 可用 | 可用 |
| `CoreBluetooth`(BLE GATT 2A19) | 可用 | 可用 |

Direct 版三条路全通,App Store 版只剩两条(且其中一条对经典蓝牙无效——Redmi 这类设备不发 GATT)。

## 二、三数据源合并架构

按 `BluetoothBatterySampler.swift` 的设计:

**数据源角色**:
1. **IOBluetooth**:双渠道一致可用——设备清单(已配对已连接)、归一化 MAC、系统名(设备端改名秒级反映)、CoD 类型、AVRCP/HFP 上报的系统侧电量
2. **system_profiler**:仅 Direct 版有数据;作为电量冗余兜底
3. **CoreBluetooth GATT**:双渠道可用——BLE 设备 2A19 Notify 实时电量推送

**电量优先级**(核心规则):GATT 精确值(设备自报、实时)> 系统侧读数(粗粒度分档)

**身份关联**:数据源间无公开地址互换接口,用持久化绑定表(归一化 MAC ↔ BLE identifier)跨源对齐。绑定在「同名匹配 / 名称相似度唯一配对」的无歧义窗口学习一次后永久生效,设备改名、多设备并存都能稳定合并。

## 三、解决 Redmi 经典蓝牙电量的关键——KVC 私有属性

IOBluetooth 公开 framework 没有电量接口,但 bluetoothd 把 AVRCP/HFP 收到的电量缓存在 `IOBluetoothDevice` 的未公开 getter 里(`batteryPercentSingle` / `batteryPercentLeft/Right/Case` 等)。沙盒内这条通道畅通,是 App Store 版经典蓝牙电量的唯一来源。

安全性封装(满足 App Store 审核 + 系统 API 漂移保护):

```swift
device.responds(to: Selector(key))          // 先确认 getter 存在
device.value(forKey: key) as? NSNumber      // 按 NSNumber 装箱提取
(1...100).contains(boxed.intValue)          // 值域过滤
```

`responds(to:)` 验证方法存在性,系统 API 变更时安全降级为 nil,绝不崩溃;不引用任何私有 API 符号,App Store 审核兼容。

## 四、健壮性保障(治「时有时无」)

实测发现 IOBluetooth 私有属性**会间歇性回空**(AVRCP 会话重建/懒加载期间)。Direct 版有 profiler 兜底所以一直正常,App Store 版只有一条路就表现成「时有时无」。三层加固:

1. **电量粘性缓存**(核心):按归一化地址缓存最近读数,属性回空时沿用;设备离场即清,重连重新学习——不伪造数据(连接会话内沿用系统本身粗粒度分档合理),不残留跨会话旧值
2. **读取宽容化**:装箱值统一按 NSNumber 提取,补 `batteryPercent` 裸键兜底
3. **重试增强**:连接后渐进重试 2/6/15/30s 四档,覆盖 AVRCP 慢上报;防抖窗口内连接事件标志不被夹在中间的断开事件取消

## 五、响应速度优化

10 秒轮询的角色被重定义为「通知遗漏的兜底」,主路径改成事件驱动:

- **拆分快速/慢速路径**:IOBluetooth 枚举(微秒级)主线程独立发布,profiler(数百毫秒~8s)后台独立补充
- **IOBluetooth 连断通知**:全局连接通知(class 方法)+ 每设备断开通知(instance 方法,随清单动态注册/注销)→ 0.5s 防抖(合并 ACL/HFP/A2DP 连发链路事件)→ 立即刷新面板
- **连接后电量渐进重试**:2s/6s/15s/30s
- **BLE 侧新增 `refreshImmediately()`**:事件触发即时召回,新设备出现延迟从 ~10s 降到 0.5s

## 六、跨渠道一致性设计原则

- 所有数据源逻辑(合并、排序、绑定、解析)放共享代码,`#if DISPLAY_CONTROL` 只隔离 Direct 独有的硬件控制能力
- 两版用同一合并纯函数(`merge(ioDevices:profilerDevices:bleSnapshots:bindings:)`),单测覆盖 App Store / Direct 两套场景
- 单一 `@Published devices` 路径,UI 不感知渠道差异
- 不把渠道内部术语(如「沙盒」、「Direct」)写进面向用户的文案——面板只显示「蓝牙」模块,差异由数据源自然处理

## 七、自绘图标的对齐收尾

蓝牙模块因 Apple 商标原因无 SF Symbols,用自绘 SVG 符文。两处对齐问题及修复:

- **面板行头**:`frame(width: 14, height: 14)` → `frame(width: 18, height: 14)`,与其他行 SF Symbols 18pt 占位一致,标题列对齐
- **设置侧栏**:SF Symbols 跟随字体(~16pt),自绘资产按 24pt 固有尺寸渲染——蓝牙侧单独 `resizable + 16×16 frame` 收敛视觉大小

## 八、总结

**双版本蓝牙监测的精髓就是「承认沙盒砍了路,但 IOBluetooth 公开框架 + 私有 KVC 这条路在沙盒内依然通」,然后用合并算法让 UI 端无感**。
