# 面板原生图层运动协议

本协议对应两渠道正式原生运动路径。普通启动无需实验开关；参考 Demo 独立保留在 `prototypes/panel-motion-demo`。旧窗口高度预测、窗口弹簧和 SwiftUI 单宿主实验已移除，有限解析模型及测试夹具继续验证几何边界。

## 内容和所有权

| 组件 | 内容来源 | 迁移的差异 |
| --- | --- | --- |
| CPU / GPU / 内存 / 磁盘 | `MetricGlassRow`、现有指标网格和进程列表 | 原值、图标、缺失状态和指标顺序均由原组件负责 |
| 风扇 | `MetricGlassRow` / `FanList` | 实际数量决定是否可展开；App Store 不编译风扇模块 |
| 网络 | 现有网络行及诊断、进程列表 | 保留连接状态、长值和复制操作 |
| 电源 | `BatteryGlassRow` / `PowerDetailPages` | 原分页状态与供电语义；自然高度变化重新登记 |
| 蓝牙 | `BluetoothGlassRow` / `BluetoothDeviceList` | 原组件是整体展开和逐设备静态列表，不新增设备子展开动作；无设备不可展开 |
| 显示器 | `DisplaySection` / `DisplayControlGroup` / 档案组件 | 顶层 `display` 与逐设备档案 ID 递归登记；Direct 保留原控制，App Store 保留原信息 |
| 标题与底部 | `MonitorPanelView` 原组件 | 统计、监视器、工具、设置及置顶操作保留真实动作 |

`NativePanelSurface` 拥有经典窗口底座及可见轮廓。顶层卡片的静态底座独立托管，并复用原 `MonitorPalette`、提亮与行材质；原内容通过环境标记让出顶层底座，嵌套卡片仍保留自身材质。`MonitorConstants` 是尺寸与运动参数的唯一所有者。

## 几何与运动

每个稳定 ID 保留一个自然尺寸内容宿主。子宿主测量异步合并，不能在父 SwiftUI Layout 的测量过程中同步进入另一个 NSHostingView。公开的产品环境逐项继承，不能复制整个父 ViewGraph 环境。同一次内容提交不重复测量宿主；同一批自然尺寸与宽度回报合并为后续一次异步校准，已移除节点的迟到回报丢弃。

`PanelDimensionRegistry` 生成不可变快照，`PanelGeometrySolver` 后序求解揭示高度和嵌套位置。`NativePanelLayerMotion` 在操作或自然尺寸改变时生成有限共享轨迹；系统图层播放位置、揭示、视口、轮廓、描边、阴影和显示器角标，普通播放不发布显示帧或调整真实窗口高度。

反转继承当前位置与速度。自然内容变矮时相位保持合法范围，点数余量保存原揭示高度及速度并沿同一解析运动归零。几何重排的位移余量同时作用于绝对分区坐标。过时完成回调用代际令牌作废。隐藏期间的结构与逻辑展开变更只保留最新值，不重新发布画面或安装事件监视器；重新显示一次提交最新端点。

## 滚动、排序和输入

透明窗口只提供屏幕约束内的容量。窗口级输入边界与可见圆角轮廓对应；指针静止时只安排轮廓交叉时的单次判定。关闭阶段冻结呈现图层，取消边界任务并退出输入；重新打开恢复刷新门控和事件监视器。

自动揭示与卡片使用同一轨迹。双击表头全部展开/收起明确回到主体顶部，从全部收起展开时首个模块全程固定在顶部；单行展开仍揭示该行。分页及数据刷新仅保留当前合法滚动偏移，不重放上次展开的揭示目标。分页选择先以禁用布局动画的事务提交新内容，再由自然尺寸登记生成统一高度轨迹。用户滚动从 ClipView 的呈现偏移接管，实际滚动范围按当前文档几何钳制，数据刷新不能重放旧的自动滚动目标。触控板惯性与离散滚轮均可结束接管；上下渐隐使用原面板的边缘语义。

独立 NSHostingView 的 SwiftUI `.global` 原点不能直接用于排序。排序读取已有捕获锚点的窗口坐标，并将指针转换到同一左上角坐标；保留原移动命令、预览、保存和取消模型。仅在实际拖动期间运行有限边缘滚动任务。

与 `panel-long-press-reordering` 的交叉范围为宿主坐标和滚动适配；该 change 的未完成功能和任务标记不在本次改动范围内。HUD、报表、采样算法、权限及安装版均不属于本次迁移。

## 验证入口

菜单栏负载环与面板可见性独立平滑；展开门控只暂停其发布，恢复从停住的位置渐进到最新目标。它的显示订阅不进入面板观察树，独立计算与验证记录见 [负载环审计](menu-bar-load-ring.md)。

- `NativePanelMotionTests` 验证组合轨迹、反转、嵌套变矮、滚动接管、生命周期及减弱动态效果。
- 原几何、滚动、排序、观察、宽度及设备测试继续运行，不用编译替代真实控件验证。
- `HAGIMI_PANEL_BENCH` 的原 `single/all/reverse` 保留三卡范围。`full-all/full-sequence/full-reverse` 使用当前真实可见模块并保留显示器组件；这些自动操作不替代显示器嵌套和分页的手动验收。
- `HAGIMI_PANEL_TEST_DISPLAY` 和 `HAGIMI_PANEL_TEST_HOST` 仅控制测试定位/宿主，不改变主屏或用户其他窗口。测试副本的配置与正式安装版分离。

实机原始证据保存在本 change 的验证索引登记的位置；未测硬件、不同操作范围和错误采集必须明确列出。录屏输出帧率、主线程打卡间隔和进程 CPU 分别是不同指标，不能互相冒充。

## 宿主换页与正常启动

行内容及显示器控制/档案宿主均以顶部对齐，避免新内容在旧 frame 内先居中、测量后再回到顶部。自然尺寸未变时不重复失效 intrinsicContentSize；卡片及替换页对同一 generation 只提交一次运动，新节点或承载尺寸变化时重新同步。承载 frame/遮罩的调整采用禁用隐式动画的图层事务，材质外观仅在外观变化时更新。

原生卡片测量与摆放使用同一个完整明细高度；零高度提议仅保留给旧视口路径。每层内容宿主传递扣除本层左右内衬后的 `nativePanelContentWidth`，与实际宿主宽度一致，避免显示器控制页在内容更新和布局测量之间交替使用父宽度与子宽度。`NativePanelHostingTests` 使用离屏 NSHostingView 覆盖四种分页高度、滑杆数值更新、嵌套宽度继承及旧视口兼容；它验证布局协议，不代替真实鼠标拖动和材质闪烁验收。

电源宿主按当前面板/屏幕的可用容量预留内容承载高度，换页时承载层不随自然高度缩小再扩容；几何登记仍使用每页的真实自然高度，不把预留空间计入可见卡片。超过预留容量的真实内容仍可扩容，不截断数据。预留宿主改变承载尺寸时不作废并重播上一版遮罩计划，新的可见几何由统一轨迹接管。其他模块的承载策略保持原有行为。

显示器两页的 AppKit hitTest 显式路由到当前逻辑页，不以透明度或 SwiftUI 的 allowsHitTesting 替代宿主级输入隔离。鼠标边界只有忽略状态实际改变时才写入窗口。

普通验收副本仅保留原生运动开关，不登记固定屏幕或 pinned 测试宿主。启动不自动打开测试窗口，用户点击状态项时沿原菜单栏窗口定位链路呈现；内容上限优先读取当前状态项所在屏幕。测试屏幕/宿主仅由显式夹具选择启用。

## 算法与平台参考

解析轨迹是二阶常系数方程 `x'' + 2ωx' + ω²(x-T) = 0` 的临界阻尼闭式解：`x = T + (A + Bt)e^(-ωt)`，其中 `A=x₀-T`、`B=v₀+ωA`；代码中的速度是该式的导数。数学背景参见 [MIT OCW: Damped Harmonic Oscillators](https://ocw.mit.edu/courses/18-03sc-differential-equations-fall-2011/pages/unit-ii-second-order-constant-coefficient-linear-equations/damped-harmonic-oscillators/)。这说明公式的来源，并不宣称 Swift 实现复制自该课程。

关键帧的共享时间点与显式模型端点遵循 [Apple: Animating Layer Content](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/CoreAnimation_guide/CreatingBasicAnimations/CreatingBasicAnimations.html) 和 [CAKeyframeAnimation.keyTimes](https://developer.apple.com/documentation/quartzcore/cakeyframeanimation/keytimes)。本轮未发现需单独保留第三方代码许可证的复制实现；此前原型代码的创作过程无法由当前未提交文件独立证明，保留原始源码和哈希作为参考边界。

## 可重复采集入口

`full-matrix` 在当前可用配置上依次操作全部顶层项，再循环全部展开、全部显示器档案、排名/健康/供电/拓扑分页、档案收起、CPU 快速反转及全部收起。不存在的分页记录 `page-skipped`；它不伪造真实数据。旧 Autotest 档案序列与 Bench 互斥。`full-all` 的显示器主分区现已纳入明确的展开意图；旧三卡 `single/all/reverse` 保留。

`PanelLayoutCounters` 记录面板根 body、卡片布局及自然尺寸次数；`NativePanelWindow` 记录真实窗口提交；`native-plan` 记录结构版本、节点数和一次准备成本。诊断由显式 Bench 环境启用，正式运行不打印或加锁计数。普通图层播放的判断同时依靠运行计数与无逐帧发布的模型测试，不能仅以某个计数较少推导整棵 SwiftUI 内部的全部布局次数。

`scripts/validation/capture-panel-motion.py` 只接受 `local.hagimi.closeout.*` 独立产物，记录准确可执行文件哈希与 PID，并只清理自身子进程；`panel-resource-probe.swift` 记录进程累计 CPU、RSS、物理 footprint、系统 CPU tick 和驱动可获得的 GPU 利用率。CPU 采用相邻累计计数差分，WindowServer 读取失败保留状态码。采集与录像分轮进行；后台负载、屏幕报告的模式和实际压力程序读数必须随结果一起解释。

## 数据发布与显隐租约

`PanelPublicationGate` 按模块、风扇、蓝牙及进程切片合并最新界面动作。连续反转延长截止时刻时，旧的一次性回调由代际取消；即使主队列到期回调晚于新结果到达，也不会用旧结果覆盖新值。门控回调弱持有所有者，没有逐帧定时器。最后一个可见宿主退出时清除进程会话并恢复发布，过期的进程结果仍须通过会话检查。

主采样在到达时推进私有缓存，并立即以 `freshKinds` 及到达时间送入统计；界面发布等到运动稳定。风扇统计读取独立采样器当前值，不读取被界面门控延迟的显示副本。这样统计记录和采样排期不依赖面板是否正在运动。

`full-lifecycle` 是显式、有限次数的诊断入口：依次打开菜单栏、同时打开两个宿主、只保留快捷键宿主、全部隐藏，循环六次并记录真实窗口状态、共享可见租约和采样值。它不用于控件或焦点的人工验收。通常 Bench 只启动指定宿主，避免隐藏的另一棵面板树重复执行操作。资源探针有超时并校验压力进程退出；异常轮次保留原始记录并排除对照。

## 固定底部操作区

限高时只有模块卡片进入滚动文档，操作区独立留在可见轮廓底部。几何快照的 `pinsFooter` 使文档、视口和底部操作区分别求解：视口先扣除操作区自然高度及已有行间距，最后一个模块仍可完整滚动到达；未限高时总高度与原布局一致。原生宿主的操作区位于 ScrollView 外，随轮廓共享轨迹移动，命中使用当前呈现坐标；模块位置重排余量不作用于固定操作区。兼容 SwiftUI 路径同样将既有按钮移到滚动容器外，保留原动作与材质。
