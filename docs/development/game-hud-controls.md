# Game HUD 名单、透明度与预览

本文记录 Game HUD 的游戏名单、背景透明度与设置页局部预览的设计合同和所有权。实现与参数以源码为准：统一登记与持久化见 `GameHUDAppRegistry`、`GameHUDRegistryStore`，旧版兼容与总开关迁移见 `GameHUDSettingsMigration`，来源识别与扫描见 `GameHUDAutoDetection`、`GameHUDGameScanner`，显示资格见 `GameHUDSessionController`，设置名单与预览见 `GameHUDSettingsView`、`GameHUDPreviewContract`，背景外观见 `GameHUDBackgroundAppearance`。

## 来源与获取渠道分离

游戏证据与发现方式不是一回事，名单和来源标签必须区分：

- **来源（证据）**：Steam 清单（`libraryfolders.vdf` 与 `appmanifest_*.acf`）、Epic 清单（`Manifests/*.item`）、应用包游戏类别（`Info.plist` 的 `LSApplicationCategoryType`，英文规范 ID 与本地化类别名都接受）。
- **获取渠道**：全量扫描、前台激活时的即时发现；Spotlight 只是可能缺失的枚举索引。

来源标签只描述证据，平台名直接用 Steam、Epic，其余来源用应用类别；不能把一次扫描命中写成商店清单，也不能把索引缺失写成应用被卸载。Steam/Epic 应尽量关联实际游戏包：只有唯一候选或名称唯一匹配时才采用，不能从安装目录里随便取一个 `.app`；仅路径相似不是依据。启动器与商店本体的过滤属于发现规则，不能变成隐藏的运行时否决集合：只要应用实际获得资格，设置名单就必须能看到它并允许排除。

## 统一登记是唯一权威

所有能够触发 HUD、被手动添加或被排除的应用都进入同一份应用登记；设置名单、显示资格和扫描结果只是这份登记的投影或输入。`GameHUDAppRegistry` 按 bundle ID 去重，记录应用身份、可用名称与路径、来源集合、手动添加意图和黑名单状态；`GameHUDRegistryStore` 负责读写与旧版兼容输出。

自动识别结果全部直接采纳并登记持久化，不设待确认、首次接受或询问状态；用户手动添加与自动识别具有同等资格。名单从登记投影：自动项标「自动识别」并显示真实来源，手动项标「手动添加」，同一应用只出现一次。

扫描只合并元数据与补充来源，不能替换或删除手动添加和黑名单决定；扫描未返回不等于卸载，应用包暂时找不到时只提示未找到并保留原有决定（`GameHUDPackageLocator` 区分身份与包可用性）。运行时即时发现必须先登记再发布显示资格，保证所有可显示的应用在设置中都有管理行。

## 黑名单优先与立即隐藏

显示资格为「存在有效自动来源或手动添加意图，且不在黑名单」。黑名单独立保存、优先级最高，不受来源数量、扫描次数或添加顺序影响。实际显示仍要求总开关开启、目标应用位于前台且目标窗口可靠，名单不能替代这些门槛。

排除先保存决定，再隐藏目标并停止该目标的专用测帧；已排队的快照、测帧和几何回调在显示前复核最新资格与会话代次，晚到结果不能复活被排除的应用。移出排除只解除黑名单，保留自动来源与手动添加意图；仅为提前排除而登记、没有启用来源的记录，解除后不会凭空变成手动添加。明确添加一个已排除的应用会解除同一应用的黑名单并更新同一条记录，不产生启用与排除两行。

## 旧偏好迁移与兼容输出

只迁移正式版本已存在的旧 `custom`（手动添加）、`excluded`（排除）、总开关、样式、位置和指标偏好，入口是 `GameHUDRegistryStore` 的迁移与 `GameHUDSettingsMigration` 的总开关解析：

- 旧排除优先于旧添加，进入黑名单；旧添加保留手动添加意图并按「手动添加」呈现，内部保留迁移来源只用于兼容，不伪称当前自动识别。
- 显式总开关值优先；可识别的旧档案缺少显式值时按旧版有效默认兼容；完整新档案默认关闭。
- 迁移幂等，重复启动不会复活黑名单或产生重复项。损坏的新版数据保留旧记录并提供可恢复说明，不清空用户决定。
- `GameHUDRegistryStore` 是唯一权威决定所有者；为回退旧版本，向旧 `custom`/`excluded` 输出兼容值，但禁止从兼容值反向覆盖新决定。

## 扫描、门控与副作用边界

扫描沿用现有缓存、后台扫描与事件去抖，不在每秒采样中枚举安装应用。HUD 专用常驻监听受总开关门控：`GameHUDGameScanner` 在关闭时停止目录监听、激活观察与定时扫描；设置页「重新扫描」只执行一次扫描，不打开总开关。扫描本身不改变名单决定。

第三方 HUD 偏好清理只能发生在「总开关开启且目标确实获得运行时显示资格」的路径（`GameHUDCoordinator` 的运行时入口）；黑名单、设置刷新、预览和扫描发现本身不得触发外部进程偏好写入或删除。清理失败静默，不影响硬件 HUD 显示。

## 背景透明度的所有者

外观区只有当前样式的一个透明度控件：标题、滑杆、百分比与恢复默认。卡片与顶部横条分别保存各自的值；默认值来自两种样式现有的背景常量，集中登记，不把两种样式静默统一成新的默认。

内部把透明度归一化后按 `alpha = 1 - transparency` 计算背景填充，透明度增加表示背景更透明。该变化只作用于背景填充：不修改 `NSPanel` 整体 alpha，不修改整棵 HUD 的 opacity，文字、指标和行内容保持自身不透明度。非法存储值夹取或回退；顶部横条按既有几何规则回退卡片时，使用实际渲染的卡片样式值。

更新沿现有内容观察链，不重启采样或测帧，不重建材质。常量、默认值、夹取与 alpha 解析由 `GameHUDBackgroundAppearance` 单一拥有；`GameHUDView` 与 `GameHUDTopStripView` 只消费解析后的背景色，文档不复制数值。

## 局部预览合同

透明度设置下方的示例预览用于观察背景透出与文字对比，不是完整 HUD 的缩略图：

- 复用正式背景、字体和指标行渲染，只给预览传入 `GameHUDPreviewSample` 的固定少量示例指标；不改用户勾选集合，不复制第二套 HUD 绘制代码。
- 按正式字号显示，不使用缩放；宽度受详情可用宽度约束，卡片显示头部与少量指标，顶部横条只显示能完整容纳的指标。
- 预览有单一的共享高度上限常量（`GameHUDPreviewContract`）；任何样式超限时减少静态样本内容，不压缩正式文字。
- 只保留观察背景所需的内衬，不画大游戏场景；背景选择使用轻量原生控件，不提供缩略/放大模式切换。
- 示例数据不进入 `MonitorStore`、历史、帧统计或导出；预览不创建真实 HUD 浮窗、不启动采样器或计时器、不申请截图/录屏权限、不启动游戏。关闭设置页后没有预览专属后台任务。

## 验证边界

本文说明设计与所有权，不代替验收。固定宽度、长名称、全部指标、两种样式、空黑名单以及排除/移出排除闭环需要原生设置页检查；真实游戏的前台、窗口、全屏、Space 与点击穿透按对应 Game HUD 规格另行验收。构建成功或规格校验通过不能证明这些行为。
