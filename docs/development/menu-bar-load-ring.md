# 菜单栏负载环计算与动画审计

本轮针对绿黄交界处的突跳、幅度变化和渲染开销。保留真实采样、综合负载口径、环的几何与状态项系统行为；改动集中在显示轨迹、颜色同步、订阅范围与图像缓存。

## 计算口径

`ComputeLoadModel.combined` 将 CPU、GPU 和内存压力分值合成为综合负载。合成采用归一化 log-sum-exp：先减去最大输入保持数值稳定，再计算指数均值并还原尺度。压力映射和平滑参数由源码拥有。结果位于输入均值与最大值之间，任意单项增大不会降低结果；它突出瓶颈，但不是 CPU 百分比，也不保证某项满载时环填满。

| CPU | GPU | 内存压力 | 综合分值（约） |
| --- | --- | --- | --- |
| 100 | 0 | normal | 86.28 |
| 50 | 25 | normal | 38.05 |
| 0 | 0 | warning | 36.72 |
| 0 | 0 | critical | 71.30 |
| 80 | 80 | normal | 74.94 |

保留这套含义比为了观感放大真实读数更稳妥。本轮修正了“严重内存压力单独必定触发红色”的旧注释，实际分类仍由 `ComputeLoadModel.loadLevel` 决定。unknown 压力及缺失 GPU 沿既有规则按零进入计算，会影响综合分值，不能把环解释为完整硬件健康评估。

## 可定位的问题与修正

| 原行为 | 影响 | 当前实现 |
| --- | --- | --- |
| 打开面板取消平滑并直接发布目标 | 每秒采样可表现为猛增猛降 | 环的平滑与面板开关独立 |
| 颜色使用即时值，弧长使用平滑值 | 颜色先跳、弧长随后追赶 | 核心颜色与弧长消费同一显示桶 |
| 每回调步进，并将整数取整结果回灌 | 回调延迟改变速度，末段出现阶梯 | 单调时钟上的解析临界阻尼，取整仅在输出 |
| 小变化一律被阈值过滤 | 等级交界处可能漏掉变化 | 保留过滤，但等级跨界必定接收 |
| `Published` 订阅回读尚未写入的属性 | 图标落后一帧，最后一帧可能停在旧值 | 状态项直接使用订阅携带的新值 |
| 指标模式也运行环动画 | 不显示环时仍有定时工作 | 指标模式停帧并保留有效目标 |
| 原始等级单独参与缓存键，等价徽标分开缓存 | 相同图像重复占用缓存 | 数字键仅含显示桶、外观和最终徽标 |

`MenuBarLoadMotion` 从当前位置与速度续接新目标，没有弹性振荡。快速反转时允许已有速度短暂延续后转向，保持速度连续；正常起落在合法范围内收敛。减弱动态效果直接使用端点。展开期间沿现有门控暂停发布，恢复时从已显示位置静止渐进到最新目标，不把暂停时长算作已播放。

颜色保留已有四级配色，在等级交界附近用 smoothstep 混合。原始离散等级仍供 LIVE 状态及其他既有语义使用，环的过渡色不改变告警判定。运动、停止和颜色混合参数统一由 `MonitorConstants` 拥有。

## 开销与平台行为

仍把缓存的 `NSImage` 交给标准 `NSStatusBarButton.image`，保留系统的多屏副本、外观和非活动状态处理。没有增加按钮覆盖层或 SwiftUI 全树逐帧快照。

动画仅在有效目标变化且尚未收敛时运行，同一整数显示桶不重复发布。模块采样不再兜底重刷环。设置页与 SwiftUI 标签通过独立的 `MenuBarLoadRingPreview` 叶子观察动画，每帧不进入整个 `MonitorStore` 观察树。

与原隐藏面板平滑路径相比，回调预算从 30 Hz 调为 24 Hz。理论缓存键空间从 3232 种缩小到 606 种，驻留上限仍为 300，不能据此声称内存同比下降。合成的 20→80、一秒轨迹记录到原版 30 次回调 / 27 次整数变化，当前 24 次回调 / 17 次整数变化；这是该输入的逻辑预算，不是 CPU 或 GPU 基准。

面板打开时，原版通过取消动画减少工作但带来突跳；当前保留平滑，可能比直接跳值增加图标更新。不能把隐藏路径的预算下降推广为所有交互状态的性能收益。

## 验证与边界

- 原版“面板可见时目标不能直接替换显示值”的新回归失败，修正后通过。
- 两轮定向检查共覆盖 58 个不同测试：时间一致性、反转连续、暂停恢复、跨界、减弱动态效果、模式门控、缓存及预览刷新，并覆盖既有状态项适配、原生宿主、运动和观察范围回归。
- Direct Release 与 App Store Debug 构建成功。只重启一份独立 Direct 测试副本供用户目测。
- 离屏原生绘图核对浅色与深色的交界颜色；它不是桌面截图或动态流畅度验收。
- 日志、合成轨迹和绘图对照在 `tmp/load-ring-audit-2026-10-01/`，运行身份见该目录的预览回执。

真实菜单栏在不同壁纸、多屏及实际高负载下的观感仍需验收。本轮未采集实际 CPU、GPU、能耗或帧丢失数据，不报告性能改善百分比。

## 工程收尾验证（2026-10-01）

用户已明确确认整批人工操作矩阵通过，其中包括负载环观感。该确认取代上文历史阶段的“仍需验收”状态，不要求重复检查。随后 Direct 全量回归包含负载环运动、颜色、缓存和叶子订阅测试；两渠道 Release 构建及独立产物运行均纳入面板 change 的最终验证记录。

全模块资源对照测量整个应用。兼容运动路径和原生路径在同一产物中共享当前负载环；原版源码基线保留旧负载环。两类对照分别登记，不能由整应用 CPU 差异推算负载环单独的 CPU、GPU、内存或能耗收益。
