# settings-window Spec Delta

## ADDED Requirements

### Requirement: Game HUD 可解释应用管理名单

Game HUD 设置 SHALL 将名单命名为「应用与游戏」，按「已启用」「待确认」「已关闭」展示同源登记中的全部可管理项。每行 SHALL 显示可用名称、图标、来源与可理解的识别依据，自动启用与明确启用可区分；完整身份及必要的最近触发信息可在行内详情查看。

#### Scenario: 自动和手动来源如实展示
- **WHEN** 用户查看自动发现、主动添加或此前版本保留的条目
- **THEN** 分别标明自动、手动或此前已启用，不将所有条目统称已添加
- **AND** 来源使用 Steam 安装清单、Epic 安装清单、应用声明为游戏类别等真实依据，不把激活探测一律称为 Spotlight

#### Scenario: 已关闭与未找到应用
- **WHEN** 已关闭或未找到的应用不在当前扫描结果中
- **THEN** 仍以保存的名称和可用图标展示，拿不到名称时才回退应用身份
- **AND** 已关闭行提供直接可见的重新启用操作，不只放在右键菜单
- **AND** 未找到只作为可用性说明，不替代启用/关闭决定

#### Scenario: 名单刷新不改变决定
- **WHEN** 用户刷新扫描，或者扫描返回空结果、部分结果或失败
- **THEN** 已有登记与用户决定保持可见，不显示成全部失效或被移除
- **AND** 扫描状态与失败反馈可区分，支持重新尝试，不以空列表伪装成功

### Requirement: Game HUD 名单操作与目标深链

设置 SHALL 支持逐行启用、关闭、重新启用和浏览添加应用；菜单栏「管理应用…」 SHALL 直达 Game HUD 页面并定位对应应用，首次打开设置或目标未被扫描覆盖时同样有效。

#### Scenario: 手动添加未被扫描的应用
- **WHEN** 用户选择一个有效应用包添加，扫描器尚未或无法发现它
- **THEN** 读取名称、身份和路径并建立明确启用记录，立即显示正常管理行
- **AND** 已关闭的同一应用经主动添加后明确重新启用，不产生重复条目

#### Scenario: 打开指定目标
- **WHEN** 用户从菜单栏为目标 A 打开管理应用
- **THEN** 设置进入 Game HUD 页面并滚动/定位到 A 的行，A 的名称和决定可见
- **AND** 不要求用户自己搜索应用身份，不因设置打开而将目标改为监控软件

#### Scenario: 添加失败
- **WHEN** 用户取消选择，或选中的应用缺少可用身份、已移动或不可读取
- **THEN** 取消不改动名单，失败以可理解的行内信息说明并允许重新选择
- **AND** 不生成空身份项、虚构应用或错误的已启用反馈

#### Scenario: 空名单提供有效下一步
- **WHEN** 没有已登记应用或没有扫描结果
- **THEN** 展示可用的手动添加和扫描入口，并解释可靠游戏可自动发现、其他应用需要确认
- **AND** 不提示等待空的内置名单更新，不要求用户输入或自行查找 Bundle ID

### Requirement: Game HUD 外观设置与背景透明度控件

Game HUD 页面 SHALL 按总开关/状态、外观与预览、监控项目、应用与游戏的顺序组织。外观区域 SHALL 提供现有样式/位置设置、当前样式的背景透明度滑杆、百分比及恢复默认；文字 SHALL 明确透明度只作用于背景。

#### Scenario: 无游戏且总开关关闭时调节
- **WHEN** 总开关关闭或没有游戏运行，用户打开外观区域
- **THEN** 仍可切换样式、调整透明度并看到预览，不因此开启总开关或产生真实浮窗
- **AND** 改动自动保存，恢复默认只重置当前样式透明度

#### Scenario: 控件方向和键盘访问
- **WHEN** 用户拖动滑杆或通过键盘调整
- **THEN** 百分比与可访问值同步更新，数值增加使背景更透明
- **AND** 端点明确表示不透明与全透明，焦点和恢复默认操作可用

### Requirement: 内嵌模拟游戏预览窗

外观区域 SHALL 包含有界的小型模拟游戏画面，叠加当前样式的真实 HUD 内容组件并实时反映透明度、位置与指标选择。预览 SHALL 明确标注示例及非实时数据，提供明亮、深色和复杂背景切换，并保持在现有设置详情宽度内。

#### Scenario: 背景与样式即时预览
- **WHEN** 用户修改透明度、背景、HUD 样式或卡片位置
- **THEN** 相同设置在预览中立即呈现，背景画面保持自身不透明度，HUD 文字不随背景透明度一起淡出
- **AND** 切换背景仅改变预览场景，不更改用户桌面、主题或真实游戏

#### Scenario: 多指标与缩略预览
- **WHEN** 所选指标使真实 HUD 无法按原尺寸放入小型预览画面
- **THEN** 预览以明确的缩略视图呈现完整组件，必要时提供放大查看
- **AND** 不以删除指标、截断数值或改动正式排版来让预览塞入容器
- **AND** 实际 HUD 的窗口容纳规则仍独立按真实窗口几何执行

#### Scenario: 预览不触发运行时副作用
- **WHEN** 用户打开、停留或关闭预览，或者总开关始终关闭
- **THEN** 示例数据只进入预览，不进入正式监控、历史、测帧或导出
- **AND** 不捕获屏幕、不启动游戏、不申请权限、不创建桌面覆盖窗或预览专属采样器
- **AND** 预览没有常驻逐帧动画或周期更新，页面关闭后没有预览后台工作

#### Scenario: 预览与真实显示一致
- **WHEN** 在相同样式、背景和设置下比较预览与实际 HUD
- **THEN** 两者采用相同背景透明度、文字样式与内容渲染规则，缩略比例除外
- **AND** 预览只说明模拟画面的效果，不将其标为真实游戏全屏、Space 或可读性验收

### Requirement: Game HUD 新交互的本地化与可访问性

名单、状态、操作、来源、透明度、背景选择及示例标记 SHALL 接入现有本地化资源，补齐中英与主规格要求的日文；按钮、滑杆和背景选择 SHALL 支持键盘及可访问名称，长应用名不得遮盖主要操作。

#### Scenario: 长名称与不同语言
- **WHEN** 在支持语言下显示较长应用名、识别原因或操作标签
- **THEN** 保留可读布局与可达操作，完整目标名称和依据可读取
- **AND** 不以红绿色或单一徽章颜色作为唯一状态区别
