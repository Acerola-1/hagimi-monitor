# settings-window Spec Delta

## ADDED Requirements

### Requirement: 以确认截图为基准的应用名单

Game HUD 设置 SHALL 采用本 change 的名单参考截图：图标在左，名称旁有自动识别或手动添加标记，下一行显示简短真实来源；行尾容纳明确操作。默认行不堆叠规则说明、时间、内部身份或多重状态，不以复杂详情表替代该结构。

#### Scenario: 自动和手动项
- **WHEN** 用户查看自动识别和手动添加的应用
- **THEN** 自动项显示自动识别标记及 Steam 清单登记、Epic 清单登记或应用游戏类别等真实来源，手动项显示手动添加
- **AND** 同一应用只出现一次，名称、标记和来源均不遮盖行尾操作
- **AND** 默认行不要求展开箭头才能发现排除按钮；内部 Bundle ID 不作为主要名称

#### Scenario: 两组名单
- **WHEN** 用户进入应用与游戏区域
- **THEN** 可以区分启用名单与独立的已排除黑名单，不出现待确认、待接受或否认游戏的流程
- **AND** 黑名单即使当前为空也有可识别的区域和空状态；长名单可以纵向滚动到达

### Requirement: 名单操作完整且直接可见

设置 SHALL 提供明显的添加应用、重新扫描及已排除区域的添加排除入口。启用名单每行 SHALL 有排除按钮，黑名单每行 SHALL 有移出排除按钮；这些入口不能只存在于右键、悬停或折叠详情中。

#### Scenario: 浏览添加
- **WHEN** 用户选择添加应用并选中有效应用包
- **THEN** 应用立即出现在启用名单并标记手动添加，无须等待重扫
- **AND** 已在黑名单的应用经此明确添加后移出排除，并提供对象明确的反馈

#### Scenario: 排除与恢复
- **WHEN** 用户点击某行排除或移出排除
- **THEN** 排除后移入黑名单并立即停止该目标 HUD；恢复后按保留的自动/手动来源返回正常识别规则
- **AND** 操作不修改总开关或其他应用，可逆动作不要求额外模态确认

#### Scenario: 添加未被识别的排除项
- **WHEN** 用户在已排除区域选择添加排除并选中应用包
- **THEN** 该应用以名称、图标和移出排除按钮出现在黑名单，即使从未被扫描发现
- **AND** 不能以只允许排除扫描列表项的限制阻断用户纠正

#### Scenario: 取消、失败和扫描状态
- **WHEN** 用户取消选择、包无法读取或扫描失败
- **THEN** 取消不改名单，失败显示可理解的简短反馈并允许重试，已有数据保持可用
- **AND** 手动刷新有明确进行/完成/失败反馈，不把失败表现为空名单或全部失效

### Requirement: 名单在固定详情宽度内完整可用

所有名单与外观内容 SHALL 遵守现有固定设置窗口及详情可用宽度，不撑大窗口、不横向溢出、不靠横向滚动访问主要操作。长名称允许换行，操作区保持可达；指标数值不得缩放或截断来掩盖布局问题。

#### Scenario: 长名称与不同语言
- **WHEN** 名称、来源或本地化按钮较长，在现有固定设置窗口中显示
- **THEN** 名称/来源按需要换行或使用可访问全文的既有名称策略，添加、排除和恢复按钮仍完整显示
- **AND** 控件和卡片右边缘留白与左侧协调，不延伸到窗口外

#### Scenario: 全指标与列表变化
- **WHEN** 用户启用全部 HUD 指标、切换样式、刷新列表或出现空名单
- **THEN** 页面内容宽度保持受约束，各主要动作不因某个预览组件的自然宽度被推到窗口外
- **AND** 不用扩大设置窗口或缩放整页作为解决方案

### Requirement: 背景透明度控件简洁可理解

外观区 SHALL 复用现有设置容器，提供样式、适用的位置、背景透明度滑杆、百分比和恢复默认。透明度名称不重复堆叠，说明简短；即使总开关关闭、没有游戏运行也可设置和预览。

#### Scenario: 调节外观
- **WHEN** 用户使用鼠标或键盘调整当前样式透明度或恢复默认
- **THEN** 百分比和局部预览即时更新并自动保存，文字自身不随背景变淡
- **AND** 该操作不打开总开关、不创建真实 HUD 浮窗，恢复默认只影响当前样式透明度

#### Scenario: 不同样式与无游戏
- **WHEN** 用户在未运行游戏时切换卡片/顶部横条
- **THEN** 可查看各自透明度与简短可读样本，原位置/指标偏好保留
- **AND** 不增加解释内部实现、测帧 API 或渠道术语的文字块

### Requirement: 正常字号的紧凑局部预览

预览 SHALL 优先展示正常字号下的背景透出和文字对比，使用少量固定示例指标及正式背景/内容渲染；不要求展示全部已选指标。它 SHALL 是紧凑局部样本，不是大游戏场景，也不能把完整 HUD 缩成无法阅读的小字。

#### Scenario: 查看透明效果
- **WHEN** 用户调整背景透明度
- **THEN** 局部样本在自身可见背景上实时体现变化，指标文字使用正式样式字号无需放大即可读取
- **AND** 不因正式 HUD 指标数量变多而扩大预览或缩小文字；可选指标的完整性仅约束真实 HUD

#### Scenario: 样本边界
- **WHEN** 用户切换样式或示例背景
- **THEN** 样本完整位于可用详情宽度内，保持紧凑高度，不裁掉示例文字的开头或末尾
- **AND** 背景选择使用轻量控件，不把大幅插画、复杂工具栏、缩略/放大模式作为主要操作

#### Scenario: 预览隔离
- **WHEN** 打开、停留或关闭设置页的预览
- **THEN** 明确标注示例，静态数据只进入预览，不进入正式监控、历史、测帧和导出
- **AND** 不申请截图/录屏权限、不运行游戏、不创建桌面覆盖窗、不启动采样器或持续动画
- **AND** 页面关闭后没有预览专属后台工作

### Requirement: 设置页交付前完成原生自查

执行者 SHALL 在交付前实际运行设置页并检查名单和透明度的固定宽度表现，保留可核对的截图和操作记录。构建、单元测试和规格校验不能代替此项；真实游戏全屏/Space 验收另行记录。

#### Scenario: 交付检查
- **WHEN** 执行者准备提交本需求的完成报告
- **THEN** 至少检查两种 HUD 样式、全部正式指标、长名称、空名单及排除/移出排除后的原生页面，验证所有主要操作完整可见
- **AND** 在隔离测试偏好中实际执行添加、排除和恢复并记录结果；用户实际视觉满意度仍由用户确认
- **AND** 无原生访问能力时明确报告未完成，不能把视觉任务勾成通过

### Requirement: 本地化和键盘可访问性

新增/改写的名称、来源、操作、透明度与示例说明 SHALL 接入现有本地化资源，完成中英及主规格要求的日文；动作和滑杆 SHALL 有可访问名称、键盘路径和焦点反馈。

#### Scenario: 操作无需猜测
- **WHEN** 用户使用键盘或辅助功能访问名单和透明度控件
- **THEN** 可辨认操作对象、执行添加/排除/移出排除并读取百分比
- **AND** 不以标记颜色作为自动/手动或启用/排除状态的唯一表达
