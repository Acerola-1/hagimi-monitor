# monitor-panel Spec Delta

## ADDED Requirements

### Requirement: Game HUD 上下文控制入口

菜单栏面板 SHALL 在无需先打开设置的位置提供 Game HUD 上下文区，显示当前或最近相关目标、实际状态和可理解的依据。入口 SHALL 不依赖某种菜单栏图标模式或单独命中微小徽章，并保留现有监控模块和固定底部操作区。

#### Scenario: 从正在显示的游戏打开面板
- **WHEN** 用户在游戏 HUD 显示期间点击菜单栏应用图标
- **THEN** 正常打开既有面板，并可直接看到目标名称、自动或手动启用来源及「本次隐藏」「为此应用关闭」「管理应用…」
- **AND** 不需要退出游戏、不需要先寻找工具列表或设置页

#### Scenario: 失焦后仍可管理刚才目标
- **WHEN** 打开面板使原游戏失去前台并使真实 HUD 隐藏
- **THEN** 上下文区保留打开时捕获的目标，准确标明最近显示或当前已隐藏，不宣称仍在显示
- **AND** 游戏到面板的激活通知顺序变化不会清空操作目标

#### Scenario: 没有相关目标
- **WHEN** 没有当前或最近可管理的 HUD 目标，且没有当前待确认候选
- **THEN** 面板只保留简短状态与打开 Game HUD 设置的入口，不展示无对象的关闭或隐藏按钮
- **AND** 总开关开启但没有可靠目标窗口时明确区分允许自动显示与实际显示

### Requirement: Game HUD 操作使用固定目标身份

面板操作 SHALL 绑定用户所见目标的稳定应用身份；本次隐藏/恢复还 SHALL 绑定所见运行实例。面板打开后前台应用或后台扫描变化不得悄悄将同一按钮转向另一个对象。

#### Scenario: 操作期间切换应用
- **WHEN** 面板显示目标 A，之后前台切换到 B，用户操作仍标明 A 的关闭按钮
- **THEN** 只修改 A 的持久决定，B 不受影响
- **AND** 如展示目标发生切换，名称与动作必须同时更新，不能保留旧名称绑定新目标

#### Scenario: 最近目标退出
- **WHEN** 面板所示目标实例已经退出
- **THEN** 本次隐藏/恢复不可作用于新进程，但仍可为该应用关闭或打开其管理行
- **AND** 不自动启动、激活、结束或重启目标应用

### Requirement: 弱证据确认不打扰当前操作

待确认应用 SHALL 仅在用户主动打开菜单栏面板或设置时提供「为此应用启用」与「不启用」操作，不先显示完整 HUD，不抢焦点、不自动展开面板、不弹模态确认或反复提示。

#### Scenario: 首次激活自声明类别应用
- **WHEN** Swift Craft Launcher 类应用仅凭游戏类别成为候选，用户没有既有决定
- **THEN** 游戏画面上没有 HUD，菜单栏面板可解释为应用声明的游戏类别并询问是否启用
- **AND** 忽略该候选不构成同意，只有主动启用才产生明确启用决定

#### Scenario: 拒绝或启用候选
- **WHEN** 用户选择不启用或为此应用启用
- **THEN** 保存对应决定并同步设置名单
- **AND** 不启用后再次激活不重复请求，重新启用仍可从设置进入
- **AND** 选择启用后不强行切回或启动目标应用，回到该应用且窗口可靠时再显示

### Requirement: Game HUD 就地反馈与恢复

上下文控制操作 SHALL 提供对象明确的即时反馈，并在临时隐藏后提供恢复、持久关闭后提供重新启用或管理入口；这些可逆操作 SHALL 不要求额外确认。面板状态与实际覆盖窗显示结果 SHALL 一致。

#### Scenario: 本次隐藏与恢复
- **WHEN** 用户为所示运行实例选择本次隐藏
- **THEN** 显示本次已隐藏，保持目标名称，并提供恢复显示
- **AND** 恢复只撤销临时暂停，仍遵守总开关、应用决定和前台窗口门槛

#### Scenario: 持久关闭的反馈
- **WHEN** 用户选择为此应用关闭
- **THEN** 展示已为该应用关闭的反馈，设置中对应项出现在已关闭
- **AND** 无需再次弹窗；重新启用入口可达，不自动关闭整个 Game HUD

#### Scenario: 覆盖窗无法呈现
- **WHEN** 应用已允许但窗口不可确认或无法容纳 HUD
- **THEN** 面板不能仅凭允许状态展示正在显示或运行徽章
- **AND** 最近目标的保留不导致 HUD 在无关前台应用上重新出现
