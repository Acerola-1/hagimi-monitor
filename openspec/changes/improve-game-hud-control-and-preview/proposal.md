# Proposal

## Why

Game HUD 的自动识别可能误收录普通应用，用户需要能看见来源、手动添加、立即排除误判并从黑名单恢复。首轮实现还暴露了设置页横向溢出、操作不可见和预览难以阅读的问题，因此这次以明确的名单样式和完整可操作性为交付目标。

## What Changes

- 自动采纳全部有效识别结果；取消置信度确认流程，不设待确认、首次接受或是/不是游戏的询问。显示仍需总开关开启、目标位于前台且窗口可靠，用户黑名单始终优先。
- 自动来源来自游戏安装记录、应用声明类别等可解释依据；仅使用 Metal/OpenGL 或仅路径字符串相似不能成为游戏识别依据。
- Game HUD 管理统一放设置页。主面板保持基线样子，不新增管理入口、规则说明、状态行或上下文区；原有总开关入口继续维持原行为。
- 名单采用用户选定的 [视觉参考](assets/list-style-reference.png)：应用图标、名称、紧邻名称的浅蓝色「自动识别」标记，下一行用辅助文字显示真实来源。手动添加标「手动添加」。操作固定在可见行尾，不靠右键或悬停才能发现。
- 提供明显的「添加应用…」「重新扫描」及每行「排除」。单独提供「已排除」黑名单，每行可「移出排除」，并可直接选择任意应用加入排除。
- 名单与判定同源；即时识别先登记再显示。重扫、目标应用重启和监控重启不能清除黑名单或手动添加，扫描漏项不等于卸载。
- 保留现有样式、位置和指标设置。新增背景透明度，仅背景变化，文字不一起变淡；卡片/顶部横条分别保存，默认沿用各自当前外观。
- 透明度预览改为紧凑、正常字号的局部样本，复用正式背景和内容绘制。它用于观察背景透出与文字对比，不画一个大游戏场景，不将全部指标缩成小字，不强制展示完整 HUD。
- 新用户总开关默认关闭，保留旧用户显式偏好；首次说明仅放设置页，简短且不打断操作。新增/改写文案完成现有中英及主规格要求的日文。
- 交付前必须运行设置页检查固定宽度、长名称、全部指标和全部名单动作，保留原生截图；真实游戏验收另行记录，不能以构建/规格校验代替 UI 自查。

## Capabilities

### New Capabilities

- `game-hud`: 自动采纳、同源应用登记、手动添加和黑名单、偏好兼容、背景透明度合同。主规格当前无此能力；沿用在途 `add-game-hud` 的同名能力路径。

### Modified Capabilities

- `monitor-panel`: 明确本变更不得新增 Game HUD 管理、说明或状态区域，保留原交互。
- `settings-window`: 明确参考名单视觉、添加/排除/恢复闭环、固定宽度和局部透明度预览，以及原生视觉自查要求。

## Impact

- 实施基于当前基线源码，不复用已放弃的 A–D 实验实现。主要涉及官网版 Game HUD 的扫描、名单、会话、两种 HUD 和设置，及共享偏好、本地化和必要的设置组件。
- 不扩展 App Store 渠道，不增加权限、外部依赖、录屏、注入或采样频率；共享触点须构建两个渠道。所有模拟数据仅进入预览。
- 本次修订替代该 change 之前的待确认、主面板上下文、管理深链和完整缩略预览方案；不实施本次隐藏/恢复及独立进程暂停系统。用户明确选择「自动显示，再以黑名单纠正」。
- 在途 `add-game-hud` 的名单/持久化冲突由本次要求接管，其余窗口归属、点击穿透和真实数据约束保留。实施或归档时串行衔接，不借机恢复已移除的启动链，也不勾完旧 change 的无关任务。
- 本轮仅修订规划和保存视觉输入，不编写应用代码、不归档、不发布。规划校验通过只表示文档结构有效。
