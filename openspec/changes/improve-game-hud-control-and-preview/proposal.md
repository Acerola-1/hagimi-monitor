# Proposal

## Why

用户开启 Game HUD 后，Swift Craft Launcher 这类启动器可能被自动当成游戏，却无法在设置名单里找到对应项并单独关闭；识别、展示和纠正入口脱节，迫使用户关闭整个功能。设置还缺少背景透明度调节与直观预览，用户无法在进入游戏前判断遮挡和可读性。

## What Changes

- 将发现证据与用户选择分离：可靠安装来源关联的游戏本体可自动启用，仅自声明游戏类别或路径线索的应用先进入待确认；启动器规则限制自动启用，用户仍可主动添加。
- 建立同源应用登记与决策集合，完整展示「已启用 / 待确认 / 已关闭」，保留名称、图标、来源、识别原因及必要的最近发现/触发时间。重扫不得覆盖用户选择，也不能把「未扫到」直接视为失效。
- 在现有菜单栏面板提供当前或最近目标的 Game HUD 控制区，支持「本次隐藏」「为此应用关闭」「管理应用…」；保留点击菜单栏前的目标身份。弱证据确认也使用该入口，不抢焦点、不主动展开。
- 保持真实 HUD 点击穿透，在卡片和顶部横条中以紧凑方式标明目标应用；名单称「应用与游戏」，自动启用明确标为自动，空状态提供有效操作。
- 新用户总开关默认关闭，首次主动开启时以行内说明解释自动显示规则；存量总开关和逐应用选择保持，不通过迁移重新打开。
- 在 Game HUD 设置的外观区域新增「背景透明度」滑杆、百分比与恢复默认，以及内嵌的小型模拟游戏预览窗。调节仅影响背景，不淡化文字；卡片和顶部横条分别记住透明度，切换样式可预览，两者默认外观沿用现有实现。
- 预览使用正式 HUD 内容和背景渲染路径、静态且明确标注的示例读数，提供明亮、深色和复杂背景，不需要真实游戏、截图或新权限，也不启动采样或独立覆盖窗。
- 新增文案进入 `Localizable.xcstrings`，至少完成中英；遵守主规格已有的日文本地化要求，不引入新增 key 的日文缺口。

## Capabilities

### New Capabilities

- `game-hud`: 应用发现证据、逐应用决策、同源登记、运行会话暂停、迁移和背景透明度渲染合同。主规格尚无此能力；复用在途 `add-game-hud` 的同名能力路径，不另建近义能力。

### Modified Capabilities

- `monitor-panel`: 增加 Game HUD 目标说明与就地控制区、弱证据确认和稳定操作目标。
- `settings-window`: 增加可解释应用名单、逐行启用/关闭/恢复、目标深链，以及背景透明度与小型模拟预览。

## Impact

- 主要涉及 `HagimiMonitorDirectOnly/GameHUD/` 下扫描器、目录、会话控制器、协调器、两种 HUD 视图和设置页；共享触点为 `MonitorSettings`、设置路由、菜单栏面板装配及本地化。
- 当前 Game HUD 代码与设置位于官网版；本计划不将它扩展到 App Store。共享触点需要构建两个渠道，功能及测试使用官网版。
- 不引入依赖、新权限、外部服务或持续逐帧刷新；模拟读数只用于预览，实际监控继续来自真实采样。
- 与仍在途的 `add-game-hud` 关联：本计划覆盖其游戏识别/名单/设置交互中与本需求冲突的约定，其余窗口归属、点击穿透、真实数据和性能边界继续保留；不借本计划恢复已移除的受控启动或官方 HUD 功能。实施时须同步相关旧条款，避免两个 change 在归档时互相覆盖。
- 本次仅提交规划产物，不修改源代码、不执行构建、不归档旧 change、不提交 Git；严格规格校验通过仅代表计划结构有效。
