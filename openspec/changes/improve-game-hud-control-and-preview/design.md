# Design

## Context

动机见 [proposal.md](proposal.md)。本设计因跨扫描/决策/会话/设置/菜单栏及偏好迁移而必需；本轮仅规划。

当前源码提供的基线：

| 位置 | 当前行为 | 设计影响 |
|---|---|---|
| `GameHUDGameDirectory.matches` | 内置、custom、扫描器 known ID 合并后减排除 | 必须从纯集合命中改为统一决策，不在多个消费者各写规则 |
| `GameHUDGameScanner.handleActivation` / `rescanNow` | 激活可临时加入，重扫整体替换；来源只有 Steam/Epic/Spotlight | 发现事件合并到持久登记；获取渠道与判定证据分开 |
| `GameHUDSettingsView.gameListGroup` | 列表主要消费扫描结果；手动项未被扫描即进入 stale | 改读登记投影；安装可用性和用户决定正交 |
| `GameHUDSessionController` | 失焦清除当前目标；每秒及激活事件检查窗口 | 管理快照与真实显示资格分离，不改变前台门槛 |
| `GameHUDCoordinator` | 暴露 isShowing；扫描结果还触发 per-app HUD 偏好清理 | 状态必须反映实际呈现；候选发现不得触发外部写入 |
| 两种 HUD View | 各自固定黑底透明程度，无目标应用名 | 抽取共同样式输入与背景渲染所有权 |
| `MonitorSettings` | 总开关默认开启，已有迁移和 custom/excluded 键 | 必须核对旧迁移执行顺序，保存存量选择 |

Swift Craft Launcher 的实际包身份、类别与触发来源尚未现场复现，不能填造其 bundle ID。先用等价夹具覆盖机制，再以真实应用完成负例验收。

项目 `DESIGN.md` 的原生系统控件、经典毛玻璃设置容器和共享色彩/几何仍是基线。Game HUD 继续沿用已有黑色半透明监控覆盖层，不用本次需求重新试验 Liquid Glass。原生实机验收优先于预览截图与构建。

## Goals / Non-Goals

**Goals:**
- 使规则只计算一次，展示和运行时共享结果，并能说明证据与决定来源。
- 用户在菜单栏完成纠正后，后续回调不能使 HUD 重新出现。
- 把外观预览作为正式视图的另一个宿主，避免出现与真实效果不一致的第二套 HUD。
- 用确定夹具验证判定、迁移与竞态，用真实窗口验证穿透、全屏和可读性。

**Non-Goals:**
- 不新增全机应用活动追踪、进程性能数据源、截图、游戏启动/注入或第三方偏好自动开启功能。
- 不保证识别任意 Java/Minecraft/模拟器内部的游戏；启动器与真正游戏进程独立识别，不继承启用决定。
- 不增加每游戏透明度、单独常驻预览窗或新的菜单栏状态项；不扩展 App Store 能力。
- 不以计划完成替代功能完成，不自动提交、发布或归档既有 change。

## Decisions

### 1. 统一登记，证据、决定、可用性分开

增加 Game HUD 专用的主线程可观察登记/决策所有者，按应用稳定身份去重。`MonitorSettings` 保留总开关和外观偏好，逐应用数据由该所有者统一读写；扫描器、会话和视图不分别写偏好。

最小记录包括：应用身份、最近已知名称/路径、可恢复图标信息、证据集合、用户决定、最近发现/实际成功显示时间和安装可用性。图标从现有应用包/缓存解析，缺失用通用图标，不把大图像写入偏好。证据区分安装清单、包类别、路径线索、旧记录来源未知；发现渠道（扫描或激活）不能冒充证据。

用户决定为 `unspecified / enabled / disabled`；自动资格为独立的可计算结果；可用性为已找到、尚未确认或确认未找到。列表的「已启用 / 待确认 / 已关闭」是这些数据的投影，不单独持久化一个可能漂移的列表。

决策顺序：明确关闭 → 明确启用 → 启动器/商店/工具自动过滤 → 已验证安装清单所关联游戏本体 → 待确认。可靠来源仍要核对目标包身份与本体关系，Steam 目录中的第一个 `.app` 不天然等于游戏本体；歧义时退回待确认。手动选择任何有效应用包都允许启用。

发现事件必须先合并登记、再发布资格。显示结果反馈时才更新实际触发时间。重扫只合并证据，不替换全部登记，不删除决定；未被扫描返回不等于已卸载。未找到通过明确的包路径/系统解析结果确认，暂时访问失败保留未知状态。

替代方案：直接用扫描结果并集 custom/excluded 修补列表。它能缓解漏行，却仍让来源、状态和异步覆盖分散，因此不采用。

### 2. 扫描与候选确认保持保守

保留既有低频缓存、目录事件、激活探测与后台扫描，不在每秒轮询中枚举应用。系统类别发现使用与本地化文本无关的应用包类别核验；若仍使用 Spotlight 作为索引入口，要同时覆盖英文/本地化返回，且激活登记与手动添加不依赖其成功。实现前用中文/英文机器或固定元数据夹具核对，不能仅添加几个翻译字符串便宣称解决。

启动器过滤共享于所有自动发现入口；通用 launcher/启动器名称信号结合已验证身份，但不得阻断手动覆盖。Minecraft 启动器身份仅在取得实际包证据后登记。

弱证据仅进入候选；面板主动打开时可确认，不发系统通知、不自动弹出。在关闭总开关时不维持 HUD 专用自动发现；用户在设置主动刷新允许执行一次扫描，该请求不启动常驻监听、不赋予显示资格，也不触发外部应用写入。

扫描结果以来源轮次/新鲜度合并，旧扫描不能移除较新的激活证据；任何结果到达时都使用最新决定重新计算。现有 `cleanupPerAppHUD` 不得继续对所有发现项执行，至少收紧到总开关开启且目标实际获得显示资格的运行时路径；候选、不启用项与预览永不触发它。本次不扩展该清理行为。

替代方案：先显示 HUD 再让用户点击否认。第一次覆盖已造成打扰，且穿透窗无法就地点击，故不采用。

### 3. 管理目标与运行目标分别建模

真实显示仍只跟随当前可靠的前台游戏窗口。新增只读上下文模型，包含：目标身份/名称、证据与决定、进程实例、是否实际显示、不可显示原因和最近相关目标。

在既有菜单栏面板打开事件中捕获目标快照；并保留最近相关目标，处理失焦通知先到的顺序。面板每个动作绑定快照中的应用身份，临时操作额外绑定进程实例，不在点击回调里重新读取 frontmostApplication。优先呈现当前待确认候选，其次当前 HUD 目标，再其次最近相关目标；打开后的快照保持稳定直到关闭/重新打开，状态可以更新但不会静默替换对象。

最近相关目标只作为管理对象，不能用于继续显示。没有目标时只显示状态与设置入口；最近目标退出后仍允许修改应用持久决定，但隐藏/恢复动作失效。`isShowing`/徽章以实际面板显示成功为准，而非仅 session 的允许状态。

上下文区位于菜单栏面板的紧凑状态区域，接在既有标题下方，不新增一级菜单或另一块 popover。动作可直接触达且保留固定底部入口；状态区尺寸变化沿现有原生尺寸提交链路，不新建逐帧动画。若采用新的共享状态组件，设置页复用同一语义与动作所有者。

替代方案：把徽章变成微小独立命中目标或放开整个 HUD 的鼠标交互。两者分别有可发现性问题和误吞游戏点击风险，因此不采用。

### 4. 关闭、暂停与异步显示门控

持久关闭先提交决定，随后同步撤销目标会话、停止测帧和隐藏面板，最后反馈。协调器的快照、测帧、几何回调在呈现前统一复核显示令牌/资格；决定变化撤销旧令牌，避免排队回调将面板复活。

本次隐藏按进程号加启动身份登记，不能只用 PID。暂停持续到该实例退出，切换焦点、扫描、总开关切换不清除；另有「恢复显示」动作。为符合“至目标退出”语义，监控进程重启时也应恢复仍然存活的暂停实例：只保存最小实例标识，启动后核对启动身份并清理退出/重用/无法验证记录，不当作应用活动历史。

明确重新启用不会悄悄解除同一实例的临时暂停；恢复操作单独撤销暂停。总开关仍是独立门控。

### 5. 迁移一次完成且可重入

新版本登记使用版本化存储；先完整解析旧数据并生成新记录，再写新快照及迁移版本。解析失败保留旧数据并显示可恢复状态，不清空全部决定。重复执行必须幂等。

旧 `excluded` 转明确关闭；旧 `custom` 在未排除时保留启用，无法证明原始操作来源时标「此前已启用」。扫描缓存不提升为明确决定。优先读取旧总开关显式值；无该值但能确认是旧档案的，保留旧有效默认；完全新档案默认关闭。检查并禁用会覆盖该规则的默认开启迁移分支。

旧样式/位置/指标集完整保留。透明度按样式缺省时取现有视图的正式默认程度，由统一外观所有者登记，文档不另复制一套默认常量。

迁移保留旧键用于回退核对，但新版本运行时只使用一个权威决定集合，禁止两个集合双向推断。持久决定变更同步兼容旧版的 custom/excluded 表示，或在回退交付前导出兼容值，确保回退到旧版也不会丢失本次关闭；兼容写仅是输出适配，不能反向覆盖新决定。

### 6. 透明度作用于背景，按样式保存

设置页显示「背景透明度」，范围和方向见规格；内部用明确的归一化字段，绘制时只在背景层执行 `alpha = 1 - transparency`。禁止修改整个 NSPanel 的 alpha 或对整棵 HUD 视图使用 opacity，避免文字一起变淡。

卡片与顶部横条共享外观解析/背景组件，但保存各自值，沿用各自既有默认外观；这避免单一新默认静默改变任一种现有样式。当前样式只有一条滑杆，切换时读取该样式保存值，恢复默认仅作用于该样式。顶部横条回退卡片时使用实际渲染样式的值，预览清楚反映当前所见样式。

值更新既写偏好也驱动现有 HUD 内容刷新，不重建测帧、采样或整套面板材质；用户返回游戏即可看到效果，不承诺失焦后继续显示。全透明仅去掉黑色背景，现有文字、分隔线、目标标识仍按自身样式绘制。

系统提高对比度、减少透明度等环境偏好如作用于正式渲染，同一解析结果必须进入预览；不得只对预览加不一致滤镜。正式组件仍维持现有背景合同，不借本次引入额外材质策略。

### 7. 内嵌预览复用正式组件

预览是 Game HUD 设置「外观」分组内的原生 SwiftUI 子视图，不是另一个 NSPanel。场景用本地静态图形构造明亮、深色、复杂三种可切换画面，不下载图、不采集桌面。示例名称和固定数据由预览专用 fixture 注入，标注「模拟预览 · 示例数据」，从不写 MonitorStore 或采样历史。

`GameHUDView` / `GameHUDTopStripView` 接受同样的外观、目标名和指标输入；`GameHUDContent` 或共享渲染入口用于真实面板和预览。小画面可将完整 HUD 作为整体缩略显示，并标注缩略/提供放大查看，不能修改正式字体字号和指标布局来迁就容器。缩略变换仅属于预览宿主，不改变真实窗口几何算法。

预览背景切换是临时预览状态，不改变系统主题。样式、位置、指标、透明度使用正式偏好即时联动；后台没有定时器，改变控件才更新，关页即停止视图工作。支持总开关关闭和未运行游戏的情况。

### 8. 旧计划衔接与规格所有权

`openspec/specs/` 当前没有 game-hud，故本计划该 delta 使用 ADDED 并复用同名能力路径；settings-window/monitor-panel 的新增要求也使用 ADDED，不改写无关旧要求。已有 `add-game-hud` 的点击穿透、窗口归属和性能门槛仍有效；其保守名单、自动候选不持久化与旧设置描述中冲突部分以本次已确认决定为准。

实施阶段先核对两个 change 和当前源码，整理冲突映射并同步旧条款；旧 change 其余未完成验收不阻断本次已授权实现，也不得被顺便勾完。本计划归档前，若旧 change 已建立 game-hud 主规格，必须将本次对应已有条款重整为完整 MODIFIED、其余保持 ADDED，再严格校验；不能重复 ADDED 同名要求或覆盖已存在指标/窗口规格。归档顺序串行处理，当前不归档任一 change。

## Risks / Trade-offs

- [Steam/Epic 安装记录包含工具或多个应用包] → 自动资格要求身份和本体关联明确；不确定时待确认；测试强证据正例与工具/启动器负例。
- [弱证据候选未显示会降低自动发现感] → 菜单栏主动打开时呈现当前候选，设置保留待确认和浏览添加；不以先覆盖游戏换取可发现性。
- [识别缓存残留或扫描竞态] → 证据与决定分离、按轮次合并、显示令牌撤销、旧扫描不得复活关闭项。
- [小预览与真实游戏尺寸不同] → 复用绘制输入、明确缩略示例、必要时放大；原生全屏/Space 及复杂背景仍需实机验收。
- [全透明在部分游戏背景上对比度不足] → 提供三种背景与恢复默认，默认沿用当前程度；不宣称任意透明度在任意画面都可读。
- [旧登记来源不明确] → 保留原启用而标此前已启用，不伪称用户确认；不因此清空旧偏好。
- [多语言长标题挤占] → 使用原生可换行说明、完整可访问名称与可达动作，实测中英及新增日文，指标数值不缩放/截断；新增静态指标标签时更新对应宽度契约。
- [App Store 共享代码误引用官网版符号] → 编译条件和装配入口维持渠道隔离，构建两渠道并重启检查共享入口。

## Migration Plan

1. 冻结实际源码、既有偏好格式和两份 change 的冲突映射；建立可重放迁移夹具，不修改真实用户偏好做测试。
2. 实现版本化登记与纯决策，完成迁移与竞态回归后切换扫描、名单和会话消费者；同步收紧候选引发的副作用。
3. 接入稳定目标快照、逐应用关闭/恢复和实例暂停，验证打开面板的激活通知时序。
4. 接入共享外观与透明度，再用同一组件建立预览、目标名和本地化；不增加新数据采集权限。
5. 执行 tasks 的自动化及真实原生验收，记录实际未完成项；完成后才考虑用户另行授权的 Git 保存、归档或发布。
6. 回退时保留版本化快照，保证最近逐应用关闭已输出至旧版可识别排除记录，再恢复旧二进制。新版透明度键可保留由旧版忽略；不能用清空偏好作为回退。

## Acceptance Evidence

实施记录统一放 `tmp/game-hud-control-preview/`，记录构建版本、系统版本、样式、输入夹具、预期/实际与截图或操作结果。核心用例为：Swift Craft Launcher 等价弱证据负例及真实复现、可靠游戏正例、每条显示记录都可管理、关闭后跨重扫/重启不恢复、本次隐藏实例隔离、点击菜单栏后的正确目标、手动未扫描项、透明度端点与按样式保存、无游戏/总开关关闭预览、全屏/Space/点击穿透回归。自动测试、构建、原生目测分开记录；环境缺失标 BLOCKED，不以模拟预览替代真实游戏证据。
