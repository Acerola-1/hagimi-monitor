# Design

## Context

动机见 [proposal.md](proposal.md)，行为合同见 [game-hud](specs/game-hud/spec.md)、[设置页](specs/settings-window/spec.md) 和 [主面板](specs/monitor-panel/spec.md)。本次修订依据用户明确选择：所有有效识别结果直接采纳，误判通过黑名单纠正。

当前基线仅包含计划，未合并 A–D 实验代码。实验分支和 worktree 已按用户要求删除，新的执行者从基线源码实现，不从旧实验挑选代码。首轮用户截图与反馈作为失败用例参考，不能作为当前代码已修复的证据。

现有实现的主要约束：扫描器存在全量快照与即时激活两条发现路径；目录把扫描 ID、手动添加和排除组合；设置页偏重扫描快照，未扫到的手动项会进入失效区。卡片与横条各自绘制黑色半透明背景。设置采用固定窗口宽度，公共设置容器、颜色和几何已有所有者。

## Goals / Non-Goals

**Goals:**
- 在最少状态下闭合自动发现、手动添加、排除、移出排除四条路径。
- 名单和显示资格读取同一份记录；来源与用户决定不互相覆盖。
- 默认行忠实于选定截图，所有按钮在固定宽度内可见，预览以可读性优先。
- 开发者先自行运行设置页检查布局，再交付给用户评价；真实游戏验收单列。

**Non-Goals:**
- 不实现待确认、置信度同意、主面板新入口/说明/上下文、管理深链或本次隐藏进程系统。
- 不绘制大游戏场景，不把完整 HUD 全指标缩略作为透明度预览，不增加放大/回到缩略的模式切换。
- 不增加权限、硬件采样、外部依赖、注入、受控启动或 App Store HUD 能力。
- 不把使用 Metal/OpenGL 作为识别依据，不承诺 Java/模拟器宿主内部游戏的新识别能力。

## Decisions

### 1. 名单状态只有启用与排除，来源单独保存

在现有目录/设置数据通路中建立统一的应用登记所有者。最小记录包含应用身份、可用名称/路径、来源集合、手动添加意图和包可用性；用户黑名单独立保存并具有最高优先级。不另建待确认状态机，不持久化一份会与来源漂移的自动允许布尔值。

显示资格为：存在有效自动来源或手动添加意图，且不在黑名单；最终显示继续要求总开关、前台和可靠窗口。来源描述与获取渠道分开：Steam/Epic 清单、应用包游戏类别是证据，扫描/激活只是获取方式，不能用目录名字伪装清单来源。

目录登记集合包含自动识别、手动添加、黑名单和必要的最近已知项，列表从该集合投影。先完成登记再发布运行时资格，避免可显示却没有管理行。重扫合并元数据，不能替换手动/黑名单；扫描未返回不等于卸载。确认包未找到时给辅助说明，不删决定。

替代方案：让每个视图临时拼接三个集合。它会重复造成名单与判定不同源，因此不采用。也不引入与本需求无关的活动历史或复杂审计数据库。

### 2. 自动发现不再有确认门槛

保留安装记录扫描和类别发现，统一汇入登记后自动采纳。类别等来源不因较弱而进入候选；主面板和设置都不出现接受/拒绝首次识别的询问。

Steam/Epic 尽量关联实际游戏包，避免目录中随便取第一个 `.app`；仅路径相似不是充分依据。基线已有的商店/平台本体过滤可以保留为发现规则，但不另建隐藏的运行时否决集合：凡实际获得资格的身份都必须在设置中出现，用户手动添加可以覆盖发现过滤。一个通过有效类别识别而误收录的启动器仍按用户选择直接采纳，纠正入口是黑名单。

修复类别发现的语言依赖，稳定应用包类别可作为核验依据；Spotlight 只是可缺失的索引，中文类别/英文类别与子类别都有夹具。保持缓存、后台扫描、事件去抖，不在每秒轮询中枚举安装应用。关闭总开关时停止 HUD 专用常驻监听；用户在设置明确刷新可执行一次扫描，扫描本身不打开总开关。

替代方案：弱证据先确认已被用户明确否决，执行者不能以精度优先为由重新引入。

### 3. 添加、排除和恢复直接修改单一所有者

「添加应用…」选择有效 `.app`，读取身份/名称/路径，建立手动添加意图并解除同一应用黑名单；重复添加更新同一条记录。「添加排除…」允许选择任意有效应用包，登记身份/名称后写黑名单，不要求它先被发现。

行内「排除」只写黑名单，保留自动来源/手动意图；「移出排除」只解除黑名单，按原来源恢复正常资格。仅为提前排除登记的应用没有启用来源时，解除后给简短反馈，不凭空当成手动添加，用户可再点添加应用。两种可逆操作不增加模态确认。

排除操作先保存决定，再同步隐藏目标/停止测帧，完成后反馈。所有快照、测帧和几何呈现回调在显示前复核当前资格/会话代次，晚到结果不能复活目标。名单变更在主线程发布，扫描在后台产生结果，不能在渲染阶段修改集合。

现有 per-app 官方 HUD 偏好清理不能继续由任意发现项触发，至少收紧为总开关开启且目标真正允许的运行时路径。黑名单、设置刷新和预览不触发第三方偏好修改；不扩展此行为。

### 4. 视觉参考拥有名单方向，按钮是必须补足的交互

唯一确认的视觉输入是 [list-style-reference.png](assets/list-style-reference.png)。其图标/名称/浅蓝标记/来源两层阅读顺序应保留；截图不是完整操作稿，不能以截图中没出现按钮为由省略排除。

使用现有 SettingsPage/SettingsGroup/SettingsRow、MonitorPalette 与系统主题。自动识别标记沿现有 accent 语义作轻量浅底，不为每行增加多种颜色或内部状态串；手动项用相同结构的手动添加标记。来源只用一行简短用户语言，内部身份、扫描时间等最多作为辅助 tooltip，不默认堆在每行下方。不新增展开详情箭头和多级管理菜单。

名单结构：

```text
应用与游戏                    [重新扫描] [添加应用…]
┌──────────────────────────────────────────────────┐
│ [图标] 名称  [自动识别]                    [排除]   │
│        Steam                                      │
│ [图标] 名称  [手动添加]                    [排除]   │
│        用户选择的应用                             │
└──────────────────────────────────────────────────┘
已排除                              [添加排除…]
┌──────────────────────────────────────────────────┐
│ [图标] 应用名称                        [移出排除]   │
│        保留的真实来源                             │
└──────────────────────────────────────────────────┘
```

优先保持名称旁的标记；空间不足允许名称换行，行尾动作不被挤走。空黑名单显示简短空状态并保留添加排除。长名单沿现有页面纵向滚动，不为了减少行数隐藏必须操作。

替代方案：把规则、原因、来源、时间全部默认展开，会重复首轮列表杂乱的问题，因此不采用。

### 5. 固定宽度由父级约束，先解决自然尺寸传播

正式设置窗口与侧栏宽度不改。详情从公共容器取得可用宽度，减去同源内衬后约束每个分组、行、滑杆及预览。不得让顶部横条的 `fixedSize` 或宽 HStack 的理想宽度向上撑大详情树；不能只在最外层 `clipped` 把按钮藏起来。

行内先为尾部按钮保留可用空间，再让名称/来源区弹性收缩或换行。公共 SettingsRow 不适合多控件宽行时，在该分组内使用现有支持的多行结构，必要时修正共用原语的受控变体，不随意修改其他设置页。左右内衬继续由现有组件/常量拥有，不在调用点复制一套尺寸。

原生截图需覆盖卡片/横条、全部正式指标、长中英文名称、名单为空及排除后状态。任何行尾按钮、透明度值或控件越界即验收失败，不能靠扩大窗口或缩放整页规避。

### 6. 背景透明度只有一个当前样式控件

样式分段、卡片位置继续沿用正式设置。透明度一组只显示一次标题、滑杆、百分比及恢复默认，附一句「仅改变背景，文字不变」。当前样式保存一份值，卡片与横条默认分别从既有正式背景常量集中登记；不要把两种样式静默统一成一个新默认。

内部归一化数值，背景 alpha 为 `1 - transparency`，仅作用于背景填充。不能修改 NSPanel 整体 alpha 或整棵 HUD 的 opacity。非法值夹取或回退；样式回退使用实际渲染样式的偏好。更新走现有内容观察链，不重启采样/测帧，不重建材质。默认和参数由一个外观所有者维护。

### 7. 预览展示局部效果，正式字号优先

透明度下方放一个浅背景容器，呈现少量静态示例（例如 FPS 与 CPU），而不是完整已选指标。两种样式均复用正式字体、背景和指标行/片段渲染；给预览传入独立、固定的小型示例目录，不改用户真实勾选集合，也不复制出第二套 HUD CSS/绘制代码。

样本按正式字号显示，不使用 scaleEffect 缩小。预览宽度受详情约束，卡片可以显示头部及少量指标，横条显示能完整容纳的少量指标。容器只留观察背景的必要内衬，无宽阔空场景；建议共享预览高度上限为 140 逻辑点，任何样式超限应减少静态样本内容，不压缩正式文字。此上限为本次新增的预览几何契约，实施时仅由一处常量登记。

背景用静态明亮/深色/复杂底纹，无大型太阳/草地等场景插画。默认背景对比清楚，切换可用标题旁一个紧凑原生菜单，不再在预览底部铺一排大型模式按钮。始终标「示例预览」，没有缩略/放大/回到缩略模式。

示意：

```text
外观
显示样式                          [顶部横条 | 卡片]
背景透明度                    ───●────  43% [恢复默认]
仅改变背景，文字不变。
示例预览                               [背景：明亮 ▾]
┌──────────────────────────────────────────────────┐
│            FPS 60.0  |  CPU 12%                   │
└──────────────────────────────────────────────────┘
```

正式 HUD 指标仍完整显示并遵守实际窗口回退/隐藏；只允许预览选择少量示例。预览不证明正式窗口能装下全部指标，正式几何单独测试。示例数据不进入 MonitorStore、历史、帧统计或导出；没有计时器、截图、游戏启动或新权限。

替代方案：完整缩略预览会让文字不可读，局部裁切完整长横条又会丢掉开头/末尾，均不采用；应在输入层选择完整可读的示例片段。

### 8. 偏好迁移与主面板回归

只迁移正式基线已存在的 custom/excluded/总开关、样式、位置和指标。排除优先，旧添加统一按手动添加呈现（内部保留迁移来源）；显式总开关值优先，无显式值但可识别旧档案按原有效默认兼容，完整新档案默认关闭。迁移幂等，损坏新版数据保留旧记录与可恢复备份，不清空用户选择。

新登记格式使用明确 schema。A–D 不是正式发布版本，不以它们的实验登记格式作为必需升级来源，也不读取不兼容实验快照来推断用户意图。开发和验证使用隔离偏好套件，不删除用户真实偏好；删除实验文件不等于重置运行时偏好。

新版本只有一个权威决定所有者，向旧 custom/excluded 输出兼容值用于回退，禁止反向双向推导覆盖新决定；重启后黑名单不丢失。本文不要求复杂数据库或完整活动历史。

主面板代码原则上不需要修改。若为共享设置/装配作必要调整，必须对照基线确认没有新 Game HUD 入口/说明/状态区，原菜单栏点击开合和底部入口正常。首次开启说明只在设置页简短呈现，不挤占主面板。

### 9. 先做原生自查，再交付用户验证

开发过程先跑通固定宽度的设置页骨架与局部预览，以参考图检查列表节奏和按钮可达，再接入完整动作。首次原生截图后由执行者自查并修复溢出/不可读问题，不把等待用户评价当成停止基本检查的理由。

在隔离测试偏好下执行「添加未扫描应用 → 排除 → 重扫 → 重启 → 仍排除 → 移出排除 → 恢复」和「提前排除 → 后发现 → 仍排除」闭环。生成截图时允许运行正式应用的隔离验收实例，不关闭用户其他实例、不覆盖 /Applications；若无法安全隔离或缺少原生访问能力，诚实报告视觉验收未完成，完成其他可执行工作。

截图、操作日志、构建与用例结果放 `tmp/game-hud-control-preview/`，记录提交、系统版本、样式及输入；真实 Swift Craft Launcher、真实游戏正例、全屏/Space/穿透仍单独记录。首次交付只称已实现候选，只有对应证据齐备才标相应任务通过。

## Risks / Trade-offs

- [自动采纳类别识别可能误收录普通软件] → 这是用户已选择的行为；来源可解释、每项可排除、黑名单覆盖全部来源，不再偷偷改回确认制。
- [手动/黑名单项没有扫描元数据] → 浏览时先登记名称/身份，失去应用包时保留可用名称；回退通用图标，不要求用户手输 ID。
- [预览抽取共享渲染影响正式布局] → 共享字体/背景/行，预览目录独立；正式全指标和窗口回退回归测试分别覆盖。
- [高透明度在部分背景不易读] → 提供正常字号局部示例和恢复默认，不宣称任意背景都可读。
- [主面板点击失效] → 不增加上下文/路由钩子，运行重复打开/关闭和从设置返回后呼出回归。
- [原生环境缺失] → 构建与逻辑验证继续，原生视觉任务保持未完成；不能以静态断言代替截图。
- [在途旧 change 的条款冲突] → 当前 change 的已确认选择优先，同步受影响条款，保留无关窗口/指标边界；归档串行处理。

## Migration Plan

1. 从当前基线源码开始，读取本次修订和参考图；不恢复 A–D 代码。
2. 先实现同源登记、黑名单及迁移与确定夹具，确认旧偏好不丢失。
3. 做固定宽度名单、局部预览和原生自查，再接入扫描/会话及完整操作；主面板维持基线。
4. 收紧排除后的异步呈现和发现副作用，运行两渠道构建、逻辑/几何回归及原生设置闭环。
5. 保留 `add-game-hud` 的窗口/真实数据约束，修订其冲突名单/设置条款；若归档前已有 game-hud 主规格，则将对应 delta 转完整 MODIFIED 后重新校验，不覆盖其他要求。
6. 用户另行授权 Git 保存/发布/归档时执行。回退保留版本化数据和旧版兼容排除值，不通过清空偏好回退。
