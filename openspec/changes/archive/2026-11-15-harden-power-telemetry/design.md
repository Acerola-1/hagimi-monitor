# Design

## Context

IOReport 当前为单例且按 250ms 复用，GPU/内存/电源分别调用；状态只剩 Double?。Direct 私有接口与 App Store 源码保持隔离。经典毛玻璃与紧凑指标格不变。

## Goals / Non-Goals

**Goals:** 本机 CPU 恢复真实计数，屏幕间歇零增量不再直出假零；异常差分可恢复；各功率语义一致且可确定性测试。

**Non-Goals:** 不恢复旧流向图、不增加分项、不构建特权 helper、不把模型估算称为电气仪表真值、不声称完成无法访问的 M3/真实睡眠硬件验收。

## Decisions

1. 共享的 PowerReading 仅包含值/状态/来源/观测时间/区间；MonitorMetric 可选携带该元数据。UI 悬停提供业务化说明，不显示驱动、渠道等内部术语；诊断探针输出完整来源。采样计算不执行本地化。
2. 新增纯计数区间解算器，保留每条 rail 的 Int64 原始值与缩放，先分别差分再求和，避免累计量经 Double/Int64 往返。源身份或单位/成员变化即重建基线；每条必需 rail 都要通过验证，不能只求和成功解析的子集。通用能量源与 DCP 分别按下文状态规则解算。
3. 屏幕初始候选最小区间 2s、有效时效 5s；同源短窗内等待计数更新，时效后缺失。这是保守策略参数，不是已证实的硬件刷新周期。屏幕活动状态改变清除区间；只有源更新且屏幕非活动时允许持续零，活动状态未知时不输出推定零值。参数集中管理，经本机连续采样验证，调整需记录依据并更新边界测试。
4. macOS 27 的 CPU/ANE 优先验证 macmon 公布的按驱动 allowlist 的 CLPC aggregate report ID（nJ）。准入、来源切换和计数健康是三个独立检查，详见下文；未知版本/驱动不试猜。保留 MIT 署名及许可。每个来源独立追踪，避免新源失败污染旧源基线；GPU 保留现有 AGX 能量源。
5. Subscription 通过现有采样入口管理，失败后按退避上限限频重试；连续读失败或长暂停失效重建；重新发现基于 driverID+channelID，不按名字丢弃其他驱动。使用包含睡眠的单调时钟识别长暂停；无独立计时器。SystemMonitorSampler 在一次 frame 开头取遥测，通过显式输入给三个消费者，单独调用仍可安全采样。
6. 整机负载解算与 battery-flow 分开，输入分别是 IOPS 状态、实测功率和明确的电池幅度有效性，不互相递归推导。整机优先 PSTR/SystemLoad；无负载实测时，已知充电为 input−battery、已知放电补差为 input+battery、纯电池为 battery，无法确定流向/幅度时不推导。取消 PDTR 冒充负载。电池流向继续只由 IOPS 状态判定，Direct 纯电池时仍优先取当前 systemPower（正常即 PSTR）作为负幅度，再回退到 BatteryPower。充电回退仅用已验证的 pack voltage × signed instant current 的幅度，无法确认时缺失。派生值标为估算并与实测来源分开。
7. IOPS unavailable module 保留 placeholder，用于隔离未知电池状态；额外携带的独立组件只向拓扑的四项指标放行，不取消任一消费者的全局 placeholder 保护。下文列出逐消费者契约及集成断言。

### 通用能量源：状态与时间边界

以下规则适用于已经通过来源准入且提供有效源时间戳的 CPU/GPU/ANE 能量源。CLPC 不提供时间戳的情况仅适用后文专用规则。源身份包含实际 registry driverID、完整 64 位 channelID、格式、单位及必需 rail 成员。`t` 是包含睡眠的单调观测时间；`τ` 是 RawElements 的源时间戳，不是报告创建时间。先确认时间基准/非零值及解析范围，不能以本轮调用时间冒充源时间戳。

- 首份完整样本只建基线，状态为预热，不输出瓦数。首份之后 5s 内仍没有可用区间，保持预热；达到 5s 时，有完整重复样本且 `E、τ` 都不变判冻结，缺报告/缺时间戳或来源尚未准入判暂缺。两种状态都不输出数值。
- 已有有效区间后，`τ` 前进且 `E` 非递减、单位与成员不变，才可形成新区间；差分为零时允许 0 W，不需要 ANE 每轮都产生正能量。`τ` 不前进而 `E` 变化属不一致样本，丢弃并重建，不算有效增长。
- 已有有效区间后，完整样本 `E、τ` 同时不变，前 5s 判暂缺，到 5s 判冻结；该期间不把上一数值作为新观测发布。缺报告/缺字段是暂缺，不能仅凭缺报断言驱动冻结。缺报会中断差分连续性。
- 源时间戳曾停顿后，首次出现正增量的样本可能包含此前积累，也必须只重建基线；健康源时间戳前进且能量不变的零值区间不触发此保护。避免把 5s 阈值以下的停顿补报除以后一个短轮询间隔。
- 冻结、缺报中断、来源/单位/成员变化、计数回退或观测间隔超过 30s 后，下一份完整样本只重建基线；该份可能含补报，绝不输出瓦数。随后第一份 `τ` 前进的完整样本若差分为零，允许立即恢复为 0 W；不额外要求再一次正增量。
- 元数据不合法、负计数/无效哨兵、溢出、非有限值或超出经平台验证的合理功率范围，均不输出有效值。冻结恢复丢弃的跳变量不能用于 CLPC 准入；通用 1000W 上限不能单独作为新映射正确的证据。

### DCP：独立的屏幕区间规则

- 已有证据显示 DCP 的 `τ` 可能前进但 `E` 未变，因此通用源的“新时间戳 + 零差分”规则不适用于活动屏幕。
- 活动屏幕只在至少 2s 的同源完整区间中输出正能量平均值；单帧零增量可以进入该区间，但不能直接生成单帧 0 W。尚无有效区间时显示预热/等待更新。
- 等待下一次能量更新时，最多展示距最后正增量观测不足 5s 的已有区间结果，并保留原区间端点和观测时间，不刷新成新实测。达到 5s 不再展示该数值：`τ` 仍前进时为“能量更新暂缺”，`E、τ` 均停止时为冻结。两者下一次完整能量更新都先重建基线，防止延迟补报尖峰。
- 已确认内屏非活动且源时间戳在至少 2s 的完整区间内前进、能量零增量，才允许 0 W。无内屏、屏幕状态未知、时间戳不前进或读取失败，均不能由“关屏”推算瓦数。
- 屏幕状态改变、缺报、复位、来源变化和长暂停清空旧区间；恢复后重新满足最小区间，不将活动时的旧值带进非活动状态。

### CLPC：准入与切换验收

- allowlist 项必须记录系统大版本、精确驱动 bundle ID、完整报告 ID、预期格式/单位及依据版本。以实际 registry ID 绑定该驱动；核对订阅实际返回的 driverID、完整 channelID、格式及单位，不以显示名、低 32 位 ID 或请求数组下标匹配，也不接受缺失成员。
- CLPC 各 rail 在当前订阅代次内，至少观察到一次时间戳前进的正增量，且区间/功率合法，才完成该 rail 的动态准入。一直为零即使时间戳前进也不能证明该映射可用：5s 后标为“来源尚未验证”，继续限频检查或使用已健康的旧源。ANE 首次真实工作前可能保持缺失，这是保守准入的明确取舍，不可填零掩盖。
- 通过准入后，ANE 空闲遵循通用规则，时间戳前进但计数不变即可输出 0 W。冻结不撤销同一订阅代次已确认的身份，但会切断差分；重建订阅、身份/单位变化则清除准入证据，必须重新验证。
- 新候选需有两个连续有效区间（其中至少一个正增量）才可提升为首选；仅因单帧暂缺不来回切源。当前源连续 5s 无有效新区间或身份/格式失效时才退到已准入的健康备用源；没有备用源就显示缺失。
- 每次切换都以候选当前样本重新建选中源基线，切换帧不输出候选的历史功率；下一份新时间戳样本再出值。同源取样、切换和订阅重建均需记录身份/代次，避免跨源相减。映射正确性还需本机负载响应及同机对照，不能只用“正数且小于 1000W”验收。

### CLPC 无时间戳驱动的专用规则

本机 M4/macOS 27.3 的原始报告显示：CPU 能量计数持续增长，但 CPU/ANE 的 RawElements timestamp 都恒为 0。该事实采用保守规则：采样调用时间不作为源时间戳，真实增长按连续正增量准入。

- 仅在已精确匹配的 CLPC 报告上启用无时间戳策略；其他来源不放宽。读取时间采用包含睡眠的单调时钟，来源身份明确记录无源时间戳。
- 必需 rail 均连续产生合法正增量时才计算正功率，仍需两个连续有效区间才能提升来源，切换帧仍重建基线。时间戳缺失的 CLPC 不支持“健康零”判断；零增量显示暂缺，冷启动持续零超过 5s 为来源未验证，不宣称冻结或真实空闲。
- 一旦零增量、缺报、复位或长暂停中断连续增长，恢复后的第一份增长仅重建基线，后续连续增长再出值；不把补报或零值间隙整体除以最后一秒。
- 具体回归序列 `(t,E,τ)`：`(0,100,0) → (1,110,0) → (2,120,0)` 可以形成候选正功率；`(3,120,0) → (8,120,0)` 均无数值，`(9,9000,0)` 丢弃补报，`(10,9010,0)` 恢复正功率。冷启动 `(0,0,0) → (5,0,0)` 保持未验证，不能准入。上文“恢复后允许健康零”只适用于有有效源时间戳的驱动。

### IOPS 失败：逐消费者契约

- 采样模块明确输出 `type=battery-unavailable`、`status=unknown`、`summary=--`、`isPlaceholder=true`。四项独立指标为 `display-power/cpu-power/gpu-power/ane-power`；每项按自己的 PowerReading 有效性输出值或缺失。旧电量 value 若为模型兼容而保留，只是内部缓存，任何显示或统计都不得消费为新真值。
- 拓扑网格是唯一的电池占位模块分项例外：仅上述四个名称可透传。用户已开启其中任一项时，拓扑可展开并保留当前页；健康/供电页不因独立分项而被视为有效，也不展示缓存健康指标或“未连接”。占位供电状态显示未知。没有已开启分项时按现有缺失布局收起，不新增空白页。
- 电源行头、PowerReadings、菜单栏电量/整机功率和辅助功能读数继续拒绝占位模块的电池值。整机 `power`、输入 `power-in`、额定适配器、充电功率、battery-flow 和 ETA 不回填上一帧，不从独立分项凑出整机。
- 电量 samples 不追加缓存值；占位期间隐藏电量曲线，历史数组只作缓存，恢复帧以本轮真实值重新开始可见曲线，避免画出跨未知区间的连续观测。
- StatisticsRecorder 继续跳过整个占位 battery 模块，不录入电量、功率、AC/充电占比或电池慢指标；不为了分项更改全局过滤。独立 CPU/GPU 模块各自的有效统计照常。ReportLiveReadings 对该 battery 模块继续返回 nil，本次不扩展其字段或放宽过滤。
- 集成夹具必须包含“上一帧有效电池数据 → IOPS 失败但分项有效 → 状态恢复”：断言主读数缺失、status unknown、独立指标及页签可用、无旧电量曲线新点、统计无 battery 增量、报表实时电池行缺失；另覆盖没有有效/启用分项与全分项暂缺的情况。

### 确定性输入序列与回退回归

序列表示 `(t秒, 累计E, 源τ)`，τ 的示例数是同一时间基准下的单调标识；测试夹具需显式提供合法元数据/准入状态、可控时钟和屏幕活动状态，不用真实 sleep。下列是断言输入，不是新的硬件实测：

- 已准入通用源健康零：`(0,100,1000) → (1,110,1100) → (2,110,1200)`，首份预热，后两份分别为正功率、0 W。
- 冻结零：`(0,100,1000) → (1,100,1000) → (5,100,1000)`，首次/1s 仍预热，5s 冻结；若从已有有效区间进入相同重复序列，5s 前为暂缺。
- 冻结后的补报与健康零：接冻结序列，`(6,9000,1600) → (7,9000,1700)`，6s 丢弃补报并预热，7s 在同代次已准入的前提下恢复 0 W。
- CLPC 冷启动持续零：`(0,0,1000) → (1,0,1100) → (5,0,1500)`，不能准入或显示 0 W；另测正增量后两个有效区间准入、切换帧重建、后续健康零恢复。
- 活动屏间歇更新：`(0,100,1000) → (1,1100,1100) → (2,1100,1200)`，2s 可得到正区间均值而非零；继续到 `(6,1100,1600)` 则达到距上次正增量 5s，显示能量更新暂缺；另测 τ 也停止时为冻结及恢复丢补报。
- 非活动屏真零：屏幕已确认非活动，`(0,100,1000) → (1,100,1100) → (2,100,1200)`，2s 允许 0 W；相同计数但 τ 固定或屏幕状态未知时不能输出零。
- Direct 纯电池：PSTR=10W、BatteryPower 幅度=6W 时，整机=10W、battery-flow=-10W；PSTR 不可用再按原优先级使用有效 registry 负载/电池幅度。正负 BatteryPower 编码不改变方向，不能以补差回退改写该语义。
- 插电补差：IOPS 未充电/已连接且确认放电幅度=10W、input=45W、无实测负载时，派生整机约 55W、battery-flow=-10W；已知充电同组幅度时整机约 35W、battery-flow=+10W。状态/幅度未知时不套公式。
- 单位：覆盖 `0x0300007f00000000`（十进制指数字节 127，即 10^0 J）和 Apple scale-unity 特例 `0x0300000000000000`；`unit=0` 不含 Energy quantity，必须拒绝。另测 mJ/uJ/nJ、常数/二进制缩放与非法编码。

## Risks / Trade-offs

- 私有 report ID 随系统变化 → 精确驱动/大版本门控、订阅返回校验、健康检查和未知平台回退；M3 映射可单测但不冒充实机证据。
- 屏幕短窗引入约数秒响应延迟 → 明确区间说明，5s 后不再使用旧值；不以额外高频采样弥补。
- 多来源数值边界不同 → 同来源内差分、切换重建，不强制分项相加等于整机。
- 元数据可能扩大 UI 更新 → 仅功率指标携带，沿现有主线程发布，不引入后台 UI 状态或逐帧动画。
- CLPC 冷启动 ANE 只有零计数 → 保守保持来源未验证，首次有效正增量后才建立健康零语义；不将这类缺失误报为冻结或宣称所有机器启动即可显示零。

## Migration Plan

先完成纯模型及上述序列回归，再接入 CLPC/订阅管理和消费者，最后接 UI 说明及本地化。构建两渠道，实际运行并记录功率、宽度、排版及 SamplingGateStateTests 等门控测试；重启两版检查，真实采样记录完整身份、准入、来源切换与负载响应。无需偏好/数据库迁移。未覆盖的硬件项目保留为后续验收。
