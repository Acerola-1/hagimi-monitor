# Design

## Context

动机见 `proposal.md`。当前默认路径由 `MonitorPanelView` 的展开高度插值、`PanelExpansionDriver` 的高度预测及控制器的窗口弹簧共同工作；已有 `SingleHostMotionCoordinator` 实验仍含主线程显示帧提交和真实窗口 resize。此前归档方案和本次认可 Demo 不是同一架构，不能复用其“通过”标签或只打开旧实验开关完成迁移。

本次参考为 `prototypes/panel-motion-demo/NativeCPUMotionDemo.swift` 和 CPU 正式组件适配脚本。Demo 采用固定透明窗口、完整自然尺寸宿主、系统图层弹簧、同步遮罩/位移/轮廓，并保留真实数据。其双渠道构建及 CPU 操作证据仅支持当前 CPU 原型，不证明全模块、滚动、透明区域事件或完整应用收益。参考清单见 `reference/demo-baseline.md`。

项目最低支持 macOS 15，正式风格为经典毛玻璃。当前排序变更仍在进行，显示器/电源存在嵌套及专用交互；这些是正式迁移的组成部分。

## Goals / Non-Goals

**Goals:**

- 将认可的运动方式用于所有可用模块与两种面板控制器，同一个 change 完成全量交付和验收。
- 让普通展开动画的主线程工作集中在目标提交与结构变更，不逐帧触发 SwiftUI 排版、全局发布或真实窗口高度调整。
- 以稳定几何和真实组件保住内容细节、材质层次、输入、滚动、焦点及后台生命周期。

**Non-Goals:**

- 不改采样算法、统计口径、权限及渠道能力；不把 Demo 的精简 Store 初始化、独立 Bundle ID、设置导入或控制窗复制进正式应用。
- 不重做设置窗口、统计报表、独立 HUD、应用图标；不新增 Liquid Glass 实验。
- 不使用位图快照、文字缩放、私有窗口 API 或降低实时数据采样频率换取运动流畅。
- 不替其他进行中的 change 完成或勾选尚未实现的功能。

## Decisions

### 1. 固定承载容量，动画改变可见轮廓

菜单栏、快捷键和置顶面板使用屏幕约束内的透明容量窗口。一次显示会话中的普通展开/收起不改变真实窗口尺寸；内容变高时通过可见遮罩和轮廓揭示，超限部分进入主体滚动。窗口移动、跨屏、宽度/缩放环境变化时可在受控的环境提交中重新设定容量，不把容量变化混进逐帧展开链路。

标题、模块和底部入口采用正式组件。标题固定；封顶时模块和底部入口依照正式面板现有主体滚动规则呈现，不额外改成另一种工具栏布局。外框圆角、描边和阴影由当前可见路径提供，避免系统阴影围绕整个透明矩形绘制。底座仍为 `.popover / .behindWindow`，行材质仍为 `.menu / .withinWindow`，使用现有主题令牌及宽度/内衬常量。

备选的真实窗口逐帧 resize 保留了原生矩形边界，但继续承担本次要移除的提交成本与两条边界链路；不作为新框架的正常展开实现。

### 2. 正式内容作为稳定宿主，共享运动适配层

提取原有行头、明细和专用组件的内容接口，为每个可展开节点提供稳定 ID、父子关系、自然尺寸及实际操作。宿主身份跨数据更新、展开和排序保持稳定，保留分页、编辑、焦点等内部状态；不维护一套手绘的 Demo 布局。内容在自然高度回报前也以顶部对齐；同一尺寸不重复失效固有高度，同一图层计划不因内容重测而重复播放。控制页与档案页可保留各自自然尺寸，但 AppKit 命中只进入当前逻辑页。

| 组件族 | 迁移范围 | 必须保留的差异 |
| --- | --- | --- |
| 通用指标行 | CPU、GPU、内存、磁盘、风扇 | 逐核/风扇、压力模式、卷列表、进程榜及图标、静态指标跨度 |
| 网络行 | 网络明细、状态和诊断、进程榜 | Wi-Fi/有线/断开切换、缺失值、现有聚合规则 |
| 电源行 | 功率流、健康、供电分页和诊断 | 分页状态、插拔电与充放电语义、拓扑及不同页高度 |
| 蓝牙行 | 设备列表和电量明细 | 零设备、连接/断开、设备名称与可用电量 |
| 显示器 | 主分区、逐设备及档案/控制明细 | 递归展开、设备身份、App Store 信息与 Direct 控制边界 |
| 面板公共区域 | 标题、工具/统计/设置入口、钉住与关闭 | 原有入口、手势、文案和布局优先级 |

显示器子节点使用同一递归适配，不给它另建 SwiftUI 高度动画。复用现有嵌套宽度解算和静态指标宽度登记；结构测量与指标文本宽度审计是两件事，不以运行时文字测量改变半行/整行归属。

### 3. 同一解析状态生成完整运动向量，由系统播放

集中迁移认可 Demo 的临界阻尼运动令牌。协调器管理各展开节点的位置、速度、目标、结构版本及统一时间基准；每次操作先求当前呈现状态，再将所有受影响量重基到同一时刻，在一个图层事务中提交。后续行位置、父子揭示、视口、可见高度、描边和阴影均从这一状态派生，不各自选择动画时长。

单节点线性情形可使用同参 `CASpringAnimation`。多节点交错、嵌套或跨封顶时，位置是多个运动的组合，而 `min(内容高度, 屏幕上限)` 存在分段边界：不能简单给所有属性各发一条起终点弹簧。此时从同一解析向量一次生成有限的 `CAKeyframeAnimation` 轨迹，所有属性共享时间点和几何解，之后交给系统播放；采样精度以派生几何误差不超过一个物理像素为验证目标。

正常运行不保留主线程显示帧动画驱动，也不逐帧发布相位或重新量尺寸。事件命中需要时查询当前轨迹/表现层；独立性能采集可临时采样，但不得成为正式动画的运行依赖。新操作和新结构版本取消过时完成回调；边界接触统一处理，既不露出空白，也不分别钳制各个运动量破坏关联。

### 4. 数据、尺寸与运动分别失效

采样继续沿原有 Store 队列和主线程发布路径。初期沿用展开期间的界面刷新门控，运动稳定后合并刷新最新快照；采样及统计不能因视觉门控被停掉，多个面板的可见期计数不能被破坏。

各宿主只刷新相关数据。值更新若不改变结构，不重新登记整块面板尺寸；语言、字体、宽度、指标显隐/顺序、核心数、设备拓扑和分页等形成明确的结构签名。尺寸登记生成新的完整版本，从当前运动重定向到最新几何。Demo 中对自然高度变化的立即贴合只是原型限制，正式迁移必须补成连续换版。

原生卡片的明细测量和摆放必须使用相同自然高度，不能沿用旧视口的零高度摆放提议。递归宿主必须将扣除本层左右内衬后的内容宽度传给下一层，使控件内容更新与布局测量使用一致宽度；不得在滑杆数值更新时先用父宽度改动宿主，再由布局恢复子宽度。

### 5. 封顶滚动与重排使用同一文档几何

复用现有滚动规则和纯滚动模型，以原生滚动宿主承载完整文档。自动揭示偏移与展开揭示从同一轨迹生成，处理跨封顶及解封顶；双击表头全部展开/收起以首个模块为顶部锚点，单行展开揭示该行；其他批量操作按可见顺序选择最后一个新展开分区，单次目标不能取无序集合的任意元素。

用户滚动开始时按当前呈现偏移重基，自动揭示让出控制权；原生滚动事件及惯性允许即时更新滚动偏移，不回流为展开动画的逐帧布局驱动。滚动范围按当前有效文档几何钳制，接管时不跳到预设终点。

现有排序的稳定 ID、持久化和作用域不变。重排命中、浮起预览、占位及边缘自动滚动使用当前文档坐标与呈现坐标之间的变换。对已实现的排序入口做适配回归；其他 change 尚未完成的长按能力分别记录，不擅自宣告通过。

### 6. 固定透明窗口必须补齐事件与辅助功能

可见外框之外的点击要到达下方应用，普通面板还要按既有规则关闭。单独让 `NSView.hitTest` 返回 nil 并不能证明窗口级输入穿透；此项是架构启用前的硬门槛。

实现使用公开 AppKit 能力，基于现有本地/全局鼠标监视和当前位置管理窗口是否忽略鼠标输入，并处理鼠标不动而轮廓从其下方经过的情形。边界重评估按运动交叉时刻或有限事件任务调度，只负责输入边界，不提交绘制、排版或真实窗口尺寸。所有任务在隐藏时停止；不得依赖新增辅助功能权限、事件注入或私有窗口 API。

原生验证覆盖点击、拖动和滚轮是否真正到达下方应用，透明圆角、动画中边界及置顶模式均要检查。若公开路径未通过，候选保持实验状态，先修正边界方案，不以关闭整个窗口的点击能力或截图成功作替代。

内部点击使用当前呈现几何，防止目标态 NSView frame 与运动中的图层位置错位。收起时隐藏控件退出键盘/辅助功能访问，内部焦点移回行头；逻辑展开状态稳定发布，不逐帧播报。窗口拖动与行内复制、滑杆、分页、排序手势相互隔离。

### 7. 全模块一次交付，证据分层验收

实施按组件族分组是工程顺序，全模块覆盖之前不切换正式默认入口、不进行 CPU-only 的最终验收。双渠道通过相同共享框架；风扇和显示器控制依实际渠道/硬件验证，缺失条件用明确标注的夹具补充分支，不把夹具写成真实硬件结果。

保留现有 `HAGIMI_PANEL_AUTOTEST`、`HAGIMI_PANEL_BENCH`；当前 Bench 的三卡范围只能继续用于可比基准，另补全模块及嵌套场景覆盖。采集唯一应用身份/准确 PID、版本、显示模式、配置和原始证据，录屏与性能测量分开进行。

统一验收矩阵：

- 两渠道 × 普通/快捷键临时/置顶面板；各可用模块单独切换、交错切换、全部切换和快速反转。
- 浅/深外观 × 平衡/活力配色；白色、深色及复杂真实背景，检查终态和运动中的圆角、材质、正文/辅助文字及图标。
- 正常、CPU 压力、CPU/GPU 同时压力；60Hz 与可用高刷新率模式，报告未能运行的系统/硬件项。
- 封顶/解封顶、原生惯性与自动揭示接管、设备增减、分页/指标/顺序变化、跨屏缩放、显隐和重新打开。
- 数值复制、已有排序、入口、置顶拖动、Direct 控制、透明区域穿透、键盘焦点和辅助功能。

归因指标包括每次操作的主线程排版/窗口提交成本、CPU 中位数与高分位、GPU/WindowServer 可获得数据，以及可见/隐藏内存与恢复情况。目标为展开归因成本下降并减少高负载可见停顿，后台及稳态资源不出现新回归；不预先承诺收益百分比。主线程探针间隔和录屏文件帧率不等于实际显示掉帧，必须结合连续画面及可获得的 Hitches 证据。零跳步、可读性、输入和全模块功能是硬门槛；最终交付附证据清单，由用户对全量效果验收。

## Risks / Trade-offs

- [Risk] 固定透明容量改变窗口级输入边界。→ 在正式开关启用前完成跨应用原生事件验证；保持可撤回候选，不以视图命中测试代替穿透证明。
- [Risk] 多节点/封顶非线性使简单同参弹簧失配。→ 统一解析几何和有限轨迹；测试多节点交错、嵌套及边界反转，不分别动画起终点。
- [Risk] 更多宿主和大容量毛玻璃增加内存或合成成本。→ 容量限制在屏幕范围，复用稳定宿主、明确隐藏回收，测量应用及可获得的合成侧成本；禁止以栅格化遮蔽问题。
- [Risk] 原生控件、分页状态、子弹窗和排序回归。→ 内容接口保留正式组件和稳定身份，加入各组件族原生交互矩阵。
- [Risk] 两种面板同时显示导致刷新/隐藏计数错误。→ 复用现有生命周期租约，按宿主取消工作，不全局误停仍可见面板的数据。
- [Risk] 历史规格与当前代码存在差异，进行中的排序 change 共享文件。→ 本变更仅更新相关运动/展开行为，按实际组件目录登记覆盖；维护 change 交叉说明，不修改其他任务的完成标记。
- [Risk] 本机不具备全部系统、设备和刷新率条件。→ 真实检查、夹具和待验证项分别列出，未覆盖项不标通过。

## Migration Plan

1. 保留并登记认可 Demo 源码与证据，补可复现说明；采集当前正式面板全模块基线，在独立 `codex/` 分支实施。
2. 建立通用自然尺寸适配、纯几何/运动向量及有限图层轨迹，复用适合的既有模型和测试。
3. 接入两个面板控制器、经典材质及可见轮廓，优先解决透明区域事件、焦点和生命周期门槛。
4. 在同一候选中迁移全部组件族和公共入口，补嵌套、结构换版、滚动与排序适配；工程过程可逐组检查，最终交付范围始终是全模块。
5. 完成定向测试、Direct 全量测试、两渠道构建和重启，全矩阵原生/性能验收并提供完整候选供用户验收。
6. 全部门槛与用户验收通过后，切换共享默认路径，清理旧展开高度预测、窗口弹簧和重复实验入口；保留 Demo 技术参考及新框架所需的测试夹具。

旧路径清理前以内部构建选择恢复基线；清理后的回退为该独立变更的源码撤回。没有持久化格式迁移，用户指标、顺序、采样数据和统计记录无需回滚。不在本变更内自动提交、合并或替换 `/Applications` 安装版。
