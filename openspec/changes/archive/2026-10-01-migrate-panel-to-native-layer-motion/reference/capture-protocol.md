# 实机采集协议

当前 OS 为 macOS 27.0.1 (26A434)，Xcode 27.0 (27A266a)。系统更新前的基线不与更新后的候选直接计算收益。

## 身份、条件与原始记录

- 基线及候选均使用 Release、自有独立 Bundle ID、相同真实设置投影；关闭测试副本的自动更新与独立 HUD。记录 Git 基点、源码及可执行文件 SHA-256、PID、启动路径、配置和时间，不修改安装版或其设置。
- 每轮只运行一个被测面板。完成构建/测试后再测资源，记录同期总负载与 WindowServer。固定屏幕 ID、逻辑/像素尺寸、缩放、实际 CGDisplayMode 刷新率；不能只用设备宣称支持的最高刷新率。
- 显式选择内置显示器 ID 1，用全局 CGDisplayBounds 验证窗口属于该显示器。录制固定桌面区域，包含面板外围真实背景；SCDisplay 原点相交或窗口专属截图不能替代背景记录。
- 每轮分别记录展开前/操作期/收敛后/隐藏后 CPU 与内存。原始采样保留时间戳，报告操作期中位数与高分位、隐藏恢复趋势。锁屏、窗口遮挡、构建或测试并行运行的轮次独立标注，不计入正常桌面对比。

## 操作覆盖

1. 旧 `single/all/reverse` 保留 CPU/GPU/内存三卡范围，可复用同一 `HAGIMI_PANEL_FIXTURE` 文件。其结果只能说明这个范围。
2. 候选 `full-all/full-sequence/full-reverse` 使用当前真实可见模块；拒绝三卡 fixture。日志的 `scope=live-full` 和 IDs 必须与当前配置核对。自动基准执行 50 次，普通间隔 700ms、快速反转间隔 100ms，前置等待以当前实现为准。
3. `full-all` 切换顶层监控模块，不自动打开显示器档案；`full-reverse` 快速反转 CPU。不可称为所有嵌套节点都被自动覆盖。
4. 对原基线的完整面板，通过原生操作执行相同逐行、交错、双击全部、显示器逐设备档案、电源分页、封顶滚动与滚动接管顺序；原基线没有新 full 模式，不能给它传新模式然后假定操作相同。
5. 普通菜单栏、快捷键临时及置顶分别检查；另外执行复制、正式入口、排序/取消/边缘滚动、透明区域对下方应用的点击/拖动/滚轮及 Tab/辅助功能显隐。

## 背景与压力

- 两种外观 × 平衡/活力，包含真实白色页面、深色页面和复杂桌面背景，保留端点及连续运动录像。
- 正常、CPU 压力、CPU+GPU 压力各一轮，条件匹配后重复测量。压力 helper 采用明确有限时长，记录 worker 数、实际负载与结束恢复，不停止用户应用。
- 可用 60Hz 与高刷新率模式分别执行；不存在或尚未运行的模式明确列为缺项，不能用录屏请求 120fps 代替实际屏幕模式。

## 证据解释

录像判断底边、圆角、描边、阴影、内容位移是否一致、是否跳步及对比度是否下降。有限轨迹模型测试是几何误差证据，CPU 是主线程成本线索，WindowServer/GPU 数据是可获得的合成线索。录屏文件帧率、SC 回调间隔、Autotest 的 `slowframes` 都不是实际显示掉帧率。可获得 Instruments Hitches/Profiler 时保存准确 PID 和有限时长 trace；不可获得时如实列出。

全模块功能、输入、可读性和资源证据齐备后，才交付用户统一验收并切换默认路径。

## 收尾采集补充协议（2026-10-01）

- `full-matrix` 明确提交全部顶层项、全部展开、全部可用显示器档案、可用电源四页、档案收起、CPU 反转和全部收起；缺失页只记 `page-skipped`。旧自动档案序列与 Bench 互斥。
- 两类基线分别命名：同一候选产物的兼容运动路径用于隔离运动路径成本；源码快照 `54ddc51492fc0ebc408f0a325cd8395594aded97` 的独立原版副本保留旧运动、采样、统计门控和负载环，只加入同一有限操作入口、窗口/root body 计数及相同 CPU 测量窗口。保存原始/插桩源码哈希，不能称为未插桩的安装版。
- 全模块近景另外限制可见项为电源或显示器，以便档案和分页实际出现在录像里；这些轮次不替代全模块资源对照。快速反转另录 `full-reverse`。
- 资源 CPU 由 Mach 累计计数按该轮 `mach_timebase_info` 换算纳秒再除以实际单调时间差；100% 表示一核。RSS 与物理 footprint 分开报告，隐藏初期与最后五个样本分开登记。原始 WindowServer 读取失败状态保留，不能当零。压力程序的真实 CPU、Metal 批数/GPU 执行时间及驱动总利用率随表登记。
- 每轮导出该独立域的配置和哈希。蓝牙身份的最后发现时间、被测试屏幕覆盖的保存位置属于运行期元数据；配置对照另外核对有效设置投影。构建、解码 QA 或多宿主意外并行的轮次排除资源收益；原始文件仍保留。
- 实际观察到的双屏 120Hz 与随后单内建屏 60Hz 分组报告，不跨组计算收益。录像请求帧率与文件平均帧率均不能代替实际屏幕模式。
- Animation Hitches trace 保存 PID、表目录、系统/app 事件及导出表。显示 surface 的生命周期、swap 数和应用 Hitch 事件不是同一种统计量，不把 surface 生命周期除以刷新周期换算成掉帧率。录像/trace 轮不进入无录制的 CPU 资源对照。
- 首次 Demo 录制遇到冷启动尚未产生窗口的情况；有界窗口就绪等待与明确录制完成检查用于后续重试，失败回执保留。参考 Demo 原始源码及哈希保持不变。
