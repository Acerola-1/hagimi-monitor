## Context

动机及产品范围见 proposal.md。本设计依据 2026-09-08 仓库审计；执行时应重新检查符号与现状，行号不作为实现依据。

当前链路为 DisplaySection → DisplayControlController → 全局 DisplayControlWorker → DisplayControlService → DisplayDDCBridge / DisplayServicesBridge / GammaDimmingController。DDC 使用 IOAVService 私有调用，门禁统一接收睡眠与显示重配置事件。现有 arm64 和 MCDP29XX 地址适配应保留。

## Goals / Non-Goals

**Goals:**
- 将身份、状态转换、协议解析和排队策略抽为可测试的小模块；名称可顺应代码风格调整，行为与测试合同不变。
- 主线程只持有可发布快照与用户交互；阻塞 I/O 不进入主线程。
- 本轮在进程内保留一个有界串行 DDC 执行通道，优先解决任务积压、陈旧写入和真实反馈。
- 保留可写不可读设备支持；不能用“读不到即禁用”替代完整状态模型。

**Non-Goals:**
- 不承诺挂起内核调用能被取消、重置队列后恢复，或一台屏挂起时其他 DDC 屏仍必然可用。
- 不新增 XPC/helper 进程、Intel 后端、通用 Gamma 不支持设备的遮罩后端。
- 不扫描并试写所有 VCP，不把 0x13、0x6B 或厂商码当成通用替代码。
- 不实现输入源、硬件静音、RGB、KVM/PBP；不自动调整 HDR/显示器 OSD 模式。

## Decisions

### D1. 设备身份和连接代次分离

建议拆分 DisplayIdentity、DisplayConnectionToken、DisplayMatchEvidence，替代用 CGDirectDisplayID 贯穿持久化和异步请求。

- 稳定身份优先使用厂商/型号/有效序列信息，结合已有系统 UUID、EDID 字母数字序列；不能把 EDID 哈希当作绝对唯一，也不能假设换口后 UUID 必定稳定。
- 缺序列的同款屏采用连接位置辅助区分。没有唯一证据时状态为 ambiguous，不任意写；允许用户将可视屏与候选服务显式绑定，并明确标注“绑定此连接”。换口/拓扑变化导致证据变化则重新确认。
- 匹配器输出唯一匹配、歧义候选或未匹配。优先精确连接位置和有效序列，厂商/型号不一致拒绝；低分名称相同仅能成为候选。所有强证据先处理，同分冲突不得贪心分配。
- 手动绑定仅在用户主动执行时允许通过对所选候选做一次可恢复小幅亮度变化辅助识别；没有可靠原值则不自动试写，可提供连接信息供选择。完成时重新核验拓扑。
- 每次断开、服务对象替换、身份不一致都更新 generation。普通轮询不重建服务，从而不无故更新 generation。
- 请求携带身份、generation、属性、requestID；入底层前和回主线程前均校验。清理 maxValues、controlCodes、能力、去重、pending、suppressed、最近目标和音量记忆；用身份保存的历史值与瞬时会话状态分开。

替代方案：继续增加匹配分数仍不能解决平分或同型号碰撞；持久化单用系统显示编号会受编号复用影响。

### D2. 目标、读数、历史与确认独立

建议 AttributeState 包含 optional observedValue、desiredValue、lastAppliedValue、historicalValue、source、timestamp 和 writeStatus。能力不放在 writeStatus 内。

状态至少区分 idle、pending、deferred、sentUnverified、verified、failed。I/O 返回 KERN_SUCCESS 表示传输调用成功，不宣称显示器已经执行或产生应用层确认。

- 移除跨独立用户操作的永久 lastWrittenValues 去重；仅合并同一交互尚未执行的相同目标。最简单正确实现是每次新的显式操作至少产生一次最终发送。
- 请求 ID 用于判断回调是否当前请求；不能只按 Double 是否相同判断，因为 50→80→50 会重复值。
- pending/最近目标优先展示，但带目标或待确认语义；已过期读取不能盖掉新目标。确认期结束后可展示实际读数并保留未达到目标的状态。
- 手动拖动连续节流建议 150ms，松手立即排入最终值；不是每次输入取消定时器直到停止的无限尾部 debounce。媒体键按同样最新目标机制合并。
- 自动读取模式在交互结束 300ms 后安排一次回读；未匹配时最多再试一次、间隔 500ms。慢速模式分别 800ms/1000ms。按有效原始范围容许 1 raw unit 的量化偏差（最多不小于 0.5 个 UI 百分点），不要强制浮点完全相等。时序使用注入时钟，常量集中定义。
- 只写模式不回读；发送成功仅记上次设置。未知值显示 `--`；滑块若需内部初值，初值不得作为数值标签/设备事实。相对媒体键无已知基准时交还系统，绝不从伪造默认值大幅跳转。
- finite 校验在 UI 输入和范围转换入口执行，拒绝 NaN/Infinity；连续值范围可表示完整 UInt16，异常高字节仅按有证据的 profile 处理，不统一截成 32767。

替代方案：每包写后回读导致总线负担，完全盲写又无法解释无效操作；有限终态确认兼顾两者。

### D3. 有界调度与超时后的真实状态

建议将 DisplayCommandScheduler 和阻塞 DDCTransport 分开。调度器维护每连接每属性一个最新待写目标、每连接一个合并读请求，调度器状态由 actor 或单一串行队列独占；不要把同一可变字典分散给多个队列。

- 一个进程全局最多一个已提交到底层的 DDC transaction；底层尚未返回时不再向 ioQueue 追加闭包。可调度命令留在受控容器而非 GCD 无限队列。
- normal call deadline 初始保留 2s。超时后设置 transport busy/stalled，完成上层等待但保留 in-flight 标识，直到真实调用返回。维护有限的最新目标槽，不开启新的线程绕过卡住调用。
- 进入阻塞层前检查 generation、gate 和请求有效期；已提交的读写事务内部在每次重试前再次检查门禁/有效性。一个正在内核执行的调用无法撤销，其迟到物理效果无法保证不存在，应在恢复后重新对齐最新目标。
- 真实返回后旧结果不直接发布；验证连接、重新等待门禁允许，再安排一次恢复读取或只写设备的最新目标。禁止在通道仍 stalled 时用“重试”按钮创建第二条通道。
- 普通 I/O 失败使用有界延迟重试，不改 capability 为 unsupported。连续失败进入 recoverableUnavailable；自动恢复尝试默认退避 1/2/5/15s、最多四次，之后保留手动重新检测和连接事件触发恢复，不无限忙等。
- 一个事务中的读/写报文不能被其他事务插入。写优先于未开始的周期读；多连接写请求 round-robin，避免单屏拖动饥饿其他屏。读不能插入仍在进行的事务。
- 主线程接收 Sendable 值结果；CF service 引用的生命周期由连接对象持有，不允许 timeout 后释放仍被调用使用的资源。

替代方案：每屏一个无限队列、超时后重建串行队列或不断新建线程，都可能增加挂起线程且并发访问同一实际总线。helper 隔离可在未来独立设计，当前不伪造可取消能力。

### D4. 门禁以独立原因和截止时间解算

保留 DDCEnvironmentGate 作为系统信号入口，提取可注入单调时钟的纯状态模型。

- 独立维护 systemAsleep、displayAsleep（接入屏幕睡眠/唤醒通知）、wakeUntil、reconfigureUntil；总抑制取所有有效原因。重配置完成可以缩短自身 begin safety 期限，但不能缩短唤醒期限。
- 每次状态改变重算下一截止时间；到期再次读取当前状态与代次。stale timer 不发出错误“已解除”。进入下一次睡眠后，旧 wake timer 也不能解除门禁。
- true→false 统一发出恢复事件，不限 structural flags；begin-only safety 到期也触发。refresh 与 replay 使用同一恢复协调器：先核验/更新连接，再对仍有效且非 stalled 的通道发送最新目标。
- 待写目标留在 scheduler；旧 suppressedWrites 不再另建独立真值来源。关闭面板只影响 polling。

替代方案：依赖下一次面板刷新不能保证后台媒体键和缺失通知场景的最终送达。

### D5. 按 VCP 证据聚合，按属性选择后端

建议分离 CapabilityEvidence、ReadPolicy、BackendPreference、TransportHealth；ControlledDisplay 不再用一个 dimmingMode 决定整台屏的音量和对比度。

- `supported` 指有效读应答证明支持该码，不保证写权限或当前画面模式允许写。缓存最后有效证据；一次超时只更新最近通信状态。
- 所有已配置候选明确不支持才形成该属性 unsupported；有 unknown 候选时保留 unknown。协议返回错误、零 max、校验失败不等于 unsupported。
- 默认亮度使用 0x10；保留现有 0x13 的兼容能力，但仅对显式配置/已经验证的适配 profile 开启，并根据 MCCS 复杂类型正确解析。默认不再自动试写 0x13。不新增任意 raw VCP 编辑器。
- 保留 0x37 与 MCDP29XX 0xB7 路由及祖先搜索。传输路由地址、DDC 源地址和 checksum 是独立概念；修改报文必须有字节夹具测试和实际设备依据，不凭注释猜测。
- 解析验证长度、校验和、opcode、回显 VCP、resultCode；异常帧返回结构化错误。完整 MH/ML/SH/SL 值先保留，再按类型解释。
- 本轮不新增 capabilities string 长报文读取。未来若加入，作为提示和诊断证据，不作为唯一启用/禁用依据；其缺失不妨碍逐项 GetVCP。
- 每屏提供亮度模式：自动、硬件只写、软件、禁用；每属性另设读取自动/关闭，通信速度正常/慢速、可选 max 覆盖。明确不支持时默认不写，用户显式只写覆盖需要保留原证据并标明手动模式。
- 自动模式仍优先原生或 DDC；发现服务但无应答时不反复自动切换 Gamma，提示用户选择软件模式，避免亮度来回跳动。
- Gamma 仅在可用设备和实测 API 成功时报告成功。已识别 AirPlay/虚拟设备当前保留只读信息和不可用说明，不以 Gamma 必定支持为前提强行开放；DisplayLink 如未被分类过滤但 Gamma 失败也正确报告。全面虚拟屏调光另案。

替代方案：自动 capabilities 扫描和所有码轮询增加不可靠通信；按属性探测加少量显式 override 足以修正本轮主要缺陷。

### D6. 软件调光按成功状态恢复

GammaDimmingController.setDimming 返回结果；只有成功后更新已应用 dimLevels 与成功值持久化，失败时保留用户目标与错误。硬件亮度和软件因子使用不同 key。

- 首次启用软件调光前读取并保存当前每屏传输表作为本应用基线；按基线乘因子，100% 恢复基线。原始表无法获取时不声称无损恢复：选择显式系统色彩恢复并验证影响，或报告后端不可用，不盲写 identity 假称原色彩已恢复。
- 刷新读数不重复施加 Gamma；仅用户写入、已确认系统重置后的唤醒/连接事件需要重施加。基线缓存与连接代次关联；自己的调光表不能再次作为基线累乘。
- 色彩配置变化需要使基线失效并重新获取适用基线；与其他持续修改 Gamma 的工具同时工作不承诺叠加正确，诊断明确限制，避免周期强抢。
- 自动重启恢复仅使用新版本明确保存的软件模式和成功因子；旧 brightness key 来源未知，不自动施加。
- 切后端时先确认软件恢复成功再标记硬件模式完成，失败保留待恢复状态；正常退出进行最佳努力恢复并记录失败。不承诺崩溃退出恢复。
- 0% 允许保持现有行为，需可用的恢复至 100% 操作及媒体键路径；真机测试按最小风险渐进测试，不上来就全黑。

替代方案：将 identity 表当系统原始表会影响校色；把每次 polling 都视为唤醒会覆盖其他软件的设置。

### D7. 发现、能力与值轮询分开

建议 DiscoverySnapshot 缓存服务映射，只在真实拓扑事件、明确重试或服务失效时更新。能力在首次连接或用户重试时探测；普通 polling 仅读取已启用且允许读取的属性。

- 初始 polling 保持 5s；失败属性退避到 15s/30s，成功后恢复。只写模式零自动读。
- refresh 为 single-flight，合并期间触发最多留下一个必要后续刷新；退出面板取消尚未开始的周期读。
- 排队元数据不含昂贵 IORegistry 枚举。用户拖动期间同项 polling 暂停，终态确认取代下一次相同读。

### D8. 媒体键与音频路由

AudioOutputDetector 扩展只读输出描述（设备 UID、名称、transportType、可控属性），配合 NSScreen/系统提供的可靠映射证据建立目标；不能只比较名称并假定唯一。

- 能唯一映射 HDMI/DP 输出到控制屏时使用映射，否则显示“选择音量控制显示器”，由用户对 audio UID→DisplayIdentity 显式绑定。绑定失效时不回落到鼠标屏。
- 系统自身可调节输出优先交还系统；找不到默认音频输出也交还系统。
- 亮度保留既有鼠标外接屏/单可控外接屏兜底策略。按属性过滤可控集合，缺相对值基准时不吞普通键。
- adjust 方法返回是否已接受有效操作；handle 仅在接受时消费事件。pending OSD 可呈现目标，但不得在拒绝/失败时显示成功。
- 静音仍用音量归零，本轮不新增 0x8D。归零前记住可靠的非零当前值，恢复优先级为进程内最新→持久化→1/16 满量程。与键盘锁、权限、Option 设置快捷键、细步进和 repeat 行为保持一致。

### D9. 兼容设置与诊断呈现

必要状态就近置于显示器控制区，详细配置放在现有设置结构内的逐屏配置页，诊断提供“复制诊断”操作。为手动身份绑定及音频绑定提供候选说明。先制作 HTML 原型验证新增配置流，再实现 SwiftUI；不改现有面板运动与几何。

- 使用既有 palette、布局、双语文案；Slider 补显示器名称、属性、数值来源和不可用原因的 accessibilityLabel/Value/Hint。
- `--`、上次设置、待确认、软件调光、通信异常、待绑定的表达简洁，用户界面不出现 Direct、generation、IOAVService 等内部术语。
- 每连接最近 100 条事件环形缓冲，不写全量注册表；导出 schemaVersion、版本、时间、架构、脱敏身份、连接代次、匹配依据、backend/profile、能力、raw/max/percent、请求状态、耗时、错误码、门禁原因和超时状态。
- requestID 关联排队/执行/完成，不输出用户文件路径。报告内未知链路与设备模式标为 unknown；不根据 HDMI 字样猜测扩展坞。
- 如需原始设备标识排障，另设用户明确选择的详细导出，不做默认内容，也不上传。

### D10. 持久化兼容迁移

使用独立 v2 命名空间。迁移仅在旧身份唯一匹配时复制历史值，并标记 historical/unverified；不把旧值当确认状态、不据旧 key 推断软件模式。零序列号碰撞不复制到两屏。

保存 backendPreference、readPolicy、timingProfile、rangeOverride、explicitMapping、软件成功因子及音量恢复值；请求队列、临时故障和 generation 不持久化。保留旧 key 供回滚，不双写。

## Risks / Trade-offs

- [内核永久阻塞] → 本轮保证界面可响应和资源有界，显示 DDC 通道异常；不承诺进程内强制恢复。已执行操作迟到不能物理撤销，恢复后对齐最新值。
- [显示器/扩展坞不转发 DDC] → 诊断和软件模式选择；不将所有无应答归类为设备不支持。
- [同型号无唯一身份] → 连接绑定可能在换口后失效，要求重新消歧。
- [HDR/OSD 锁定参数] → 显示未确认并给出检查画面模式的建议，不自动改系统显示模式。
- [只写设备无法验证] → 明确“上次设置”，保留人工验收；发送成功不是画面生效证明。
- [Gamma 和校色/其他调光软件冲突] → 基线恢复、事件驱动重施加、限制说明；不宣称覆盖所有虚拟屏。
- [现有面板重构仍在进行] → 修改前检查其他变更和工作区，复用当前组件，不重排动画结构。

## Migration Plan

1. 先建立测试注入边界和当前问题回归测试，保持外部 UI 接口可编译。
2. 引入身份与值模型，再接入 scheduler 和 gate，逐步替换旧 pending/去重状态，避免两套写链路并存。
3. 接入逐属性 backend、Gamma、媒体键、持久化与 UI；删除失去用途的旧状态，清理过程性注释。
4. 使用单元和模拟集成验证全部合同，双渠道构建，再按下表真机验证；不由自动测试无差别操作用户显示器。
5. 保存验证记录和未覆盖项。回滚代码时保留 v1 key；v2 key 可忽略，回滚前尽力解除软件调光；无用户明确要求不提交或合并。

### 自动验证矩阵

| 组 | 必须覆盖 |
|---|---|
| 身份 | 两台同款同分；零序列号；编号复用；换口；旧回调；服务替换缓存清理 |
| 调度 | 独立 50→50；外部改值；100 次快速目标仅保留有限待执行量；最新终值；读写优先级；round-robin |
| 故障 | 阻塞超过 deadline；未返回不再提交；迟到返回；过期请求未入底层；断开后的结果；有界退避 |
| 门禁 | sleep/wake；仅屏幕睡眠；setMode；begin-only；重叠期限；面板隐藏重放；旧 timer |
| 协议 | 有效帧、不支持、主码超时备用码不支持、错误 checksum/长度/opcode/回显；max=1/100/255/65535；NaN |
| 后端 | 亮度软件+音量DDC；Gamma失败不持久化；保存恢复；基线不累乘；只写零自动读 |
| 路由 | 双屏音频和鼠标分离；未知输出；AirPods；目标不支持；静音前外部非零值；细步进和键盘锁 |
| 诊断迁移 | 脱敏、100条有界、未知数据、双语、v1唯一迁移与冲突拒绝 |

### 硬件验证记录模板

每条记录：日期、代码版本、Mac/系统、显示器型号/固件、直连或扩展坞/转接器、接口、HDR/OSD 状态、其他调光 App 是否运行、操作步骤、预期、实际画面/OSD 值、诊断文件、结果（pass/fail/not-run）。未知信息留空标注。

最低当前可用硬件：亮度/音量/对比度独立读写；拖动终值；OSD 外部改值后设回；面板关闭期间媒体键；睡眠唤醒；分辨率变化；软件模式切换及重启恢复。扩展矩阵：USB-C/DP、HDMI（含可获得的 MCDP29XX）、扩展坞、双同型号、只写设备、Gamma 不支持设备、HDR。缺少硬件记录 not-run，不用模拟成功冒充硬件通过；相关硬件任务保持未完成或明确部分验收。

### 分阶段交接与继续执行约定

本 change 的任务较多，按以下里程碑推进。阶段边界是可验证的工作单元，不是自动提交、自动结束或跳过剩余任务的许可。接手者只在用户指定部分范围、真实阻塞或上下文交接时停下，并如实记录剩余工作。

| 里程碑 | 任务组 | 完成证据 | 依赖与交接重点 |
|---|---|---|---|
| M1 基础模型 | 1–3 | 基线记录、身份测试、值来源/重复写入回归通过 | 确定最终类型与接口名称，写入 execution-notes，后续沿用 |
| M2 可靠通信 | 4–5 | 挂起 fake、有界排队、迟到结果、门禁重放测试通过 | 这是新增兼容设置前的必要基础，不用 UI 隐藏通信错误 |
| M3 能力与恢复 | 6–8 | 帧夹具、逐属性后端、轮询/确认、Gamma与迁移测试通过 | 保留 HDMI 适配；v1 数据不自动被当作 Gamma 因子 |
| M4 产品接线 | 9–10 | 媒体路由测试、原型、两语状态及脱敏诊断 | 复用面板布局，身份与音频手动绑定均应可操作 |
| M5 集成验收 | 11–12 | 场景映射、Direct测试、双构建、实机记录 | 将自动验证和硬件验证分开记录，不能自动归档未验收变更 |

执行 Agent 的工作顺序：读取 OpenSpec apply 指令与本计划 → 核对已勾选任务的证据和当前差异 → 继续第一个依赖已满足的未完成任务。每完成一项才更新 tasks.md；不要在开始任务时预先打勾。不要复用本轮审计临时 harness 作为正式测试替代品。

execution-notes.md 至少记录：当前里程碑、实际新增/改名文件及接口、已运行测试命令与结果、未通过项、硬件 not-run 原因、已知限制、下一项任务。此文件由执行阶段创建，本轮只交付计划。现有代码若在执行前变化，优先保持规格行为，调整文件定位并记录，不凭旧行号重写。

### 后续独立变更路线（不计入本轮任务）

1. 输入源切换与硬件静音：在当前逐属性能力/请求模型上增加离散枚举控制，不复用百分比转换；输入选项依据实测或型号档案，处理切走输入后失联及不可保证切回的行为。
2. 显示器预设与 RGB/颜色模式：区分连续量与离散值，保存原始范围和设备身份，部分应用失败要逐项报告；不把相同百分比等同于跨屏相同物理亮度。
3. 电源、PBP/KVM 和 USB 厂商扩展：先获取型号、固件、可恢复测试方法，再建立独立 profile 和规格；不自动试写未知码。
4. 如真实内核挂起仍为高频问题，独立评估 helper 进程故障隔离；验证系统调用与进程终止的实际行为后再做可恢复承诺。

这些方向记录了前轮审计的扩展建议，并未承诺在本 change 完成。它们不应挤占 M1–M5 的可靠性验收。
