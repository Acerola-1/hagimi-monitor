# Design

## Context and evidence boundary

本 change 是规划文件，未授权功能实施。以下是已验证事实与仍需真实游戏验收的边界：

| 事项 | 已有证据与结论 |
|---|---|
| 独立沙盒 `NSPanel` 覆盖另一进程原生全屏、`.floating` 足够、物理点击穿透且不夺焦 | `tmp/game-hud-probe/gate-conclusions/conclusions.json` |
| 沙盒可读 CPU/GPU、内存、GPU 驱动聚合内存、整机电池遥测功耗等；SMC CPU 温度被拒、分项功耗无沙盒数据源 | `tmp/game-hud-probe/sandbox-validation/verification.json` |
| 受控探针 stderr 可读逐帧数据；统一日志隐私遮蔽；非受控游戏无帧率通路 | `tmp/game-hud-probe/gate-conclusions/conclusions.json` |
| `NSWorkspace.OpenConfiguration` 的环境与参数未到达探针；受控进程直接启动有效 | 同上；真实商业游戏启动链未验证 |
| 官方 HUD 不是可查询的窗口，位置/尺寸只能由游戏启动配置控制 | Apple `Customizing the Metal Performance HUD` 文档；真实游戏不得推定其运行时边界 |

**SCALE 口径修正：**在现有截图中，3024 px 屏幕上选定配置的官方 HUD 约 422 px，3840 px 屏幕上约 536 px；与 `drawableWidth × 0.14` 预测的 423/538 px 相符。早先“约 390 pt、偏差 1.8 倍”很可能混淆了屏幕截图像素与逻辑点。无需以该疑点为前提安排 SCALE 标定；仍不承诺官方高度或位置可查询。

## Goals / Non-Goals

**Goals:**
- 只在已识别的前台游戏且目标窗口几何可确认时，在窗口内视觉呈现硬件 HUD；退出/失焦/窗口不可靠时隐藏。
- App Store 版只提供真实硬件指标；官网版在已验证的受控启动链上额外配置官方 HUD、解析逐帧日志并提供最近 60 秒 FPS 统计。
- 两面板在受控会话中共享左/右侧选择：官方上角、硬件下角；不做像素级拼接。
- 复用既有硬件采样结果，但 HUD 选择不受主面板模块显隐影响；不增加硬件采样器与采样频率。

**Non-Goals:**
- 不把独立浮窗嵌入第三方游戏窗口层级，不读取/推测官方 HUD 的实际外框。
- 不注入游戏、Hook 图形接口、关闭 SIP、写全局 Metal HUD 偏好或自动结束/重启游戏。
- 不承诺任意游戏/Steam 启动链、CrossOver/虚拟机、独占显示捕获或上架审核在探针阶段已经通过。
- 不做每游戏独立指标配置、GPU 温度、风扇、0.1% Low 或游戏专属显存。
- 不改主面板材质、模块布局和菜单栏指标选择。

## Decision tree

### 1. 显示门槛与游戏窗口归属

`GameHUDSessionController` 先判定总开关、前台 bundle ID、保守候选/用户添加/排除，再确认属于该游戏的可见窗口、非空屏幕矩形、唯一可选的目标窗口及其所属屏幕。仅“进程还在”或“应用使用 Metal”不够。Steam 启动器与最终游戏按各自进程身份处理；不能因为启动器仍活着而留下 HUD。

窗口识别与几何追踪先用不要求录屏/辅助功能授权的公开窗口/显示信息验证。以目标窗口的屏幕矩形而不是整屏角落为硬件 HUD 坐标基准；窗口移动、缩放、换屏、进入/离开原生全屏与 Space 变化后重新选择。若 API 返回的边界无法证明与实际游戏内容一致、存在多个无法消歧的候选窗口、窗口不足以容纳卡片，立即隐藏；确认后再显示。实现前须在探针与真实游戏分别验证窗口化、无边框和原生全屏的矩形可用性，不能仅靠 bundle ID 推断窗口。

状态至少区分 `disabled`、`eligibleNoWindow`、`hardwareVisible`、`controlledPending`、`controlledTelemetryVisible`。运行会话另存目标 app/process、实际显示窗口与屏幕身份，窗口关闭/进程退出/失焦时清除当前显示。普通非受控游戏仍可进入 `hardwareVisible`。

### 2. 双面板相对位置

全局只有左/右配置，默认右。官网版受控启动生成不可变的 `GameHUDLaunchProfile`：目标游戏、所选侧、官方 HUD 的 `topright`/`topleft`、固定 `MTL_HUD_ELEMENTS` 预设、是否启用逐帧日志。硬件浮窗在同一目标游戏窗口的右下/左下角按内边距放置，`NSPanel` 使用探针已验证的浮窗档位、点击穿透与全屏辅助行为。两块都位于游戏窗口内，但不共享底板、不追求边界相接；官方 HUD 的实际位置、尺寸和高度不可查询。配置来源单一，硬件勾选不修改官方元素预设。

官网版受控会话运行中改变侧边时，现有启动快照继续决定两块 HUD 的侧边；设置显示“下次由本应用启动该游戏时生效”。普通硬件会话及 App Store 版没有受控官方 HUD，可在重新确认窗口几何后即时移动硬件窗。未受控启动的官方 HUD 可能由用户自行开启，不能推定其默认右上或与我们不重叠。

官方预设保留 `fps`、`frameinterval`、`fpsgraph` 或 `frameintervalgraph`、`gputime`、`layersize` 等渲染信息，裁掉 `device`、`memory`、`disk` 等重复块；实际支持项以目标 OS 和真实游戏验收为准。MetalFX 指标由官方 HUD 在游戏使用时瞬态显示。UI 文案只称 `layersize` 为“Metal 图层尺寸”，不称游戏内部渲染分辨率。不要禁用官方 HUD 菜单项来掩盖运行时配置漂移，菜单交互/报告能力是否保留纳入验收。

### 3. 硬件数据适配

现有 `MonitorStore.modules` 经 `settings.isVisible` 过滤，不能给独立 HUD 用。新增只读、随既有采样结果更新的 HUD 快照或订阅接口，来源为现有 `allModules` 的真实采样结果，不能由 Game HUD 单独触发采样；不把整个 `MonitorStore` 的高频重绘传播到隐藏的 HUD。HUD 自身勾选集合只过滤显示，不改主面板可见模块集合。

基础项：CPU 整机占用、GPU Render/Tiler 两个明确口径、内存已用量、GPU 驱动聚合内存。整机功耗仅在既有采样真正返回时作为可选项；官网版按运行时能力追加 CPU/GPU 分项功耗与 CPU 温度。目录中的“本机有能力”与当前采样 `nil` 分开；已选指标短暂缺值时保留行显示 `—`。沙盒中的 SMC 温度/风扇不可用，官网分项功耗来自 Direct 专属通路；GPU 温度没有已实现采样源。GPU 驱动聚合内存不叫“显存”。整机功耗与分项功耗都不能称为当前游戏的独占功耗。

### 4. 受控启动、进程归属与日志统计

仅官网版编译和呈现受控启动入口。用户明确选择目标后，在不写全局偏好的前提下用已验证能传环境的进程启动通路启动；不得使用 `NSWorkspace.OpenConfiguration.environment/arguments` 作为关键通路。若目标已在运行，只提供普通硬件 HUD，不杀进程以重开。Steam 或其他启动器只有在真实游戏上证明**最终游戏进程**接收到配置并能捕获其 stderr 后才列为增强支持；否则维持硬件模式。启动命令成功不等于增强会话成功。

逐帧解析器验证 `metal-HUD` 行的帧号、内存字段与成对的 present interval/GPU time，持续排空 stderr，限制内存缓冲、处理格式变化/子进程切换/EOF/断流，不让管道阻塞游戏。统计只消费已确认属于当前游戏进程的有效 interval；统一日志、录屏帧率、显示器刷新率均不得替代。

FPS 块显示同一最近 60 秒有效窗口的平均 FPS 与 1% Low；首版不展示 0.1% Low。实现前锁定 1% Low 算法（最慢 1% 有效 interval 的平均时间再取倒数）、最低有效样本数、焦点丢失/暂停/加载/长间隔与断流规则，并写解析测试。窗口未满或数据质量不够时不显示统计值；非受控或断流使统计失效时隐藏整个块。它与官方滚动 FPS/Missed 不同口径，不写成同一数值。

硬件指标区始终固定在窗口下角。统计块仅在有效时向上占用预留区域，不推动硬件行，也不跨出目标游戏窗口；可用高度不足时隐藏统计块，保留硬件区。官方 HUD 可能因 MetalFX 等瞬态信息长高且其实际高度不可读，因此无法保证上下绝不相碰；对受控预设采用保守的顶部预留高度，若目标窗口不足以容纳预留区与硬件区，隐藏硬件 HUD，不能把“同侧”写成零重叠保证。

### 5. 渠道与能力边界

App Store 版只有自动硬件 HUD，不出现官方 HUD 配置入口与 FPS 块；以公开 API、沙盒可读性和真实数据语义构建目录。官网版的私有 IOReport 源及受控启动代码保留在 Direct target 范围。两版的 bundle ID、UserDefaults 与测试产物独立。不得把探针沙盒可读性等同于 App Store 审核批准；在发布前核对提交包、公开 API、IORegistry 字段使用与渠道隔离。

## Risks and gates

1. **真实游戏的窗口身份和矩形**：窗口化、无边框、原生全屏、Split View、外屏/镜像/缩放、Space 切换、Dock/菜单栏变化都要确认目标矩形与隐藏兜底；无法确认则不显示。
2. **启动链覆盖率**：至少一个直接启动的原生游戏和一个 Steam 原生游戏分别验证最终进程环境、官方 HUD 出现、stderr 归属与退出回收；失败链只标硬件支持。
3. **统计与开销**：同一真实游戏/场景比较无 HUD、仅官方 HUD、双 HUD＋日志；记录平均 FPS、1% Low、卡顿与 CPU/功耗，不能只测 HUD 自身 1 Hz 绘制。
4. **渠道验收**：macOS 15 最低版本、App Store 沙盒与官网版分别构建/实机确认；不把单一 macOS 27 探针结果扩展为全机型承诺。
5. **UI 信息边界**：官方图层尺寸、整机与进程指标各标清归属；启用但无游戏、游戏窗口不可靠、普通硬件会话、增强待确认、增强有效、日志中断必须可区分。

## Open Questions for implementation validation

- 哪些真实商业游戏的窗口矩形可在不增加系统授权的条件下稳定取得；若不满足，则该显示模式不进入首版承诺。
- 官网版实际支持哪些受控启动链，以及最终游戏进程的环境和 stderr 是否可确认。Steam 支持以真实游戏验收结果为准。
- 逐帧日志格式、采样缺口和官方 HUD 元素在 macOS 15 至当前版本的兼容范围。
- 首批内置候选游戏 bundle ID 及维护办法，实施时按保守名单建立可核对来源；用户手动添加始终可用。
