# Proposal

## Why

HagimiMonitor 已有真实硬件采样，但缺少在前台游戏中自动出现、可按需选择指标的轻量 HUD。原生 Demo 已验证独立浮窗可覆盖另一个进程的原生全屏，真正开启 App Sandbox 后也能显示多项系统指标；需要将实验变成有渠道边界、生命周期与验收契约的正式功能。

## What Changes

- 在设置的小工具区域增加「游戏 HUD」配置，在主面板工具区增加控制同一自动启用状态的入口。
- 本地识别原生 macOS 游戏（包括 Steam 原生游戏），支持用户添加和排除应用；仅在匹配游戏处于前台时显示，覆盖窗口化、无边框和原生全屏。首版不支持转译软件、虚拟机及其内部游戏识别。
- 自绘部分仅展示游戏相关的现有真实硬件指标，支持逐项勾选、数值与负载曲线选择；不包括 IP、SSID、电池状态/健康/电量、蓝牙、一般电脑信息、完整进程表和历史报告。
- 指标目录按渠道及确定的硬件能力过滤。App Store 不支持的项目直接不出现，不灰显、不展示升级占位；暂时缺失的已选数据保留行并显示 `—`，不得伪造零值。
- 全局一套 HUD 配置，不增加每游戏指标配置。默认只在游戏所在屏幕的右下角显示，可选四角和调整偏移；始终点击穿透，不抢焦点。
- 保留官方 Metal HUD 的独立渲染信息；本次的指标勾选不控制官方内容。官网版可提供针对指定游戏、经验证的可选启用辅助；不得修改所有 Metal 应用的全局开关、注入游戏、自动结束或重启游戏。沙盒版不承诺代开官方 HUD。
- 复用现有采样发布通道，但 HUD 选择与主面板/菜单栏选择相互独立；不增加每帧硬件轮询，不在隐藏时重绘 HUD。
- 本 change 仅交付计划。后续实施须先完成能力门槛测试，再进行产品接入，不得将原型或文档结论当作真游戏/上架验收。

## Capabilities

### New Capabilities

- `game-hud`: 游戏识别、自动显示状态机、渠道化指标目录、真实数据适配、浮窗布局、曲线、可选官方 HUD 辅助与生命周期。

### Modified Capabilities

- `settings-window`: 新增游戏 HUD 设置组、分组勾选目录、预览、应用名单和布局配置，不改变原有模块选择规则。
- `monitor-panel`: 主面板工具区新增游戏 HUD 开关与状态反馈，不改变现有监控模块布局。

## Impact

- 主要接入点：`MonitorSettings.swift`、`MonitorModels.swift` 中的 `MonitorStore`、`QuickToolsStore.swift`、`Views/Panel/QuickToolsPopover.swift`、`Views/Settings/SettingsRootView.swift` 及对应小工具设置页、`Localizable.xcstrings`。
- 新增 HUD 的目录/数据适配/会话控制/窗口/设置视图，按现有模型—存储—视图职责组织；官网版官方辅助只编译进 `HagimiMonitorDirectOnly/`。
- App Store 保持沙盒与公开 API 边界，不新增绕过沙盒的 entitlement、外置助手或提权需求。基础 HUD 不要求录屏、辅助功能或输入监控授权。
- 不新增网络识别服务，不上传应用或进程名单，不改现有主面板材质，不引入 Liquid Glass 实验。
- 验证两个渠道与 macOS 15 最低支持版本；与正在进行的工具、面板排序和统计改动协同时保留其工作，不把 HUD 绑定到被用户过滤后的面板数据。
