# Proposal

## Why

HagimiMonitor 已有真实硬件采样，需要在游戏成为前台且窗口可确认时提供游戏内可见的硬件 HUD。原生探针已验证独立沙盒浮窗可覆盖另一进程的原生全屏、点击穿透且不夺焦；受控启动的游戏可由 Apple Metal Performance HUD 提供渲染信息。两者分别渲染，不承诺合成一个像素级连续面板。

## What Changes

- 设置页与主面板工具区共用一个 Game HUD 总开关。总开关只允许自动显示；实际显示还要求前台应用命中游戏名单、未被排除、且目标游戏窗口及其屏幕边界可确认。失焦、窗口不可确认或游戏退出即隐藏，不留下屏幕常驻浮窗。
- 硬件浮窗是独立、点击穿透、不抢焦点的 `NSPanel`，视觉上放在目标游戏窗口所选侧的下角并随窗口移动、缩放、换屏。窗口化和原生全屏均以可确认的目标窗口矩形为前提；无法确认、窗口过小或放不下时隐藏，不退回整屏角落。
- 全局布局只设左/右，默认右。App Store 版仅提供硬件 HUD；官网版受控启动时把官方 HUD 配到同侧上角，硬件 HUD 位于同侧下角。官网版受控会话在运行中改侧边时，两块 HUD 保持当前侧，提示下次启动游戏生效；普通硬件会话可即时移动。
- 硬件目录首版以 CPU 占用、GPU Render/Tiler 占用、整机内存、GPU 驱动聚合内存为基础；整机功耗仅在真实可读时可选。官网版按实际能力追加 CPU/GPU 分项功耗和 CPU 温度。不提供 GPU 温度、风扇、游戏专属显存等无可靠首版数据契约的项目。
- 官网版受控启动可配置官方 HUD 的固定渲染信息预设，并在最终游戏进程的逐帧 stderr 确认可用后显示独立的最近 60 秒平均 FPS 与 1% Low 统计块。首版不展示 0.1% Low。未受控启动、启动链未验证或数据断流时隐藏整个统计块；硬件 HUD 保持可用。
- 官方 HUD 的指标预设与硬件勾选相互独立：前者保留 FPS/帧间隔曲线、GPU 时间、Metal layer 尺寸等渲染信息，裁掉重复的设备头、内存与磁盘项。MetalFX 瞬态显示由官方 HUD 自行决定。不得把 Metal layer 尺寸称作游戏内部渲染分辨率。
- 复用 `MonitorStore` 既有硬件采样结果，但向 Game HUD 提供不受主面板模块显隐影响的已采样快照；不增加硬件轮询。Game HUD 的隐藏期不重绘。对官网版真实游戏启动链、屏幕位置和性能开销设置独立验收门槛。

## Capabilities

### New Capabilities

- `game-hud`: 游戏匹配与目标窗口确认、显示生命周期、渠道化指标、受控会话、相对位置双 HUD、FPS 统计和能力降级。

### Modified Capabilities

- `settings-window`: Game HUD 总开关、精简指标、游戏名单、左右布局与官网版启动说明。
- `monitor-panel`: 与设置页同源的 Game HUD 快速开关与状态反馈。

## Impact and Boundaries

- 计划变更位于 `openspec/changes/add-game-hud/`；本 change 仍只交付计划，实施由后续任务负责。保留现有主面板、菜单栏与其设置的独立性。
- App Store 版保持沙盒、公开 API 与现有硬件采样边界，不提供受控启动、官方 HUD 代开或 FPS 统计。官网版的受控启动不使用 `NSWorkspace.OpenConfiguration.environment/arguments`，不注入游戏、不写全局 `MetalForceHudEnabled`、不自动结束或重启游戏。
- 内置候选游戏名单以保守匹配为原则，用户可添加或排除；Steam 原生游戏只有在最终游戏进程的环境与 stderr 通路通过真实游戏验证后，才承诺官方 HUD 配置与 FPS 统计。未通过时仍可使用普通硬件 HUD。
- 上架、商业游戏覆盖率、GPU 驱动字段长期稳定性和 HUD 性能开销尚未由探针验证；实施完成后分别验收，不把计划或原型结论当成通过。
