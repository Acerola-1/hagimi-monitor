# game-hud Tasks

> 本 change 只交付计划；下面的未勾选项均是后续实施与验收任务。Phase 1.1–1.4 的探针门槛结论已完成，证据在 `tmp/game-hud-probe/gate-conclusions/conclusions.json`。真实商业游戏、窗口几何、启动链、性能和上架均未因此视为通过。
>
> 保留现有工作区修改。源文件按工程同步目录加入 target；Direct 专属代码置于 `HagimiMonitorDirectOnly/`。验证产物放 `tmp/`，不提交。受控启动、官方 HUD 与 FPS 统计只属于官网版；App Store 版交付独立硬件 HUD。

## Phase 1: 已有探针结论与新增真实游戏门槛

- [x] 1.1 确认受控探针 stderr 逐帧数据可读、统一日志明细 `<private>`、非受控进程不可读
- [x] 1.2 确认 `.floating` 可覆盖另一进程原生全屏
- [x] 1.3 确认 `ignoresMouseEvents` 物理点击穿透且游戏保持 key window
- [x] 1.4 确认 `NSWorkspace.OpenConfiguration` 环境与参数被丢弃，不作受控启动通路
- [ ] 1.5 在真实原生游戏验证：可用公开信息识别游戏 PID、唯一目标窗口、可见边界、屏幕/Space；覆盖窗口化、无边框、原生全屏、移动/缩放、最小化、失焦、退出。不可确认时记录原因并隐藏，不另求录屏或辅助功能权限
- [ ] 1.6 在一款直接启动的真实原生游戏上验证官网版受控启动：最终游戏进程收到官方 HUD 配置，官方 HUD 出现，stderr 帧流可读；记录游戏身份、启动命令和失败条件
- [ ] 1.7 在 Steam 原生游戏上单独验证启动器到最终进程的环境与 stderr 继承。未通过则标为“硬件 HUD 支持”，不承诺增强功能；不得用探针成功替代
- [ ] 1.8 用原始截图 px、目标 drawable px 与屏幕 pt 复核现有 SCALE 口径；记录 3024×0.14≈423 px、3840×0.14≈538 px 的现有截图观察。此项用于消除旧测量歧义，不作为精确拼接的标定前置

## Phase 2: 不受主面板显隐过滤的数据契约

- [ ] 2.1 提供只读 HUD 已采样快照或订阅接口，来源为 `MonitorStore.allModules` 已有采样结果，不能用已按主面板显隐过滤的 `MonitorStore.modules`；不得新增硬件采样器、提高采样频率或令隐藏 HUD 持续重绘
- [ ] 2.2 建立 `GameHUDMetricCatalog`：基础 CPU 总占用、GPU Render/Tiler、内存已用、GPU 驱动聚合内存；整机功耗在真实可读时可选；官网版按能力追加 CPU/GPU 分项功耗、CPU 温度。复用既有指标 ID 或现有模块总值，记录每项整机/驱动归属
- [ ] 2.3 把设备/渠道能力与“本次采样值为 nil”分开；沙盒不提供 SMC 温度和分项功耗；GPU 温度、风扇、0.1% Low 不进首版目录；已勾选项目临时缺值保留行并显示 `—`
- [ ] 2.4 实现 HUD 独立的指标选择适配与 CPU/GPU 负载历史；隐藏主面板 CPU/GPU/内存/电源模块后，HUD 勾选仍可读真实快照；GPU Render/Tiler 不互相冒充，GPU 驱动内存不写“显存”

## Phase 3: 游戏识别和目标窗口几何

- [ ] 3.1 建立保守的内置游戏 bundle ID 候选与用户添加/排除名单，排除优先；首批名单逐项记录来源，不能仅因使用 Metal/OpenGL 就加入
- [ ] 3.2 建立 `GameHUDWindowLocator`：从匹配前台游戏的窗口中确认唯一目标、可见屏幕矩形与所属显示器；若窗口不可见、候选歧义或内容区域无法确认，返回“不可显示”，不退回整屏角落
- [ ] 3.3 建立 `GameHUDSessionController`：区分总开关、前台游戏、目标窗口、普通硬件会话、受控增强待确认、增强有效与失效；游戏失焦、退出、窗口关闭、切屏和 Space 变化时及时隐藏或重算
- [ ] 3.4 窗口跟随只运行于候选前台游戏期间；验证最小化、Split View、多窗口、显示器断连、镜像/缩放、Dock 与菜单栏变化下不遗留旧屏幕浮窗
- [ ] 3.5 用明确的目标游戏进程身份而非 Steam 启动器存活状态决定退出与 FPS 归属；非受控启动也允许普通硬件 HUD

## Phase 4: 设置与主面板入口

- [ ] 4.1 扩展 `MonitorSettings`：总开关、独立硬件指标勾选、用户游戏添加/排除名单、全局左/右侧（默认右）；移除旧计划的四角及像素偏移设计，按现有键与迁移规则持久化
- [ ] 4.2 新建设置页，顺序为总开关、监控项目、游戏名单、左右布局；显示“已启用但未显示”“窗口不可确认”“普通硬件”“受控增强待确认/有效”等可理解状态；官网版另给受控启动说明，App Store 版不出现该入口
- [ ] 4.3 注册 `SettingsRoute` 与侧栏「扩展」入口；设置页不因进入而全量枚举安装的应用
- [ ] 4.4 在 `QuickToolKind` 中新增 Game HUD 工具条目，沿用既有存储标识/标题/图标/存量迁移模式；按钮只切换同源总开关，不把“允许显示”误标为“当前正在显示”
- [ ] 4.5 验证官网受控会话运行中改侧边时两窗当前侧不变且提示下次启动生效；普通硬件会话可在重算目标窗口后即时移动

## Phase 5: 硬件浮窗

- [ ] 5.1 新建独立 `GameHUDPanelController`，不用 `PinnedPanelController` 配置；按探针采用 borderless、nonactivating、`.floating`、点击穿透及全屏辅助行为，不成为 key window
- [ ] 5.2 以已确认的目标游戏窗口矩形计算左下/右下位置与安全边距；窗口移动/缩放/换屏时更新；卡片放不进窗口或矩形不可靠时隐藏，不能裁切、遮盖邻近应用或留在旧屏幕
- [ ] 5.3 新建紧凑 `GameHUDView`，使用既有 `MonitorPalette` 和中文/英文标签；固定尺寸与容量契约，临时缺值显示 `—`，选多项目时按既定溢出规则稳定布局
- [ ] 5.4 CPU/GPU 曲线只表示整机负载历史，不暗示帧时间；复用既有 `SparklineChart` 约定或同口径轻量绘制；隐藏后停止重绘
- [ ] 5.5 为官网受控预设保留保守的官方 HUD 顶部空间；目标窗口不足以同时容纳该预留区与硬件区时隐藏硬件 HUD。MetalFX 等瞬态高度不可查询，验收时记录可能重叠，不宣称零重叠

## Phase 6: 官网版受控启动与官方 HUD

- [ ] 6.1 在 `HagimiMonitorDirectOnly/` 实现用户主动的受控启动入口与不可变会话启动配置；核对目标已运行时只提供普通硬件 HUD，不自动结束/重启
- [ ] 6.2 启动配置单一来源生成官方左/右上角 alignment、固定 `MTL_HUD_ELEMENTS` 渲染预设、需要时的 `MTL_HUD_LOG_ENABLED` 与会话侧边；不通过 `NSWorkspace.OpenConfiguration` 传关键环境，不写全局键、不注入游戏
- [ ] 6.3 官方预设保留 FPS/帧间隔曲线、GPU 时间与 Metal layer 尺寸，去掉重复的 device/memory/disk；实际元素在最低 macOS 15 和当前系统分别验证。MetalFX 瞬态显示交由官方；文案不得称 layer size 为游戏内部渲染分辨率
- [ ] 6.4 受控游戏当前侧边取启动快照，硬件 HUD 放同侧下角；运行中改设置只影响下一次受控启动。官方 HUD 菜单及用户手动改官方配置会破坏位置假设，UI 不声称能查询官方运行态
- [ ] 6.5 对直接启动真实游戏与 Steam 启动链分别记录最终游戏进程收到的环境、官方 HUD 是否出现、stderr 是否可读；只有通过的链路才标增强支持，其他链路保留硬件 HUD

## Phase 7: 官网版逐帧统计

- [ ] 7.1 从已确认最终游戏进程持续、非阻塞地读取 stderr，解析 `metal-HUD` 帧号/内存/(present interval,GPU time) 成对样本；处理部分行、格式异常、EOF、断流、子进程切换与缓冲上限，不让管道回压游戏
- [ ] 7.2 固定最近 60 秒平均 FPS 与 1% Low 的算法、最低有效样本量、预热、焦点切换、加载/暂停、长间隔与日志缺口规则；用探针逐帧样本和构造的断流/异常样本测试。首版不计算 0.1% Low
- [ ] 7.3 仅在当前受控游戏的有效统计窗口完整时显示独立 FPS 块；非受控启动、启动链未验证或数据质量不足时隐藏整个块，硬件指标保持显示。标明“最近 60 秒”，不与官方滚动 FPS 或 `Missed` 混称
- [ ] 7.3a 统计块显隐不得推动固定在窗口下角的硬件指标区；只在窗口内向上占用可用区域，空间不足时隐藏统计块
- [ ] 7.4 验证不同刷新率、Game Mode、游戏暂停、失焦、屏幕切换及退出时统计状态及时重置/隐藏，不保留上局数字

## Phase 9: 验收

- [ ] 9.1 双渠道按 AGENTS.md 独立 DerivedData 构建；共享实现双渠道验证。新增/改长标签触发 `MetricWidthAuditTests`；文档修改本身无需构建
- [ ] 9.2 实机验证窗口化、无边框、原生全屏、Split View、多显示器、副屏、缩放/镜像、Space 切换、最小化、失焦、窗口关闭和退出；保存截图/日志，尤其核对不可靠几何时隐藏及旧屏无残留
- [ ] 9.3 实机分别验证普通非受控游戏、官网直启增强、Steam 启动链成功与失败降级、App Store 硬件版；不推断官方 HUD 是否真的出现，只以可观察证据记录
- [ ] 9.4 同一真实游戏和场景比较无 HUD、仅官方 HUD、双 HUD＋逐帧日志的平均 FPS、1% Low、卡顿、CPU 与功耗；记录场景、样本和波动，出现可重复的游戏性能退化须修复或降低功能开销后复测
- [ ] 9.5 复核不可用/暂缺数据不造 0、整机/进程/驱动聚合语义清晰、硬件 HUD 隐藏不重绘；失败与未测项如实标记，不以探针或编译成功代替商业游戏/上架验收
