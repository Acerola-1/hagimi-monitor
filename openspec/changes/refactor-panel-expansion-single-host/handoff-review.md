# 2026-09-06 测试报告证据复核

原报告保留于 `tmp/panel-single-host/handoff-results.md`。以下复核区分已核对的记录、代码推断与尚未完成的原生验证，不覆盖原始日志。

## 可以确认的结果

- `handoff-tests.log` 有 185 条测试通过记录与 `TEST SUCCEEDED`；Direct Release、两个 Debug 渠道的构建日志均为 `BUILD SUCCEEDED`。这对应边界修复前的源码。
- 单行正常、单行负载、三行正常、三行负载及反转共十轮均有 50 次 `unoccluded=1` 与 `complete`。候选首次封顶运行在第 35 次操作因遮挡中止；正式比较使用完成的 `handoff-candidate-cap-60-rerun`。
- 逐操作 JSON 中的累计 CPU 样本与报告一致：单行正常的递归放置样本 281→25ms，单行负载 188→17ms，三行正常 396→18ms，三行负载 305→4ms。布局隔离在这些场景有明显收益。
- 实际 60Hz 内屏、M4、macOS 27 与负载环境由测试 agent 报告；本次复核没有重新采集当时的显示模式。不能用当前显示状态代替历史环境证据。
- `sampleTracks` 过零即进入 resting 的分支确实会清除仍未衰减的解析速度，需要真实协调器回归覆盖。

## 需要修正的验收表述

1. **“完成全部测试”不成立。** 交回记录未提供连续画面、逐帧位置、原生手势接管、键盘/VoiceOver、双面板交互和隐藏重开内存的证据。
2. **TC-10 应记为未验收，不能由窗口开销推导呈现失败。** 2525ms 是 40 个操作窗口内的累计 inclusive 样本，不是一次卡顿或一帧耗时；代码调用次序与 CPU 占比均不证明实际错帧。`analyze_operations.py` 的 `window_ms` 匹配任何含 `setFrame` 的栈，也包含 NSView/CALayer。在候选单行正常区间复核，2525ms 中含 NSWindow 的样本为 2483ms，其余为 42ms。
3. **TC-09 的数值来自独立公式模拟和代码分析。** 能定位状态截断，但记录没有执行零交叉场景的真实协调器断言，也没有支持“肉眼硬刹车”的视频。该边界问题不能独自解释展开与收起整段的分段跳跃。可见高度的非负硬边界本身也不具有全域 C1 连续性。
4. **TC-07 仅有性能/尺寸部分证据。** `window_ms` 降低不能证明 Footer 跟随、触控板接管、渐隐和解封画面全部正确。
5. **TC-08 不足以判定无泄漏。** 脚本仅取启动约 5 秒与 `operation=49` 出现后的两次 footprint，未测隐藏稳定值和重复重开；`mem-test-*.log` 也没有保存 footprint 原始输出，且在最终 `complete` 前被终止。40–43MB 只能作为测试 agent 报告的短期观测。
6. **探针表与 CPU 表的区间不同。** 报告的 slowframe 统计脚本扫描整个日志，包含预热；逐操作 CPU JSON 丢弃前 10 次。两者不能表述为统一的预热后 40 次统计。主队列打卡间隔仍不等于呈现帧间隔；报告“候选最大压至 18ms”也与其正常单行 22.9ms 的记录不符。

## 后续验证顺序

补充并执行真实协调器的零交叉反转、跨帧跳过负相位区间、自然尺寸换版与收起残帧测试；内部速度接续与可见零高度分别验收。修复后重建两个渠道供观察，再取得真实底边/卡片连续呈现证据。屏幕同步、原始 40–50ms 阻塞归因与完整事件/生命周期门槛仍保持未完成，不据此开始全量迁移。
