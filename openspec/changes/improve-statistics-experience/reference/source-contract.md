# 数据来源合同表

用途：记录每类指标在本期实现中实际使用的来源、时间窗口与已知限制，作为 tasks 1.3 的交付物。
表中「已核实」指本次实现中读过对应源码并有测试覆盖；「限制」列是必须向用户说明的部分，
不得在界面或导出中省略。

## 应用级指标

| 指标 | 来源 | 原始单位 | 时间窗口 | 已核实的限制 |
|---|---|---|---|---|
| CPU | 进程采样（面板 TOP 采样链路），每进程另按宿主应用合并 | 单逻辑核百分比 | 每次采样的瞬时值；事件侧按相邻采样间隔积分 | 可超过 100%；不等于整机占用；80% 档位不称整机满载 |
| GPU | 同上进程采样 | 百分比 | 瞬时值 | 分母未能证实为整机份额，`StatisticsMetricDefinition.percentBasis(for: .gpu)` 标记为不可解释；不做跨应用可加性声明 |
| 内存 | 进程采样 `phys_footprint` 口径 | 字节 | 瞬时值 | 关注门槛为 `max(3.5 GiB, 物理容量 × 20%)`，容量未知时退回绝对门槛并标记无法计算份额；不冒充「系统内存压力」 |
| 网络 | 进程采样，来源为窗口均值 | 字节每秒 | 窗口均值；区间总量按相邻采样真实间隔积分 | 速率与区间总量分离；门槛沿用旧 20 MiB/s 原始值换算的约 20.97 MB/s，未暗改 |
| 磁盘 | 进程采样增量 | 字节（区间增量） | 自上次采样以来的增量 | 已是区间量，不得再乘间隔；乘任何系数都会放大 |

## 系统级指标

| 指标 | 来源 | 原始单位 | 时间窗口 | 已核实的限制 |
|---|---|---|---|---|
| CPU / GPU / 内存占比 | 系统采样（`MonitorStore` 每秒帧） | 百分比 / 字节 | 每分钟封口径；小时/日由分钟聚合 | 速率型（网络、磁盘）按「上次速率 × 距上次观测时长」分段积分，间隔超过 30s 视为睡眠丢弃该段 |
| 内存压力 / 热压力 | 系统原生档位 | 0–3 档 | 每帧 | 档位不乘 100；与「内存使用率」不是同一指标 |
| 覆盖率分母 | 有效采样秒数与整机清醒时长 | 秒 | 本期 | 只扣除系统确认的休眠；应用退出或采样失败形成的空档仍计入分母 |

## 渠道与多实例

| 项 | 结论 | 依据 |
|---|---|---|
| 沙盒 / Direct | 两个渠道构建均通过；应用统计与事件库都写在各自容器内 | 本次两渠道 `BUILD SUCCEEDED`；`StatisticsStoreDeletionTests.twoDirectoriesStayIndependent` 验证两目录互不影响 |
| 同 Bundle ID 多实例 | 未实现单写入租约；身份键按 bundle id 归并，因此两个实例会写入同一身份行 | 事件落库按稳定事件 ID 幂等，重复写入不倍增；但**跨进程并发写保护未做**，属已知限制 |
| GPU / 网络在 App Store 版 | 沿用现有编译条件，不补零 | 未新增权限或数据源 |

## 未核实项

- GPU 分母的实际来源语义（是否整机份额）无法从当前采集链路证实，因此按「不可解释」处理，而不是假定。
- CPU 采样窗口的精确语义（瞬时值 vs 短窗均值）未逐来源核对，事件侧统一按相邻采样间隔积分，不声称是精确的核·时。
- 同 Bundle ID 双实例并发写入的协调策略未实现（tasks 5.5 的剩余部分）。
