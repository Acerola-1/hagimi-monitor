## Purpose

统计数据的后台维护（汇总、清理）以增量方式进行：单次维护的开销有界，不随历史数据量增长，使菜单栏应用可常年运行而不产生持续上升的后台负载。

## ADDED Requirements

### Requirement: 汇总为增量式且有界开销
分钟数据封口后的汇总（分钟→小时→天）SHALL 只处理自上次汇总以来新增或变更的时间桶；单次汇总的读写量 SHALL 有上界，不随数据库中历史数据的年龄或总量增长。

#### Scenario: 长期运行后的每分钟维护
- **WHEN** 应用已连续运行数十天，每分钟封口触发一次维护
- **THEN** 单次维护只重算当前封口的桶及其受影响的聚合行
- **AND** 维护耗时与数据库总数据量无关

#### Scenario: 历史数据被删除或修正
- **WHEN** 用户删除某段历史数据后触发维护
- **THEN** 受影响时间桶的聚合结果得到修正
- **AND** 其余历史聚合不被全量重写
