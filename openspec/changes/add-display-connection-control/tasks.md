# Tasks

本文件列实施与验收任务。当前已进入 apply；只对已完成的整项勾选。未勾选项可能已有实现或部分证据，具体缺口见 [验收记录](reference/acceptance-results.md)，不将构建或计划校验通过等同实机验收。

## 1. 连接模型、身份与持久化

- [x] 1.1 在 `DisplayConnectionModel.swift` 建立会话拥有权、观察状态、操作状态和稳定记录投影；用纯模型测试覆盖在线、软断开、已拔出、未知及历史快照来源，验证这些状态不会互相替代。
- [x] 1.2 基于现有身份概念实现当前枚举的唯一重匹配；用测试覆盖数字 ID 重用、零序列同型号多屏、同端口换设备、UUID 变化/矛盾、幽灵条目，验证错误目标永不写入。
- [x] 1.3 扩展 `DisplayPersistence` 保存带版本的恢复拥有权、档案和镜像记录，并原子保存可报错的恢复日志；用隔离存储测试覆盖往返、旧数据不自动推断停用、损坏/未知 schema、文件写失败与偏好保留。
- [x] 1.4 实现完整物理拓扑的最后屏保护纯策略；用测试覆盖隐藏内置屏、合盖、镜像主从、虚拟/假屏、远程会话、替代屏尚未上线和多屏均有停用偏好，验证总能拒绝不安全的新停用。

## 2. 小型私有接口桥接与单屏闭环

- [x] 2.1 在 `DisplayConnectionBridge.swift` 实现可注入符号解析与动态容量枚举；先只读记录本机 OS、符号可用性、在线/离线身份信息至 `tmp/`，用 fake 测试验证缺符号不退出进程且不执行停用。
- [x] 2.2 封装会话配置事务及 no-op 跳过；用桥接测试验证 begin/configure/complete 各阶段失败、取消、原始错误保留和正确调用顺序，不将提交失败误报为已回滚。
- [x] 2.3 在 `DisplayConnectionCoordinator.swift` 实现后台串行单屏切换、当前身份重解析及有界状态核验；用 fake backend/时钟覆盖返回成功但状态未达标、延迟上线、超时、有限重试和请求失效，验证主线程不执行同步配置调用。
- [x] 2.4 在有其他可用物理屏与恢复入口的原生环境验证一块外接屏和一块内置屏的停用/恢复；记录桌面布局、实际面板状态、恢复结果与链路，无法取得的设备明确记为未验收，不用读到符号替代实测。

## 3. 镜像关系保存与恢复

- [x] 3.1 建立组成员稳定身份、主从与相关布局快照，以及预期停用后拓扑；用测试验证目标为主屏、从屏及多成员组时，变更计划不影响无关屏且保留物理幸存屏。
- [x] 3.2 实现必要的局部镜像调整、启用优先与无冲突还原；用 fake 拓扑覆盖正常还原、成员缺席、身份歧义、外部镜像/布局变更及部分事务失败，验证较新设置优先并反馈未还原原因。
- [x] 3.3 验证镜像记录跨正常退出/应用重启保留，且不把自身通知当作外部修改；补充对应持久化/协调器测试，形成可复现的镜像恢复操作记录。
- [ ] 3.4 在原生镜像场景分别停用/恢复主屏和从屏，再验证停用期间修改镜像及拔出成员；记录实际关系和可见输出，保留未覆盖机型与多成员组合的验收缺口。

## 4. 现有控制器、安全救援与生命周期接入

- [x] 4.1 由 `DisplayControlController` 持有协调器并发布稳定记录投影，沿用原在线控制列表服务 DDC；用集成测试验证异步旧刷新不覆盖新连接状态、离线条目不触发参数探测、多入口共用一次状态。
- [x] 4.2 接入目标写入撤销、连接 token 失效及 gamma/engine 清理；用定向测试覆盖停用前已排队写入、停用期间滑轨/媒体键输入、恢复后新代次及旧回调，验证不补发过期操作且不损坏其他屏的参数控制。
- [x] 4.3 复用 `DDCEnvironmentGate` / `DisplayChangeObserver` 的事件注册，分离安全通知与 DDC 沉降通知；测试覆盖不重放停用、自身通知、持续失败和两类睡眠，验证无通知循环或重复监听，轻量检查只在有停用拥有权时运行。
- [x] 4.4 实现唯一幸存屏移除后的恢复优先；覆盖拔出、合盖、恢复失败及唤醒后恢复，验证 DDC 抑制不永久阻断机器清醒时的连接救援，并以真实拔线/开盖确认可见画面。
- [x] 4.5 实现启动前恢复日志检查、异常后旧记忆清理及只恢复策略；用生命周期测试覆盖异常运行、未完成切换、退出恢复失败、再次重启不自动停用。
- [x] 4.6 为 `AppDelegate` 接入可等待的正常终止恢复流程，保留既有 gamma、日志和工具清理；测试正常、失败、超时及重复终止请求，验证恢复日志保留、恢复先于正常终止、等待有界且失败日志不被误清。
- [x] 4.7 实现“恢复所有屏幕”的请求失效、偏好清除与逐目标恢复；用竞态测试验证旧自动停用不能在恢复后重放，某目标失败不阻断其他目标，缺席屏的旧停用偏好也被清除。
- [x] 4.8 在 change 的验证记录中补充恢复步骤及各类失败含义，验证说明区分函数结果、系统状态和人眼面板结果，不声称同步调用可被硬超时取消或崩溃后即时恢复。
