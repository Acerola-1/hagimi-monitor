# Design

## 当前产品决定

在 Apple 芯片 Mac 的 GitHub 下载版提供逐屏软断开，App Store 保持只读边界。经典毛玻璃、蓝灰显示器色和既有面板几何保持不变，仅支持中文和英文。

用户在真实拔线中发现原实现不能可靠恢复内置屏，当前设计以安全恢复为先：启动只读取系统当前状态，清理旧停用记忆，不在启动、唤醒或插线时自动再次停用。恢复日志保留拥有权、未完成操作、身份与镜像，不保存可重放的停用命令。

## 模块与职责

- `DisplayConnectionModel.swift`：稳定身份、观察状态、历史快照与纯保护策略。旧 schema 的 wantsDisabled/automaticPaused 仅用于兼容读取，启动后清理，不驱动连接写入。
- `DisplayConnectionBridge.swift`：动态符号枚举、当前身份匹配和会话配置事务。私有接口仅在 Direct target，原始错误保留，缺能力不退出应用。
- `DisplayConnectionCoordinator.swift`：后台串行执行器、主线程状态投影、显式启用目标、安全探测与恢复优先调度。
- `DisplayControlController`：真实参数控制与连接状态接线，撤销排队输入，隔离迟到的刷新/写回调。
- `DDCEnvironmentGate`：唯一的 CG/电源事件注册者；DDC 沉降通知与拓扑安全通知是两条不同订阅，不共用“门禁已解除”条件。

## 连接操作与身份

每次常规写入重新枚举并唯一匹配 UUID、内置角色、厂商型号和有效序列，不依赖旧数字 ID 或名称。唯一例外是无可用物理屏时的紧急点亮：只用本会话见过、且当前未被其他设备占用的编号，不把该编号写入恢复日志。按钮向执行器传入明确的 enabled 目标，当前状态已经相符时 no-op；不因系统刚恢复屏幕就把“启用”反转为停用。

会话事务使用 `.forSession`，配置与核验在后台。返回成功不等于观察成功，核验有界且可丢弃过期结果。配置错误保留阶段和原始返回码，不能将提交失败称为已回滚。真实系统调用不能假装被硬取消。

## 最后屏保护与紧急救援

停用前按完整物理拓扑检查，不把虚拟屏、远程屏、合盖内置面板或缓存当替代屏。镜像从屏按可用输出判断，不只数 active 主屏。

物理幸存屏移除时，拓扑订阅直接通知协调器；即便 DDC 仍因显示器睡眠而永久抑制，也不阻断连接救援。移除标记针对此前可用且非本应用停用目标时，保守恢复本应用停用屏，不等待旧条目从系统列表消失。自身停用回调按目标忙状态/拥有权识别，不能马上撤销用户的停用。

仅当本应用仍拥有停用屏时运行轻量拓扑检查，补偿事件遗漏；检查只读取连接状态，不重扫 DDC 参数。恢复全部后停止该检查。真实系统睡眠时不主动唤醒，唤醒/屏幕参数通知立即重新检查。

紧急恢复先失效参数会话和排队输入，再恢复连接；不能等可能卡死的 DDC 调用。worker 使用可同步失效的代次，已经排队的 debounce 在真正写入前再次核对，旧回调也不能覆盖新会话。正常手动拓扑变更仍等待已开始 I/O 真实返回。恢复优先可见内置屏，其次其他可见物理屏；某目标失败不阻止后续目标。

真实拔线进一步表明：安全通知已触发，但私有枚举仅剩系统虚拟占位屏，无法找到内置屏。此时先启用本会话刚见过的该屏编号，编号若已被另一台设备占用则放弃；这个编号不写入恢复日志，下次启动不得重放。若仍然没有可用物理屏，且仍有本应用停用的内置屏，最多执行一次显示器睡眠/用户活动唤醒，促使系统重建硬件拓扑。仅在开盖、系统清醒且未关机时开始；睡眠和关机过程中不人为唤醒。此路径不猜测编号范围，不还原永久布局；重新枚举并匹配后才恢复具体目标。独立任务保证调用者取消不会截断已开始周期的配对唤醒；并发请求合并，连续失败不会循环闪屏。实际结果仍由新鲜拓扑与人眼画面分别确认。

## 生命周期与迁移

首次升级不从旧亮度或在线缺席推断停用。启动清除旧的停用意图，但保留本应用尚未点亮的拥有权，只读取当前连接。仍有可用物理屏时，启动和正常退出都不点亮、不关闭屏幕。没有任何可用物理屏且仍有本应用停用的内置屏时，启动才执行与运行中相同的救援。退出不重放停用。

异常后不提供“恢复自动应用”，因为没有自动停用流程。外部软件或系统重新连接屏幕后，本应用接受新状态，释放已恢复的拥有权，不再次关闭屏幕。

## 镜像

停用镜像成员前保存组内稳定身份、主从和相关布局，必要时局部解除。恢复先连接目标，再比较预期与当前相关拓扑，只有无冲突时还原；成员缺席时先保持连接，等待成员回来。外部较新设置优先，不重放无关屏幕排列或模式。

主屏重新加入造成的共同桌面原点平移，只有启用前严格核验通过且本次实际启用时才允许；相对尺寸、位置和镜像目标仍要一致。

## 界面

一至两块设备的主行保留原成对亮度药丸，停用屏只使用最后确认值，未知值缺失，不因在线集合缩小而显示总台数。

在线卡片沿原参数和档案结构。停用卡片只显示图标、名称与启用按钮，不显示参数摘要、滑轨、档案、状态或时间说明。历史信息保留在记录中供恢复在线后使用。内置屏始终列出。没有一次性恢复所有屏幕的操作；每块屏幕各自启用。没有可用物理屏时仍按安全规则救援。

启停按钮表达下一步动作，使用电源图标、紧凑圆角、蓝灰/中性底与细描边；不使用醒目的绿橙胶囊或开关状态色。文字、hover、按下和禁用状态复用 MonitorPalette。卡片作为无明细叶子完整登记 row/detail/available，避免旧档案高度残留。

## 验证边界

通知链路测试必须覆盖持续显示器睡眠、旧在线条目、漏通知、挂起参数 I/O、自身回调、启动旧记忆和目标动作竞态。纯模型通过不能代替真实拔线与合盖/开盖，详见 reference/acceptance-results.md。物理链路未验收时不宣称可见输出已保证。
