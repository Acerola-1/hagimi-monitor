# Design

## Context

见 [proposal.md](proposal.md)。当前顶层监控卡片由模块数组顺序驱动，显示器区块单独追加；风扇和蓝牙按设备／渠道状态注入。展开区指标先过滤可见项，再拆成“半行两列”和“整行沉底”；半行／整行由静态宽度登记决定。普通面板与置顶面板共用面板视图，但各自的窗口事件、滚动及尺寸行为需要共同验证。面板还有一条以稳定分区 ID 驱动的几何／展开运动路径。

现有设置持久化模块可见性与指标勾选，不保存面板顺序。排序不能改变采样器返回的顺序、宽度登记、设备归属或现有显隐语义。

## Goals / Non-Goals

**Goals:**

- 以稳定身份保存顶层与各指标区域的完整顺序，显示时按当前可用性过滤。
- 拖动时仅维护临时预览顺序，释放到有效落点后一次提交，维持既有点击、控件及面板运动语义。
- 让真实面板与设置预览共用半行／整行的顺序排布规则；不同渲染路径得到一致的位置与尺寸。

**Non-Goals:**

- 跨模块／分页移动指标、交换数据归属，或拖动进程列表、拓扑图、滑杆和显示器设备信息。
- 改写采样排期、静态宽度登记或最坏值宽度预算。
- 在设置页再建排序界面、全局恢复默认或顶层顺序恢复入口。

## Decisions

### 1. 顺序作为展示偏好，而非采样结果

建立一个集中排序模型：顶层作用域含所有已知模块 ID 与显示器 ID；指标作用域由模块、分页及连续指标区标识。每个作用域存稳定 ID 的完整排列，和显隐选择分别持久化。面板从采样结果构建当前可见项后按该排列投影，显示器由顶层排列决定位置；采样数据与统计仍按原通道使用。

载入时去重，未知 ID 作为不展示的占位保留，以免版本回退丢失位置；新版本新增 ID 依默认顺序并入：优先插在默认顺序中首个仍存在的后继之前，否则跟在最后一个仍存在的前驱之后。任何已有 ID 的相对先后保持不变。暂时不可用、被关闭的 ID 不从保存的排列删除。两渠道原有独立 UserDefaults 继续独立，App Store 不呈现风扇但保留其排序 ID。首次升级按当前默认展示顺序初始化，不改变现有用户的显隐设置。

**替代方案：**直接重排采样器模块数组或只保存当前可见项。前者把展示偏好渗入采样／统计；后者使隐藏项重现时丢失位置，因此不采用。

### 2. 单一拖动会话协调顶层与指标

在面板层维护临时拖动会话，记录作用域、稳定 ID、原顺序、当前候选插入点、指针位置和源项几何。顶层只在概览整行识别“长按后拖动”；指标格及 CPU 逐核环图区在不属于按钮／滑杆的区域识别同一序列。单击仍交给现有展开／复制动作。预览以面板根层覆盖显示，源位置保留完整卡片占位；已展开模块只显示概览行预览，避免高卡片遮挡落点。长按时截取源单元当时可见的完整内容、尺寸与表面配色，拖动期间冻结预览数值；原生材质截图能力不足时须以实际源视图渲染路径补足，不能将纯文字视为完整预览。普通拖动、右键／辅助功能移动和模块内恢复默认都经相同的顺序变更入口。

拖动期间只改变临时投影，不写偏好；有效释放后提交一次。Esc、越界、面板关闭、渠道／设备变化导致源项失效时取消会话。右键与辅助功能按现有静态跨度打包出的行列提供可行方向：首尾行不越界，同排两个半行指标可左右交换，纵向移动跨过相邻行的对应项目；隐藏项仍保留在完整排列中。

**替代方案：**在每个卡片内部各管一套拖放状态。它难以协调跨行命中、边缘滚动和普通／置顶窗口取消行为，因此不采用。优先以 SwiftUI 的长按串接拖动实现；若原生验证发现跨窗口释放或 Esc 无法可靠结束会话，再在面板窗口边界使用局部 AppKit 事件桥接，不引入全局逐帧事件监听。

### 3. 预览重排与面板几何分离

候选插入点由可排序项的稳定身份及当前可见矩形确定；跨作用域、复杂组件与固定按钮没有目标。相邻项随候选顺序让位，拖动项在根层跟随指针；滚动容器上下边缘按需自动滚动。拖动期间固定窗口内容尺寸，释放后再按新顺序提交几何和窗口尺寸。几何快照继续使用稳定分区 ID；顺序变更作为结构变化进入现有测量／运动链路，取消时恢复原结构。拖动不建立常驻采样或逐帧材质重建。

**替代方案：**每次鼠标位移立即写入设置并让窗口重新测量。这会在长面板及展开状态下反复触发持久化、布局与窗口缩放，因此不采用。

### 4. 有序混合跨度排布

为每个连续指标区建立一条有序渲染序列。跨度从现有静态宽度登记读取：半行占一格，整行占两格；合并温度／热压力作为单个整行单元。依序排布时，整行若遇到已占一格的行，先结束该行并保留空半格，再独占下一行；后续半行从下一行开始。无用户顺序时沿用现有半行在前、整行在后的默认序列。面板正常渲染、几何实验路径和设置中的实时预览使用同一排布结果，避免预览与实际面板不一致。

电池各分页与供电诊断区分别建作用域；诊断行仅当前真实可见时参与展示，但其 ID 始终保留在顺序记录。TOP 进程、功率流拓扑和显示器内部控件仍位于既有固定结构区域。CPU 逐核环图及 P/E 展示作为一个不可拆的全宽排序项加入 CPU 指标作用域，复用 core-split 稳定 ID；无自定义顺序时保持当前默认顶部位置，宽度恒为整行，高度按实际核数和可用宽度测量。CPU 温度／热压力合并行使用一个可见排序 ID，不拆成两个拖动目标。

**替代方案：**继续先按跨度分组，再只在组内排序。它不能实现已确认的“半行 A、整行 B、半行 C”，因此不采用。

### 5. 设置与可访问性

具有可排序指标的模块设置页只新增“恢复本模块默认指标布局”，电池一次恢复该模块全部分页／诊断作用域；显隐、展开、其他模块与顶层顺序不变。面板可排序项提供右键移动命令与辅助功能动作；悬停反馈提示可拖动，不常驻手柄。新增文案接入当前本地化目录。

**替代方案：**设置页放全局重置或第二套拖动列表。用户已明确排除，且会让两个入口的状态和预览同步变复杂。

## Risks / Trade-offs

- [长按与展开、数值复制、滑杆或置顶窗口移动争夺事件] → 仅对概览行及合格指标格挂手势，明确子控件排除区；两种面板逐项原生操作验收。
- [混合跨度后的空半格影响视觉节奏] → 按保存顺序忠实排布，并用插入预览显示最终位置；宽度审计不放宽。
- [拖动展开模块时几何、滚动和窗口尺寸互相反馈] → 预览顺序与持久化分离，拖动中固定窗口尺寸，复用现有稳定 ID 与运动链路，使用现有面板性能夹具对照。
- [动态指标缺失、风扇／蓝牙出现与渠道差异改变目标集合] → 保存完整 ID，展示时过滤，源项失效即取消拖动；双渠道和设备状态切换验证。
- [App Store 版长按无响应或图像渲染回退纯文字] → 对几何登记、长按阶段、会话开始和截图结果做运行时诊断；双渠道分别原生验证，源卡片颜色取当前模块而非作用域默认值。
- [旧规格中的“整行沉底、语义配对”与用户排序冲突] → `monitor-panel` delta 显式更新行序：无自定义时维持旧默认，用户自定义后以其顺序为准。

## Migration Plan

1. 新顺序偏好缺失时，以现有默认布局初始化；旧显隐及指标勾选值原样保留。
2. 后续版本新增或移除项目时，去重并保留暂不认识的 ID，再按默认相对顺序补入新 ID；恢复可用项时读取其原有位置。
3. 若需要回滚实现，移除新排序展示路径即可恢复旧默认布局；独立顺序键可保留而不影响旧版读取。实施不迁移或重写现有可见性数据。
